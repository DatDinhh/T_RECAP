# Normative contract staging

File class: **[1] hand-written repository policy document**.

This directory is the human-readable staging area for normative implementation contracts that are too broad to live directly inside a single generated JSON file. It sits between the frozen PDF specification under `docs/specs/`, the machine-readable source contracts under `spec/generated/`, the JSON schemas under `spec/schemas/`, and the generated SV/C/Python outputs produced by `scripts/gen_headers.py`.

This directory is not a substitute for the integrated Phase 2 specification. It is also not a verification architecture directory.

## Authority order

When documents disagree, use this order:

```text
1. Active integrated Phase 2 PDF under docs/specs/
2. Machine-readable source contracts under spec/generated/
3. JSON schemas under spec/schemas/
4. Generated SV/C/Python headers and filelists
5. Human-readable implementation notes under docs/architecture/ and spec/normative/
```

The active PDF freezes the mathematical core, the Ethernet/HPS DDR telemetry and command path, and the implementation repository architecture. The machine-readable JSON contracts convert that text into implementation constants and layouts. Generated outputs shall not introduce new policy.

## Provenance tags

```text
[0] imported from the Phase 2 reference-model zip, or generated by that reference model
[1] hand-written implementation, documentation, script, or source contract
[2] generated file; do not edit by hand
```

This file is `[1]`.

Important rule:

```text
spec/generated/*.json may be source-of-truth input.
rtl/include/generated/*.sv, sw/hps/include/generated/*.h,
sw/pc_dashboard/generated/*.py, filelists/*.f, and gen_manifest.json are generated outputs.
```

Do not classify a file as `[2]` just because the parent directory is named `generated`.

## What belongs here

Allowed files in `spec/normative/`:

```text
README.md
contract_notes.md
release_notes.md
rationale_*.md
```

These files may explain:

```text
- why a source contract exists;
- which PDF sections or architecture docs it implements;
- which file owns a disputed constant or layout;
- how a release freezes or promotes a reference artifact;
- how to review a generated-contract change.
```

These files shall not contain executable duplicate constants. A paragraph may say that the current baseline uses `D = L + G = 384`, but RTL, HPS C, and Python dashboard code must consume that value from generated headers.

## What does not belong here

Do not place these in `spec/normative/`:

```text
- SystemVerilog source files
- C or C++ source files
- Python generator implementation
- generated headers
- filelists
- memh coefficient files
- runtime profile JSON
- board address maps
- captured telemetry packets
- local run output
```

## Review rule for contract changes

A real contract change shall be reviewed as one patch containing all affected layers:

```text
1. Human explanation in docs/architecture/ or spec/normative/
2. Source JSON change under spec/generated/
3. Schema change under spec/schemas/ when structure changes
4. Regenerated outputs from make gen-headers
5. Regenerated filelists from make rtl-filelist when module ownership changes
6. Updated bring-up notes if software/board behavior changes
```

A generated-output-only change is suspect. A generated output shall normally change because a source JSON file or generator script changed.

## Contract-change checklist

Before accepting a change touching this area, check:

```text
[ ] The active PDF is still the top authority.
[ ] The change does not duplicate CSR offsets, packet sizes, or enum values by hand.
[ ] JSON parses with strict syntax.
[ ] JSON validates against the matching schema when the schema exists.
[ ] make gen-headers completes.
[ ] make rtl-filelist completes.
[ ] Generated outputs contain AUTO-GENERATED - DO NOT EDIT.
[ ] Generated outputs are deterministic on a second run.
[ ] HPS C and Python constants are generated from the same source as RTL constants.
[ ] No transport/dashboard file is treated as bit-accurate core signoff authority.
```

## Current R1 boundary

R1 is complete when:

```text
scripts/gen_headers.py exists and generates SV/C/Python headers.
scripts/gen_filelists.py exists and generates filelists.
spec/generated/gen_manifest.json records source and output hashes.
make gen-headers passes.
make rtl-filelist passes.
make check-generated can detect drift once git tracking is active.
```

C0 still comes later. R1 only creates the contract infrastructure. It does not prove that FFT, STFT/WOLA, BRAM replay, HPS Ethernet, or the PC dashboard is implemented.
