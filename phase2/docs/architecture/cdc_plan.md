# CDC plan

File class: **[1] hand-written architecture document**.

This document defines clock-domain-crossing policy for the T-RECAP Phase 2 implementation repository. It complements `clock_reset_plan.md`; that file defines clocks and reset ownership, while this file defines which signals may cross domains, how they cross, and what patterns are forbidden.

This file is not a verification architecture document. It defines implementation rules that future RTL and bring-up code shall obey.

## Authority

The active integrated Phase 2 specification under `docs/specs/` is the authority. This file is also tied to:

```text
docs/architecture/interface_contracts.md
docs/architecture/module_api.md

```

The CDC rules here are stricter than a first single-clock prototype because the repository must not paint itself into a corner. A single-clock build may tie domains together, but the interfaces shall still be written so a later split is possible.

## CDC design goals

CDC shall preserve these system properties:

```text
1. No multi-bit state is sampled unsafely across domains.
2. 64-bit pointers and counters are transferred atomically.
3. HPS control writes cross through synchronizers, handshakes, or shadow/commit logic.
4. Telemetry taps remain valid-only from the core side and never backpressure the STFT/WOLA core.
5. Packet FIFO or DDR writer backpressure causes telemetry drop/accounting, not core stall.
6. Reset deassertion is synchronized per domain.
7. Every intentional CDC has a named primitive or an explicit waiver in this document.
```

## Frozen fabric and Step-16 audio clock domains

| Domain | Clock | Reset | Owned logic |
| --- | --- | --- | --- |
| Fabric | `clk_fabric = CLOCK_50`, 50 MHz | canonical `rst_n_platform` | Board control, ADC controller, source/core, telemetry, CSR/HPS bridge, DDR writer, and typed Platform Designer bridges. |
| Audio MCLK output | `audio_pll_wrapper` 12.288 MHz output from `CLOCK_50` | PLL-owned/qualified lock | Peripheral `AUD_XCK` only; it does not clock core, telemetry, CSR, or DDR logic. |
| Codec BCLK receive edge | external `AUD_BCLK` positive edge | locally synchronized BCLK reset release | I2S LINE-IN receive, RX-FIFO write, TX-FIFO read control. |
| Codec BCLK transmit edge | external `AUD_BCLK` negative edge | separately synchronized transmit-edge reset release | I2S LINE-OUT serialization. |
| HPS hard subsystem | generated-system owned | HPS/generated-system owned | Linux and hard HPS peripherals; not a hand-written RTL clock domain. |

`CLOCK2_50`, `CLOCK3_50`, and `CLOCK4_50` are reserved board inputs and do not
clock active logic. `ADC_SCLK` is a serial peripheral output generated by
`clk_fabric`, not an RTL clock. The 48 kHz sample, 10 Hz STATUS, 30 Hz METRICS,
and 2 Hz heartbeat-toggle outputs are exact-average fractional clock-enable
pulses, never clocks.

The checked-in full-board architecture does not support split core, telemetry,
CSR, or AVMM clocks. A later split requires an explicit interface and CDC
redesign; logical domain names are not evidence that such a split is safe.

## Legal CDC mechanisms

Only these CDC mechanisms are allowed unless an explicit architecture waiver is added.

| Mechanism | Use case | Allowed primitive/documentation |
| --- | --- | --- |
| Two-flop synchronizer | Single-bit level that changes slowly | `reset_sync.sv` for reset, specific single-bit sync helper for controls. |
| Pulse synchronizer | One-cycle pulse crossing to another domain | `sync_pulse.sv`. |
| Snapshot/commit handshake | Multi-bit control, counters, or pointer values | `sync_bus_snapshot.sv` or documented source/destination handshake. |
| Async FIFO | Streaming payload crossing domains | `async_fifo.sv`. |
| Gray-coded pointer protocol | FIFO pointer internals only | Inside `async_fifo.sv`; not ad-hoc in leaf modules. |
| Same-clock pass-through | Owners intentionally share `clk_fabric` | Explicit top-level connection and frozen Step-10 contract. |

Forbidden:

```text
- independent bit synchronization of a multi-bit bus;
- using `ready` from telemetry to stall core sample/frame/FFT/IFFT/WOLA logic;
- reading live 64-bit counters through two 32-bit CSR reads without a snapshot;
- writing live 64-bit pointers through two 32-bit CSR writes without a commit;
- relying on Linux process timing as a hardware handshake;
- broad SDC false paths over real unsynchronized payload data.
```

## Single-bit controls

Single-bit level controls may use a two-flop synchronizer only if:

```text
- the signal is not a one-cycle pulse;
- the signal is not part of a multi-bit value;
- the destination can tolerate up to two-cycle latency;
- the source holds the value long enough for synchronization;
- there is no requirement to observe every transition.
```

Examples that may be level-synchronized after architectural review:

```text
telemetry_enable level into telemetry/writer domain
ring_writer_enable level into writer domain
status-only debug enable level
```

Examples that shall not be simple level-synchronized:

```text
THR2[55:0]
RING_BASE[63:0]
RING_SIZE_BYTES[31:0]
RING_RD[63:0]
source_mode[31:0]
packet_enable[31:0] if changed live without a safe update rule
```

## Pulse controls

A one-cycle pulse crossing domains shall use `sync_pulse.sv` or a request/acknowledge handshake.

Examples:

```text
THR2_COMMIT
SOURCE_MODE_COMMIT
RING_CONFIG_COMMIT
RING_WR_SNAPSHOT
RING_RD_COMMIT
CORE_COUNT_SNAPSHOT
telemetry_soft_reset
clear_metrics
```

Pulse crossing requirements:

```text
- source pulse shall not be lost;
- destination shall see exactly one event per accepted request;
- request/acknowledge is preferred when the source may issue back-to-back pulses;
- destination busy/reject behavior shall be explicit for unsafe commands.
```

## Multi-bit controls

Multi-bit controls crossing domains shall use shadow/commit.

Pattern:

```text
1. Source writes all shadow words in source domain.
2. Source pulses commit.
3. Destination synchronizes/handshakes the commit.
4. Destination captures all bits atomically into active state at a safe boundary.
5. Destination optionally returns accepted/rejected/pending status.
```

Affected controls:

```text
THR2_LO + THR2_HI + THR2_COMMIT
SOURCE_MODE_SHADOW + SOURCE_MODE_COMMIT
RING_BASE_LO + RING_BASE_HI + RING_SIZE_BYTES + RING_CONFIG_COMMIT
RING_RD_LO_SHADOW + RING_RD_HI_SHADOW + RING_RD_COMMIT
```

Do not use independent low/high bit synchronizers for these values.

## THR2 CDC contract

`THR2` is a 56-bit threshold. It shall cross from HPS/CSR into the core only through shadow/commit logic.

Required behavior:

```text
- HPS writes low word.
- HPS writes high word; unused high bits beyond bit 55 shall be zero.
- HPS pulses THR2_COMMIT.
- CSR logic validates range.
- Core domain captures the complete 56-bit shadow value.
- Active threshold changes only at frame boundary.
- Pending status remains visible until applied.
```

A frame shall never analyze some bins using old THR2 and other bins using new THR2.

In the Step-7 one-clock implementation, the CSR bank consumes the dedicated
`core_config_safe_boundary_o` returned by
`trecap_source_core_integration.sv`. A telemetry `tap_frame.valid` event is an
observation and is not ORed into the THR2 safe-boundary path.

## Source-mode CDC contract

Source-mode changes disturb stream alignment. They shall cross from CSR/HPS into source/core logic only through a safe source-mode commit sequence.

Required behavior:

```text
- old source stops cleanly or is marked discontinuous;
- source adapter state is cleared when required;
- input ring, OLA ring, delay alignment, and frame scheduler are cleared when source-dependent;
- metrics are cleared or discontinuity-marked;
- new source starts at a sample boundary;
- telemetry is disabled or marks discontinuity during the transition.
```

An illegal or unsafe source-mode command is rejected and counted. Do not treat `source_mode` as a plain synchronized bus.

The checked-in Step-7 implementation uses the following single-clock sequence:

```text
trecap_source_core_integration reports an actual selected-beat handshake or idle source boundary
CSR shadow/commit validates and applies the complete source-mode enum at that boundary
the post-safe-boundary source_mode_apply pulse returns to the integration layer
the integration layer immediately blocks source ready/valid for a non-idempotent change
source adapters/replay epoch state and source-dependent core state are cleared coherently
the mux changes its registered active source and emits a discontinuity pulse
the first beat of the new source remains held until the transition guard is released
```

The requested CSR mode must not directly enable a platform source. The registered
active mode exported by the source mux owns source enables and routing. Telemetry,
DDR waitrequest, packet-FIFO pressure, and network state have no path into the
source/core ready chain.

## Counter snapshot contract

HPS shall not read live multiword counters directly.

Required read sequence:

```text
1. HPS writes CORE_COUNT_SNAPSHOT = 1.
2. CSR/core snapshot logic latches frame_count and sample_count coherently.
3. HPS reads low/high halves from snapshot registers.
4. Snapshot remains stable until the next snapshot request.
```

This applies to any future multiword core, telemetry, or writer counter exposed through 32-bit CSR halves.

## Ring pointer CDC contract

The DDR ring uses absolute 64-bit byte pointers:

```text
W   = FPGA-owned producer pointer
Rd  = HPS-owned consumer pointer
```

`Rd` transfer:

```text
1. HPS writes RING_RD_LO_SHADOW.
2. HPS writes RING_RD_HI_SHADOW.
3. HPS pulses RING_RD_COMMIT.
4. Writer domain consumes the committed 64-bit value through a CDC-safe handshake.
```

`W` transfer:

```text
1. HPS writes RING_WR_SNAPSHOT = 1.
2. Writer/CSR logic latches current 64-bit W into snapshot registers.
3. HPS reads RING_WR_LO_SNAP and RING_WR_HI_SNAP.
```

Independent low/high updates are invalid.

## Telemetry tap CDC contract

Core telemetry taps are observations, not flow-control inputs. The core side may emit:

```text
tap_sample_valid
tap_x_delayed
tap_y_out
tap_error
tap_sample_idx
tap_frame_valid
tap_frame_idx
tap_mag2_unique_bins
tap_mask_unique_bins
tap_frame_stats
```

Telemetry may sample, buffer, decimate, compress, or drop these events. It shall not assert a ready signal into:

```text
sample path
frame scheduler
FFT/IFFT path
WOLA path
core metrics accumulator
```

If a CDC FIFO or packet FIFO cannot accept a tap event, the event is dropped and the appropriate drop counter increments.

### Step-8 composition and metric epoch

The checked-in `trecap_core_telemetry_top` is a one-clock composition. Its direct
sample, frame, and unique-bin tap wires therefore introduce no new CDC boundary.
Telemetry record `ready` remains downstream-only and cannot cross back into the
core clock-enable or sample/output handshakes.

On the DE1-SoC path, the raw CSR clear request is queued in
`trecap_source_core_integration` until the true core safe boundary. The resulting
`clear_metrics_apply_pulse_o` is the single applied event consumed by both the
core metric accumulator and telemetry eligible-bin aggregate. Do not separately
synchronize or regenerate that pulse for one consumer; doing so would create two
metric epochs. If core and telemetry are moved to different clocks later, replace
the direct observation path with explicit best-effort CDC FIFOs/snapshots and a
single acknowledged clear-event transfer before claiming equivalent behavior.

The same source-discontinuity pulse is an observation-epoch boundary for
telemetry admission. It is not a reset-domain crossing and does not reset the
packet FIFO: partial collections are abandoned, an already-selected record
finishes atomically, and unselected candidates drain locally to `last` under a
latched scheduler decision. If that event later crosses clocks, it requires its own
acknowledged pulse transfer and cannot be inferred from asynchronous sample-index
changes.

## Streaming CDC and backpressure

Ready/valid streams crossing domains shall not be wired directly. Use an async FIFO or keep both sides in the same clock domain.

Allowed:

```text
core domain valid-only taps -> telemetry drop-on-full capture
telemetry formatted records -> async packet FIFO -> HPS bridge/writer
```

Forbidden:

```text
telemetry FIFO full -> core in_ready low
DDR waitrequest -> core frame scheduler stall
PC disconnected -> core sample clock stop
UDP send fail -> ring writer reset -> core reset
```

Transport failure causes telemetry loss and counters. It does not throttle the core.

## Audio and ADC CDC

Live audio and ADC are not part of C0. Their platform wrappers and source
adapters are connected to the source/core hierarchy, but that source structure
does not prove codec or ADC operation. Step 16 implements the audio control,
clock, I2S, and FIFO CDC source. Step 17 implements the separate ADC protocol
boundary while preserving `clk_fabric` as the controller, word-assembly,
adapter, mux, and core domain. The wrappers shall not inject unmanaged sample
clocks into the core.

Required options:

```text
- use an async FIFO for the codec BCLK-to-fabric complete-frame payload;
- synchronize the single-bit off-chip ADC return before fabric word assembly;
- keep sample valid and the assembled multi-bit data atomic in `clk_fabric`;
- mark source discontinuity on reset or source-mode changes.
```

Do not sample a multi-bit audio or ADC data bus in the core domain with independent bit synchronizers.

The current `audio_codec_wrapper.sv` transfers each complete signed 16-bit
stereo frame from the codec bit-clock domain into `clk_fabric` through
`u_audio_rx_fifo`. Processed monitor frames cross in the opposite direction
through `u_audio_tx_fifo`; an epoch tag and synchronized flush event prevent a
disabled or source-switched monitor from replaying stale samples. The RX FIFO
drains while capture is deselected, and the BCLK receiver resets
partial-frame assembly while disabled, so a later source epoch cannot expose a
stale physical frame. Separate
reset-release synchronization covers BCLK receive and transmit edges so neither
edge domain observes asynchronous reset release. The async FIFOs carry complete
multi-bit payloads; their payloads are never reconstructed from independent bit
synchronizers.

`audio_pll_wrapper.sv` drives the peripheral-only `AUD_XCK` at 12.288 MHz from
`CLOCK_50`. Once lock is qualified and the FPGA owns the codec bus,
`audio_codec_i2c_init.sv` configures the WM8731 at 7-bit address `0x1a` for
48 kS/s, signed 16-bit I2S with the codec as BCLK/LRCK master. The HPS must hold
`HPS_I2C_CONTROL` low during that initialization; FPGA logic observes the grant
but never drives the HPS mux control. Dedicated saturating 64-bit RX-overflow,
TX-overflow, and TX-underflow counters stay separate from reserved CSR overflow
bits.

The Step-17 `adc_wrapper.sv` runs its 100 ksample/s scheduler and serial state
machine in `clk_fabric`. Its 2.5 MHz `ADC_SCLK` is only a registered peripheral
output. The asynchronous single-bit `ADC_DOUT` return passes at least two
preserved `async_reg` stages; only that synchronized bit enters the 12-bit shift
register. Raw sample data and valid are then registered together in fabric, so
the adapter and source mux require no ADC async FIFO or independent multi-bit
synchronizers. A later separate ADC controller clock would require a new atomic
CDC architecture.

Both live sources enter `trecap_source_core_integration.sv` through explicit
valid/data ports and normalized adapters. The Step-16/17 source checks do not
establish native RTL compile/simulation, external audio or ADC I/O timing,
TimeQuest closure, I2C ACKs, measured clocks, analog behavior, or live-board
evidence. Step 18 owns external timing; Step 20 owns Quartus and hardware
evidence, and BRAM replay remains the correctness prerequisite.

## Reset CDC

Reset deassertion is a CDC event. Step 10 uses one canonical synchronized release
for the entire 50 MHz fabric and local edge-specific releases for codec BCLK
state.

Rules:

```text
- The qualified board/HPS hard reset may assert asynchronously into the fabric reset synchronizer.
- `rst_n_platform` shall deassert only after at least two `CLOCK_50` edges.
- All fabric owners shall consume the same `rst_n_platform`; parallel same-clock reset chains are forbidden.
- Telemetry soft reset shall be a synchronous clear, not a derived asynchronous reset.
- Async FIFO reset shall follow the FIFO primitive's documented reset sequence.
- A domain shall not exit reset based on an unsynchronized status bit from another domain.
```

Reset policy details are in `clock_reset_plan.md`.

## SDC and CDC constraints

Constraints shall reflect implementation truth:

```text
- unrelated clocks shall be declared asynchronous only when CDC structures exist;
- synchronizer flops should be identifiable by instance name or attribute;
- async FIFO internals shall follow tool/vendor timing recommendations;
- false paths shall be specific, not broad blanket cuts over buses;
- same-clock builds shall not accidentally hide future CDC requirements in the source code.
```

A waived CDC path shall be documented with signal name, reason, and owner.

## Anti-patterns

Do not approve code containing these patterns:

```text
always_ff @(posedge clk_dst) dst_bus_q <= src_bus;
assign core_ready = !packet_fifo_full;
assign frame_scheduler_enable = !ddr_waitrequest;
assign active_thr2 = {csr_thr2_hi, csr_thr2_lo};
assign ring_rd = {csr_ring_rd_hi, csr_ring_rd_lo};
assign core_rst_n = board_rst_n & ethernet_link_up;
```

These are architecture bugs, not style issues.

## C0 CDC acceptance

C0 is core-first. It may be single-clock, but it shall still pass these checks:

```text
[ ] No HPS/DDR/Ethernet/PC signal enters the core.
[ ] BRAM replay source and core share a known clock or use a documented adapter.
[ ] Reset deassertion is synchronized for the core clock.
[ ] Core valid-only taps do not have ready inputs.
[ ] Any generated interface type used by core compiles from `trecap_iface_pkg.sv`.
```

## T0 CDC acceptance

T0 adds transport. It shall pass these checks:

```text
[ ] THR2 uses shadow/commit.
[ ] Source mode uses safe commit.
[ ] Ring `W` and `Rd` use snapshot/commit.
[ ] Core counters use snapshot registers.
[ ] Packet FIFO or CDC FIFO failure drops telemetry, not core samples.
[ ] HPS bridge validates ring records before forwarding.
[ ] SDC does not hide CDC bugs with broad false paths.
```
