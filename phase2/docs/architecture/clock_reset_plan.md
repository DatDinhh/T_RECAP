## Design goals

The clock/reset plan must preserve these system properties:

```text
1. C0 core-only builds can compile and run without HPS, DDR, Ethernet, dashboard, or board pins.
2. Reset deassertion is synchronized in every active clock domain.
3. HPS-written controls cannot tear multi-bit state inside the core.
4. Telemetry reset cannot stall or corrupt the STFT/WOLA core.
5. Ring and pointer reset cannot expose stale DDR records to HPS.
6. The checked-in full-board build has one fabric clock; any later split is an explicit CDC redesign.
```

## Frozen fabric, Step-16 audio, and Step-17 ADC timing domains

| Domain | Clock | Reset | Owned logic |
| --- | --- | --- | --- |
| Fabric | `clk_fabric = CLOCK_50`, 50 MHz | `rst_n_platform` | Board control, ADC controller, source/core, telemetry, CSR/HPS bridge, DDR writer, and typed Platform Designer bridges. |
| Audio MCLK output | `audio_pll_wrapper` 12.288 MHz output from `CLOCK_50` | `rst_n_platform` resets the wrapper; qualified lock gates codec init/admission | Peripheral `AUD_XCK` only; no core, telemetry, CSR, or DDR state. |
| Codec BCLK receive edge | external `AUD_BCLK` positive edge | local receive-edge synchronized release | I2S LINE-IN, complete-frame RX-FIFO writes, and TX-FIFO read control. |
| Codec BCLK transmit edge | external `AUD_BCLK` negative edge | local transmit-edge synchronized release | I2S LINE-OUT serialization state. |
| HPS hard subsystem | generated-system owned | generated-system owned | Linux and HPS hard peripherals; not hand-written fabric RTL. |

`CLOCK2_50`, `CLOCK3_50`, and `CLOCK4_50` are reserved inputs and do not clock
active logic. Step 17 generates `ADC_SCLK` as a 2.5 MHz registered serial
peripheral output, not an RTL clock. Its 100 ksample/s scheduler is a fabric
clock-enable event; ADC controller, word assembly, adapter, source mux, and core
all remain in `clk_fabric`. The single-bit off-chip `ADC_DOUT` input alone passes
a preserved two-flop synchronizer. The 48 kHz BRAM/audio sample, STATUS,
METRICS, and heartbeat events are also clock-enable pulses in `clk_fabric`.

Do not introduce a hidden board or HPS clock into `rtl/core/`. Board clocks terminate in `rtl/platform/de1soc/` or `rtl/top/`.

## Reset polarity and naming

All hand-written RTL uses active-low resets.

Single-clock module:

```systemverilog
input logic clk,
input logic rst_n,
```

Multi-clock modules are permitted only at a reviewed physical CDC boundary, such
as the audio wrapper:

```systemverilog
input logic clk_core,
input logic rst_core_n,
input logic clk_csr,
input logic rst_csr_n,
input logic clk_avmm,
input logic rst_avmm_n,
```

Rules:

```text
- Reset input names end with `_n`.
- Reset assertion may be asynchronous only at the board-conditioning boundary.
- Reset deassertion shall be synchronized per clock domain.
- Internal modules shall treat reset deassertion as synchronous.
- Do not gate clocks to implement reset.
- Do not use an unsynchronized pushbutton directly inside core, telemetry, or HPS bridge logic.
```

## Reset hierarchy

The reset tree is:

```text
KEY[0] stable-high qualification and HPS-to-FPGA reset
    -> rtl/platform/de1soc/clock_reset_ctrl.sv
        -> one reset_sync.sv for clk_fabric
            -> canonical rst_n_platform
                -> all fabric owners

canonical rst_n_platform
    -> edge-specific reset synchronizers in audio_codec_wrapper.sv
        -> codec BCLK receive-edge and transmit-edge state

canonical rst_n_platform
    -> audio_pll_wrapper
        -> qualified audio PLL lock
            -> FPGA codec I2C initialization eligibility
                -> codec_ready admission for I2S capture/monitor
```

`clock_reset_ctrl.sv` owns:

```text
- 20 ms stable-high qualification of released `KEY[0]`;
- combination of the qualified board reset with active-low HPS-to-FPGA reset;
- the sole at-least-two-stage `clk_fabric` reset synchronizer;
- exact-average fractional clock-enable generation;
- synchronized/debounced board controls.
```

The phase accumulators dither each enable interval between the adjacent integer
cycle counts when the requested rate does not divide 50 MHz. This introduces at
most one fabric-cycle interval variation while preserving the exact long-term
average; “exact-average” does not mean every pair of pulses is equally spaced.

Leaf modules do not instantiate board-specific reset logic. Generic reset synchronization lives under `rtl/common/reset_sync.sv`.

## Required reset primitives

The minimum reset utilities are:

```text
rtl/common/reset_sync.sv                                     [1]
rtl/common/sync_pulse.sv                                     [1]
rtl/common/sync_bus_snapshot.sv                              [1]
rtl/common/async_fifo.sv                                     [1]
rtl/platform/de1soc/clock_reset_ctrl.sv                      [1]
```

`reset_sync.sv` shall synchronize reset deassertion for a single clock domain and
shall use at least two flip-flops. Parallel reset chains for different consumers
of the same `clk_fabric` domain are forbidden because they can release on
different edges.

## Reset categories

Not every control pulse is a full reset. The repository shall distinguish these operations:

| Operation | Scope | Intended effect |
| --- | --- | --- |
| Power-on reset | Whole FPGA fabric and Platform Designer boundary | Bring all state to known reset values. |
| Core reset | Source/core scheduling and arithmetic state | Restart sample count, frame count, input ring, OLA, delay alignment, metrics as specified. |
| Telemetry soft reset | Telemetry formatter/FIFO/writer transport state | Synchronously clear packet pipeline and transport counters without redefining core arithmetic. |
| Metrics clear | Core metrics only | Clear counters at a safe sample/frame boundary. |
| Source-mode commit reset | Source adapter and stream-alignment state | Avoid mixing sources or metrics across an atomic source change. |
| Ring reconfiguration reset | DDR ring writer state and producer pointer | Prevent stale ring pointers and stale DDR records. |

Do not use a full chip reset when the intended operation is `clear_metrics` or `telemetry_soft_reset`.

## Core reset obligations

A core reset shall initialize:

```text
sample_count = 0
frame_count = 0
input ring contents = 0
input ring write pointer = 0
frame scheduler state = idle/empty
FFT/IFFT control state = idle
WOLA/OLA ring contents = 0
OLA read/write phase = 0
delay-alignment state = 0
core metrics = 0 unless reset type says metrics preserved
active threshold = reset/default THR2 unless a later safe commit updates it
source mode = reset/default source mode unless platform policy overrides at top level
```

The BRAM replay source shall also reset its vector index and full-tail flush state. A C0 core-only build shall be able to reset and restart without HPS or Platform Designer present.

## Telemetry reset obligations

A telemetry soft reset shall initialize:

```text
packet scheduler state
packetizer state
packet FIFO contents and pointers
pre-writer packet drop accounting, if reset is specified to clear transport counters
record metadata under construction
sequence number policy only if the transport spec says reset/reconfigure restarts sequence
```

It is a synchronous clear in `clk_fabric`. It shall not be converted into a
derived active-low reset by ANDing it with `rst_n_platform`.

A telemetry reset shall not:

```text
- reset the STFT/WOLA arithmetic core by accident;
- assert ready/backpressure into the core;
- change active THR2 in the middle of a frame;
- change source mode by itself;
- make HPS believe old DDR data is valid.
```

## HPS bridge and DDR ring reset obligations

A ring reset or ring reconfiguration shall occur while telemetry and ring writer enables are disabled. It shall initialize:

```text
producer pointer W = 0
committed consumer pointer shadow state as defined by CSR commit logic
ring_configured flag according to accepted base/size
writer FSM = idle
record builder = idle
DMA status = reset/default state
drop/error counters according to soft-reset policy
```

HPS shall commit `Rd = 0` before enabling the ring writer after reconfiguration. HPS shall not read a stale producer pointer from before reset as a valid commit boundary.

## Reset release ordering

Step 10 assigns reset ownership to `clock_reset_ctrl.sv`. It first requires
released `KEY[0]` to remain high for 20 ms, then combines that qualified request
with the generated active-low `h2f_reset`. One `trecap_reset_sync`, clocked by
`CLOCK_50`, creates `rst_n_platform`; assertion remains asynchronous at that
conditioning boundary and release takes at least two fabric edges.

`rst_n_platform` releases the board control state, ADC wrapper, source/core,
telemetry, CSR/HPS bridge, DDR writer, wrapper-local response state, and the two
typed generated-system Avalon bridges simultaneously. The physical board top
does not instantiate another fabric reset synchronizer. In the checked-in Qsys
graph `system.reset_n_reset_n` fans out through `clk_0.clk_reset` only to
`trecap_csr_bridge.reset` and `trecap_f2h_sdram_bridge.reset`; it is not connected
to an HPS reset sink. The HPS reset can therefore be a global full-board fabric
reset without creating a self-sustaining loop.

The direct-clock profile has no fabric PLL and does not expose a fabricated lock
signal. A later PLL or split-clock profile requires a new reviewed architecture,
generated-clock constraints, and real CDC implementation.

The clock/reset helper also no longer exports tick-derived
`frame_boundary_o` or `source_safe_boundary_o`. Those signals were scaffolds:
accepted samples can stall or change source, so a free-running divider cannot
state when the core or source is safe. The only board consumers are the real
boundaries returned by `trecap_source_core_integration` and the mathematical
core.

Full-board release and software enable order:

```text
1. Qualified board reset or HPS-to-FPGA reset holds `rst_n_platform` low.
2. After both requests release, the single synchronizer waits at least two `CLOCK_50` edges.
3. Every fabric owner exits hard reset on the same canonical release.
4. HPS software reads ID/VERSION while telemetry and ring writer remain disabled by reset defaults.
5. HPS performs the synchronous telemetry soft clear.
6. HPS configures ring base/size and commits ring config.
7. HPS commits Rd = 0.
8. HPS enables ring_writer_enable and telemetry_enable.
```

Core may run with telemetry disabled. Ethernet and dashboard availability shall
not hold the core in reset. The full-board HPS-to-FPGA reset deliberately resets
the whole fabric; C0 remains HPS-independent because its core-only tops do not
instantiate the board/HPS reset path.

## Safe update boundaries

Some HPS commands are not resets but require safe-boundary updates.

| Control | Required behavior |
| --- | --- |
| `THR2_LO/HI + THR2_COMMIT` | Latch shadow value, update active threshold only at frame boundary. |
| `SOURCE_MODE_SHADOW + SOURCE_MODE_COMMIT` | Stop old source, clear source-dependent state or mark discontinuity, activate new source at safe sample boundary. |
| `CLEAR_METRICS` | Clear metric accumulators at a safe sample/frame boundary, not while a multiword update is partially visible. |
| `RING_RD_LO/HI_SHADOW + RING_RD_COMMIT` | Cross to writer domain through CDC-safe commit. |
| `RING_WR_SNAPSHOT` | Latch producer pointer before HPS reads low/high halves. |

A register write shall not directly tear active multi-bit state in the core.

## Reset and C0

Cut C0 includes only:

```text
rtl/include/
rtl/common/
rtl/interfaces/
rtl/sources/trecap_bram_replay_source.sv
rtl/core/
rtl/fft/
rtl/top/trecap_core_only_top.sv
rtl/top/trecap_core_bram_replay_top.sv
```

C0 reset policy:

```text
- one fabric/core clock is acceptable;
- no HPS reset dependency;
- no Platform Designer reset dependency;
- no telemetry soft reset dependency;
- reset can restart BRAM replay and core-only output deterministically;
- source/core reset behavior is visible at the top-level core smoke build.
```

If C0 requires HPS, Ethernet, a PC dashboard, or a Platform Designer reset to run, C0 is wrong.

## Reset and T0

Transport Cut T0 adds telemetry, HPS bridge, HPS software, PC dashboard, and DE1-SoC platform integration. T0 shall not alter core reset semantics.

T0 reset policy:

```text
- telemetry reset can clear formatter/FIFO/writer transport state;
- ring writer reset and ring reconfiguration occur while telemetry is disabled;
- HPS can recover from malformed ring records by disable/reset/reconfigure;
- PC disconnection does not reset the core;
- packet FIFO full condition drops telemetry and increments counters, not reset/stall core.
```

## Reset coding template

Preferred sequential block style:

```systemverilog
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        state_q <= STATE_IDLE;
        count_q <= '0;
    end else begin
        state_q <= state_d;
        count_q <= count_d;
    end
end
```

Preferred combinational next-state style:

```systemverilog
always_comb begin
    state_d = state_q;
    count_d = count_q;

    unique case (state_q)
        STATE_IDLE: begin
            if (start_i) begin
                state_d = STATE_RUN;
            end
        end
        default: begin
            state_d = STATE_IDLE;
        end
    endcase
end
```

No latch should be required in reset or next-state code.

## Reset constraints and timing notes

`constraints/de1soc/clocks.sdc` and `constraints/de1soc/de1soc.sdc` shall document:

```text
- primary board clock definitions;
- `CLOCK_50` as the sole active 50 MHz fabric clock;
- reserved status of the other board clock inputs;
- the source-level 50 MHz-to-12.288 MHz peripheral audio PLL relationship;
- no claim that the PLL source declaration alone proves XCK frequency/lock,
  external codec BCLK/LRCK timing, or board behavior;
- false paths only for properly synchronized reset assertion/deassertion logic;
- CDC paths through async FIFOs or synchronizers as appropriate;
- Platform Designer clock/reset boundary assumptions.
```

Do not hide an unconstrained CDC by marking broad false paths over real data signals.

## Anti-patterns

Forbidden patterns:

```text
- using KEY[0] directly as reset inside rtl/core/;
- deasserting reset asynchronously into a fabric domain;
- synchronizing a multi-bit bus with independent two-flop synchronizers;
- changing THR2 active bits from HPS writes without a frame-boundary commit;
- resetting core because Ethernet is disconnected;
- using reset to flush backpressure into the core;
- making reset behavior depend on PC dashboard state;
- manually duplicating reset constants outside generated headers.
- exporting divider-generated frame/source-safe boundaries that do not follow accepted core data;
- hardwiring a PLL-lock status high when no PLL owns the current clock.
- clocking sequential logic from sample, STATUS, METRICS, or heartbeat ticks;
- creating separate reset synchronizers for consumers of the same fabric clock;
- deriving an asynchronous telemetry reset from a synchronous soft-reset command;
- implying that reserved alternate clocks make split-clock operation supported.
```

## Review checklist

A module touching reset or clocking is not ready until:

```text
[ ] Clock and reset ports follow `module_api.md` naming.
[ ] All 50 MHz fabric logic consumes the same canonical `rst_n_platform`.
[ ] Codec receive-edge and transmit-edge state use their owned local reset-release synchronizers.
[ ] Audio PLL lock is qualified before codec initialization; codec readiness is not part of fabric hard-reset generation.
[ ] `AUD_XCK` remains a peripheral output and is never substituted for `clk_fabric`.
[ ] Multi-clock transfers are named and documented.
[ ] Reset values are explicit.
[ ] Reset does not hide source-mode or THR2 commit semantics.
[ ] C0 reset is HPS-independent; full-board HPS reset is intentionally global to fabric.
[ ] Normal transport/PC status cannot assert fabric hard reset.
[ ] Telemetry reset cannot backpressure the core.
[ ] Ring reset cannot expose stale DDR records as committed data.
[ ] Relevant SDC notes exist or have a TODO tied to platform bring-up.
[ ] Clock-enable pulses are never used as clocks.
[ ] No derived asynchronous soft reset exists in the fabric.
```
