# Coding style

File class: **[1] hand-written architecture document**.

This document defines coding style for the T-RECAP Phase 2 implementation repository. It applies to hand-written SystemVerilog, C/C++, Python, JSON, YAML, Markdown, shell scripts, and generated-file handling.

This file is not a verification architecture document. It does not define scoreboards, monitors, assertions, coverage, or regression layout.

## Authority

The active integrated Phase 2 specification under `docs/specs/` is the authority. This document implements the style baseline already established by:

```text
.editorconfig
.clang-format
.pre-commit-config.yaml
Makefile
docs/architecture/module_api.md
docs/architecture/dependency_rules.md
docs/architecture/generated_contracts.md
docs/architecture/generated_header_flow.md
```

If style rules here conflict with `.editorconfig` or `.clang-format`, update the config file and this document together.

## General rules

```text
- Use LF line endings.
- Use UTF-8 text.
- End every text file with exactly one final newline.
- Avoid trailing whitespace except where Markdown intentionally uses it.
- Prefer explicit names over abbreviations.
- Do not add local tool output to source directories.
- Do not hide Phase 1 code at the Phase 2 root.
- Do not add verification directory structure in this implementation repository revision.
```

Root-local build and run outputs belong under `runs/`, `build/`, `out/`, or tool-specific ignored directories. Source directories should remain reviewable.

## SystemVerilog file contract

Every hand-written RTL file should start with:

```systemverilog
// SPDX-License-Identifier: MIT
// File class: [1] hand-written RTL.
// Layer: rtl/<layer>/
// Purpose: <one sentence>
// Contract: <spec/doc anchor>

`default_nettype none
```

Every hand-written RTL file should end with:

```systemverilog
`default_nettype wire
```

`default_nettype none` catches misspelled nets. Restoring to `wire` avoids breaking vendor-generated or third-party code compiled after the file.

## SystemVerilog module style

Rules:

```text
- One primary module per file.
- Filename matches module name.
- Use `logic`, not `reg` or implicit wire declarations in hand-written RTL.
- Use `always_ff` for sequential logic.
- Use `always_comb` for combinational logic.
- Sequential logic uses nonblocking assignments (`<=`).
- Combinational logic uses blocking assignments (`=`).
- No inferred latches unless explicitly justified and reviewed.
- No hidden board-demo logic inside `rtl/core/`.
- No HPS/DDR/Ethernet/dashboard dependency inside `rtl/core/`.
```

Preferred skeleton:

```systemverilog
`default_nettype none

import trecap_core_pkg::*;
import trecap_iface_pkg::*;

module trecap_example (
    input  logic clk,
    input  logic rst_n,

    input  logic in_valid,
    output logic in_ready,
    input  trecap_example_t in_payload,

    output logic out_valid,
    input  logic out_ready,
    output trecap_example_t out_payload
);

    // Implementation.

endmodule

`default_nettype wire
```

## SystemVerilog naming

| Item | Rule | Example |
| --- | --- | --- |
| T-RECAP module | `trecap_*` | `trecap_frame_scheduler` |
| Board-facing top | board prefix allowed | `de1_soc_trecap_top` |
| Package | `trecap_*_pkg` | `trecap_packet_pkg` |
| Interface | `trecap_*_if` | `trecap_sample_if` |
| Clock | `clk` or `clk_<domain>` | `clk_core`, `clk_csr` |
| Reset | active-low `rst_n` or `rst_<domain>_n` | `rst_core_n` |
| Registered state | suffix `_q` | `state_q` |
| Next state/data | suffix `_d` | `state_d` |
| Input port | suffix `_i` if scalar convention is helpful | `start_i` |
| Output port | suffix `_o` if scalar convention is helpful | `done_o` |
| Valid-only tap | `tap_*`, `*_valid` | `tap_frame_valid` |
| Ready/valid stream | `in_valid`, `in_ready`, `in_payload` | see module skeleton |

Avoid short names like `a`, `b`, `x`, `y` except inside small arithmetic expressions where the math contract uses the same symbol and scope is short.

## Generated package usage

Generated constants shall be imported from generated packages or headers.

Allowed examples:

```systemverilog
import trecap_core_pkg::*;
localparam int unsigned UNIQUE_BINS = (T_L / 2) + 1;
```

Forbidden examples:

```systemverilog
parameter int L = 256;                  // bad in a leaf T-RECAP module
localparam int STATUS_BYTES = 72;       // bad if packet package has this value
localparam int CSR_VERSION = 'h00010008;// bad outside generated CSR package/header
```

Comments may explain baseline values, but executable code uses generated constants.

## FSM style

Use typed enums:

```systemverilog
typedef enum logic [2:0] {
    STATE_IDLE,
    STATE_BUILD,
    STATE_WRITE,
    STATE_COMMIT,
    STATE_DROP
} state_e;

state_e state_q, state_d;
```

Use `unique case` only when all legal enum values are handled or there is a safe `default`. Do not use synthesis pragmas that hide incomplete cases.

## Reset style

Use active-low reset ports and explicit reset values.

```systemverilog
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        valid_q <= 1'b0;
        count_q <= '0;
    end else begin
        valid_q <= valid_d;
        count_q <= count_d;
    end
end
```

Reset deassertion shall be synchronized per clock domain. Board pushbuttons shall not enter leaf RTL directly.

## Combinational default style

Every `always_comb` block shall assign default values before conditional overrides.

```systemverilog
always_comb begin
    out_valid = 1'b0;
    out_payload = '0;
    next_q = state_q;

    if (in_valid) begin
        out_valid = 1'b1;
        out_payload = in_payload;
    end
end
```

No accidental latch is acceptable in core arithmetic, telemetry packetizers, or HPS bridge control.

## Arithmetic style

Arithmetic rules:

```text
- Use signed declarations explicitly for signed math.
- Cast before mixed signed/unsigned operations.
- Do not rely on implicit truncation.
- Do not allow internal wraparound in visible core-contract paths.
- Use shared helper modules/functions for rounding and saturation.
- Keep product widths explicit.
- Threshold comparison in mag2 domain is unsigned and full precision.
```

Example:

```systemverilog
logic signed [A_W-1:0] a_s;
logic signed [B_W-1:0] b_s;
logic signed [A_W+B_W-1:0] prod_s;

assign prod_s = a_s * b_s;
```

Bad:

```systemverilog
assign prod = a * b;  // width and signedness unclear
```

## Interfaces and structs

Use generated typedefs from `trecap_iface_pkg.sv` for shared payloads. Do not create near-duplicate structs in several directories.

Rules:

```text
- Core sample records use generated sample/frame typedefs.
- Telemetry record metadata uses generated record typedefs.
- Packet payload byte offsets come from generated packet constants.
- CSR fields come from generated CSR constants.
```

If a new type is needed across layers, add it to `spec/generated/interface_types.json` and regenerate.

## Core layer restrictions

`rtl/core/` and `rtl/fft/` shall not contain:

```text
CSR offsets
packet type IDs
UDP payload layout
DDR ring layout
HPS physical addresses
Linux virtual addresses
board switch or LED logic
Platform Designer ports
Ethernet link state
PC dashboard assumptions
```

Core code may expose valid-only taps. It may not accept telemetry backpressure.

## Telemetry layer restrictions

`rtl/telemetry/` formats packets and manages packet admission/drop policy. It shall not own DDR writes.

Allowed:

```text
packet scheduler
WAVE packetizer
SPEC packetizer
METRICS packetizer
STATUS packetizer
packet FIFO / priority dropper
```

Forbidden:

```text
trecap_ddr_ring_writer.sv inside rtl/telemetry/
Avalon-MM write master inside rtl/telemetry/
producer pointer commit inside rtl/telemetry/
HPS physical address handling inside rtl/telemetry/
```

## HPS bridge layer restrictions

`rtl/hps_bridge/` owns:

```text
CSR bank
CSR shadow/commit logic
ring pointer control
DDR record builder
DDR ring writer
Avalon/MM write master or equivalent bus master
HPS bridge top
```

This layer may know CSR and packet contracts. It shall not implement STFT/WOLA arithmetic.

## Platform layer restrictions

Board-specific logic belongs under:

```text
rtl/platform/de1soc/
rtl/top/
constraints/de1soc/
platform/de1soc/
```

Board pins, audio codec pins, ADC pins, HPS CSR ports, PLLs, and Platform Designer wrappers shall not leak into `rtl/core/`.

## C style for HPS software

HPS C code shall be conservative and explicit.

Rules:

```text
- Use C11 or the compiler baseline documented in sw/hps/Makefile.
- Include generated headers from sw/hps/include/generated/.
- Use fixed-width integer types from stdint.h.
- Parse multi-byte packet fields explicitly as little-endian.
- Do not rely on implicit struct padding for DDR/UDP wire formats.
- Read runtime addresses and UDP endpoints from sw/hps/config/trecap_hps_config.json.
- Do not hard-code CSR offsets or packet sizes in C source.
- Use nonblocking sockets or bounded send timeouts.
- On send failure, drop the datagram, advance Rd, and count the failure.
- Do not compute FFT, IFFT, masks, WOLA, or reconstruction error in HPS code.
```

Recommended error-handling style:

```c
if (!trecap_packet_validate(&record, &err)) {
    counters->malformed_record_count++;
    trecap_disable_telemetry(csr);
    return TRECAP_ERR_MALFORMED_RECORD;
}
```

Do not continue parsing beyond a malformed DDR record as if byte-scanning resynchronization were supported.

## C++ style for reference model

The current imported package is a reference model, not final golden authority. C++ code under `sw/reference_model/` shall preserve its own style where imported, but new wrapper code should follow:

```text
- C++20 only if CMakeLists.txt and compiler support it; otherwise C++17-compatible.
- Deterministic integer arithmetic for signoff paths.
- No host-math-library dependence after artifact freeze unless hash-equivalent.
- Canonical memh and JSON output rules.
- No dependency on HPS C or PC dashboard code.
```

Do not rename reference artifacts to golden authority until the freeze/signoff criteria are met.

## Python style

Python hand-written code shall follow the repository's pre-commit rules.

Rules:

```text
- Use Python 3 with type hints where practical.
- Use `pathlib.Path` for filesystem paths.
- Keep generated Python dependency-free.
- Dashboard parser imports generated constants from sw/pc_dashboard/generated/.
- UDP receiver shall not block GUI redraw.
- GUI/dashboard code shall not be a correctness authority.
- Scripts should exit nonzero on contract failure.
```

Acceptable script skeleton:

```python
#!/usr/bin/env python3
from __future__ import annotations

from pathlib import Path


def main() -> int:
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

## JSON style

JSON files are contracts. Treat them like source code.

Rules:

```text
- Use two-space indentation.
- Use stable key order.
- Do not use comments in JSON.
- Integers wider than 53 bits in signoff artifacts shall be decimal strings when required by schema.
- Runtime config values may use strings for physical addresses.
- Schema changes and generated output changes should be reviewed together.
```

Do not put runtime demo choices into normative core config. Runtime/demo profiles belong under `config/profiles/`.

## Markdown style

Markdown architecture files shall:

```text
- start with an H1 title;
- state file class `[1]` near the top;
- identify authority and related docs;
- avoid claiming generated files already exist unless they do;
- use fenced code blocks for repo paths and commands;
- avoid raw tool logs unless they are short and meaningful;
- distinguish reference-model outputs from implementation signoff.
```

Do not add long verification architecture sections to implementation docs in this revision.

## Shell script style

Rules:

```text
- Use `#!/usr/bin/env bash` for Bash scripts.
- Use `set -euo pipefail` when safe.
- Quote variables.
- Do not assume the current working directory unless the script first resolves repository root.
- Print commands or clear status messages for board/programming scripts.
- Do not embed local user paths.
```

## Generated files

Generated files are `[2]` and shall include:

```text
AUTO-GENERATED - DO NOT EDIT
```

Manual edits are invalid. Change source schemas or generator scripts instead.

Generated files that shall be committed after R1:

```text
rtl/include/generated/*.sv
sw/hps/include/generated/*.h
sw/pc_dashboard/generated/*.py
sw/reference_model/generated/*.py
spec/generated/gen_manifest.json
filelists/*.f
filelists/*.qsf.inc
```

## Filelist style

Filelists are generated by `scripts/gen_filelists.py`.

Rules:

```text
- Packages before interfaces.
- Interfaces before modules.
- Common primitives before modules that instantiate them.
- Core/FFT before core tops.
- Telemetry after core tap typedefs.
- HPS bridge after generated CSR/packet/interface packages.
- Platform and board tops last.
```

Do not hand-maintain compile order in random shell scripts.

## Artifact style

Canonical artifacts shall preserve exact encoding rules from the spec/reference flow.

Rules:

```text
- memh: one fixed-width lowercase hex value per line.
- no 0x prefix.
- no blank lines.
- exactly one LF after every value.
- hashes are over canonical logical serialization.
- artifacts/reference_outputs/ contains software reference results, not hardware completion evidence.
```

Do not edit memh files by hand to make RTL pass.

## Comments

Good comments explain contract intent, not obvious syntax.

Good:

```systemverilog
// THR2 becomes active only at a frame boundary to avoid tearing threshold decisions inside one frame.
```

Bad:

```systemverilog
// increment counter
count_q <= count_q + 1'b1;
```

Comments mentioning baseline constants shall not become a second source of truth.

## Logging and errors

HPS and PC software shall make failures visible.

Required visible counters or logs:

```text
malformed DDR record
oversized record
UDP send failure
sequence gap
command reject
DMA drop count
packet FIFO drop count
overflow/sticky flags
```

Dashboard shall display `dma_drop_count` and `packet_fifo_drop_count` separately.

## Pre-commit expectations

The root `.pre-commit-config.yaml` runs the repository hygiene command. The following component commands remain available for their documented purposes:

```text
make check-layout
make lint-basic
make check-generated
make rtl-filelist
```

Do not bypass generated-file guards by editing generated files manually.

## Review checklist

Before approving hand-written implementation code:

```text
[ ] File is in the correct ownership directory.
[ ] File class/provenance is clear where appropriate.
[ ] No Phase 1 root artifact was introduced.
[ ] No generated file was hand-edited.
[ ] No private duplicate of CSR/packet/core constants exists.
[ ] `rtl/core/` remains free of HPS, DDR, Ethernet, dashboard, and board-specific assumptions.
[ ] Telemetry cannot backpressure the core.
[ ] DDR writer logic appears only under `rtl/hps_bridge/`.
[ ] Clock/reset/CDC patterns follow `clock_reset_plan.md` and `cdc_plan.md`.
[ ] HPS software does not implement signal-processing algorithms.
[ ] PC dashboard code is parser/visualization/control only, not correctness authority.
```
