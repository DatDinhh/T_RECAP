File class: **[1] hand-written architecture document**.

This document defines the order in which the T-RECAP Phase 2 repository should be written, generated, compiled, and brought up. It aligns with the root `Makefile` already staged in R0.

This is not a verification architecture document. Compile smoke checks are implementation hygiene, not proof of functional correctness.

## Current source milestone

Step 14 is source-complete. It preserves the exact Revision-G version-1 command
request while adding an explicit version-2 command/result contract, generated
CSR minor 1.8, exact peer IP/port binding, RFC1982 at-most-once handling,
transport lifecycle and safe disabled/idle mutations, counter clear, and replay
result observation. Its source checker, non-native RTL structural/model checker,
and HPS/PC host-test sources are not packaged execution or live evidence.

Step 13 previously completed the checked-in HPS transport, which validates the frozen
runtime profile and live reservation, consumes and validates the DDR ring,
forwards one exact record per UDP datagram, latches malformed input exactly once,
and provides an independent UDP-only diagnostic STATUS mode. Its source checker
and RAM-backed host test are not active-DTB, native HPS `/dev/mem`, physical
Ethernet, systemd, FPGA, Quartus, or hardware evidence.

Step 12 previously froze the ownership contract: the FPGA is the sole
producer-pointer owner, the HPS is the sole consumer-pointer owner, physical-tail
WRAP accounting and transport-reset epochs are deterministic, and
`platform/de1soc/linux/trecap_reserved_memory.dtsi` is the only official Linux
reservation source. The checker and directed regression are source gates;
compiled-DTB, Linux boot/runtime, HPS runtime, and hardware evidence remain
pending.

Step 11 previously closed the pin-agnostic BRAM-replay path through exact core
completion and a post-core STATUS commit to the HPS-visible DDR boundary. Its
Step-11 filelist, testbench, and runner names remain stable as a historical
cumulative gate. Checked-in testbench source is not accepted simulator execution
evidence.

Step 10 previously became source-complete. The full board uses one active `CLOCK_50`-derived
50 MHz `clk_fabric` domain and one canonical `rst_n_platform`. The clock/reset
controller owns the 20 ms released-`KEY[0]` qualification, its combination with
the active-low HPS-to-FPGA reset, and the sole at-least-two-stage fabric reset
synchronizer. Fabric reset release is simultaneous. Exact-average 48 kHz, 10 Hz,
30 Hz, and 2 Hz-toggle events are clock enables rather than generated clocks;
telemetry soft reset is a synchronous clear rather than a derived asynchronous
reset. Alternate board clocks remain reserved and split-clock operation remains
unsupported pending explicit CDC redesign.

Step 9 previously made `rtl/platform/de1soc/de1_soc_trecap_top.sv` use
the real generated-Platform-Designer CSR/DDR boundaries, audio and LTC2308
wrappers, source/core owner, telemetry/HPS owner, best-effort core-y audio
monitor, and real LED/HEX status. It contains no synthetic tap or safe-idle bus
substitute. Step 16 now adds the reviewed source structure for a peripheral-only
12.288 MHz XCK, WM8731 FPGA-I2C configuration at `0x1a`, and 48 kS/s/16-bit
codec-master I2S with bidirectional async-FIFO CDC and dedicated audio counters.
Step 17 adds the pinned Rev-H LTC2308 source structure at 100 ksample/s with a
2.5 MHz registered SCLK, synchronized DOUT, six-bit next-conversion command,
epoch-latched channel, prime/discard rule, normalization/accounting, active-
source sample-rate reporting, and an explicit ADC profile. Neither live-source
contract is physical-device evidence.

Step 8 established that `rtl/top/trecap_core_telemetry_top.sv` is a real
standalone normalized-source composition containing one mathematical core and
one non-stalling telemetry formatter. Direct valid-only taps cross that boundary;
STATUS and METRICS consume authoritative core-owned counters/aggregates; and
`filelists/rtl_core_telemetry.f` is the dedicated dependency-ordered build. The
pure `filelists/rtl_telemetry.f` deliberately remains core-free.

The Step-7 `rtl/top/trecap_source_core_integration.sv` continues to own
the normalized BRAM/audio/ADC/diagnostic source fan-in, guarded source-mode
epochs, exact finite-replay tail routing, core instantiation, and real
safe-boundary/tap/status outputs. The physical Quartus top is
`rtl/platform/de1soc/de1_soc_trecap_top.sv`; the similarly named
`rtl/top/trecap_de1soc_full_top.sv` is the pin-agnostic telemetry/HPS/DDR logical
top. The board top now consumes real core taps and connects active source pins
through their platform wrappers.

The DE1-SoC board path does not instantiate the standalone composition because
the source/core layer already owns its one core. Instead, it connects that core's
taps, authoritative counters, and exact safe metric-clear apply pulse to the
telemetry-only logical top. This milestone has source-contract and static-layout
checks and directed regression sources only. The Step-13 RAM-backed host test is
execution evidence only for HPS C consumer and packetization logic. It does not
claim accepted Step-11 or Step-12 RTL compile/elaboration or functional
simulation, compiled-DTB or Linux runtime reservation evidence, Platform Designer
generation, Quartus
compilation, TimeQuest timing closure, physical BRAM replay equivalence, codec
operation, measured ADC I/O timing/analog behavior, or board validation.

Steps 16 and 17 are source-complete only. They do not change BRAM replay as the
correctness prerequisite or supply native RTL simulation, external audio/ADC
timing (Step 18), Quartus/TimeQuest, I2C ACK, measured clocks/analog response, or
live-source hardware evidence (Step 20).

## Do not build in reverse

Wrong order:

```text
PC dashboard first -> HPS Ethernet first -> DDR ring first -> telemetry first -> then core
```

Correct order:

```text
schemas/artifacts -> core-only RTL -> BRAM replay -> telemetry -> DDR ring/HPS -> dashboard
```

The reason is simple: Ethernet plots can look alive while the algorithm is wrong. The project needs a deterministic core and artifact path before live/demo transport.

```text
The pinned board/device contract is DE1-SoC Rev-H with LTC2308; older ADC variants are rejected.
CONVST is idle low and high for 40 ns; the first SCLK rise is 1.84 us after conversion start.
ADC_SCLK is a 2.5 MHz registered protocol output, never an RTL clock.
The single-bit ADC_DOUT input passes at least two preserved synchronizer flops.
Twelve MSB-first straight-binary bits are assembled atomically with valid in clk_fabric.
The 100 ksample/s transaction fits before the next request.
SW[6:4] is latched on ADC-source entry and the first previous-command result is discarded.
The adapter recenters at 2048 and retains separate saturating/drop/fault accounting.
STATUS reports 100 ksample/s only for active ADC; BRAM/audio remain 48 ksample/s.
The explicit ADC profile does not change the BRAM-replay default or LINE-IN profile.
Step-18 timing and Step-20 Quartus/analog/hardware evidence are required before live claims.
```

## CMake build order

Root `CMakeLists.txt` is host-side convenience only:

```text
reference model C++ build
optional HPS userspace build if source tree exists
CTest for host-side tools/tests
```

It shall not own SystemVerilog compile order. RTL order belongs to generated filelists.

## Failure policy

```text
If gen-headers fails, do not write RTL against guessed constants.
If check-generated fails, fix schema/generator drift before adding modules.
If rtl-filelist fails, fix file ownership/order before compile.
If compile-core fails, do not start telemetry as a workaround.
If C0 fails, do not open T0.
If compile-telemetry fails, do not debug HPS UDP first.
If HPS cannot read ID/VERSION, do not debug dashboard plots first.
```
