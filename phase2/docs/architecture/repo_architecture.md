# Repository architecture

File class: **[1] hand-written architecture document**.

This document defines how the Phase 2 implementation repository is organized, what each directory owns, and which dependencies are allowed. It is written to match the R0 root files already staged in the repository.

## Authority and scope

This document is subordinate to the active integrated spec under `docs/specs/`. It explains repository implementation ownership only. It does not replace:

```text
Part I   Core Algorithm and Signoff Contract
Part II  Ethernet/HPS DDR Telemetry and Control Architecture
Part III Core Implementation Repository Architecture
```

Verification architecture is intentionally out of scope for this revision. Do not add `dv/`, `tb/`, `uvm/`, scoreboard hierarchy, coverage hierarchy, or assertion architecture into this repository phase unless the later verification architecture document explicitly opens that work.

The repository root is expected to contain these hand-written infrastructure files:

| `.gitignore` | Keeps build outputs and Phase 1 root dumps out while allowing committed generated contracts and artifacts. |

| `.clang-format` | Conservative C/C++ style for reference/HPS code. |
| `.pre-commit-config.yaml` | R0-tolerant hygiene hooks and generated-file guardrails. |

## Provenance tags

```text
[0] imported from the Phase 2 reference-model zip, or generated by that reference model
[1] hand-written implementation, documentation, or config source file
[2] generated file; do not edit by hand
```

Important consequence: a file under a directory named `generated/` is not automatically `[2]`. Some JSON files under `spec/generated/` are source-of-truth contract files and are `[0]` or `[1]`. The generated outputs are the emitted SV/C/Python headers, filelists, and manifests.

## Naming rules

Use lowercase `snake_case` for scripts, docs, config, and Python modules. Use `trecap_` prefix for SystemVerilog implementation modules except board/vendor wrappers.

Examples:

```text
trecap_core_top.sv
threshold_commit.md
telemetry_full_demo.json
packet_parser.py
```

Generated files shall contain an `AUTO-GENERATED - DO NOT EDIT` banner. Hand-written files should not pretend to be generated.

## Platform policy

Platform Designer/Qsys ownership is split deliberately:

```text
platform/de1soc/qsys/                 source Qsys/Tcl and selected generated metadata
platform/de1soc/address_map/          bridge regions, CSR base, ring address convention
platform/de1soc/generated_notes/      notes about generated files and regeneration
rtl/platform/de1soc/                  HDL wrappers around board/PD boundary
constraints/de1soc/                   QSF/SDC/pin constraints
```

Rules:

```text
Do not manually edit generated Platform Designer HDL.
Keep `rtl/platform/de1soc/platform_designer_wrapper.sv` hand-written class `[1]`; generation owns only module `system` and its QIP/submodules.
Commit system.sopcinfo only if scripts or HPS address-map tooling consume it.
RING_BASE is FPGA-visible bus address, not Linux userspace virtual address.
Board pins and vendor wrappers stay out of rtl/core/.
```

`rtl/top/trecap_source_core_integration.sv` is pin-agnostic and owns source
selection, guarded source epochs, exact BRAM tail routing, and the real core tap
boundary. It does not own telemetry, DDR, Platform Designer, or physical pins.
`rtl/platform/de1soc/de1_soc_trecap_top.sv` is the physical Quartus top;
`rtl/top/trecap_de1soc_full_top.sv` is the pin-agnostic telemetry/HPS/DDR logical
top despite its name.

Step 8 adds a separate reusable composition filelist at
`filelists/rtl_core_telemetry.f`. It contains the FFT/core dependency closure,
the telemetry formatter/FIFO, and `trecap_core_telemetry_top.sv`; it contains no
source-selection, HPS/DDR, Platform Designer, or board files. The existing
`filelists/rtl_telemetry.f` stays telemetry-only. In the board hierarchy,
`trecap_source_core_integration.sv` remains the sole core owner and feeds the
telemetry-only logical top, preventing a duplicate core instance.

The Step-8 wiring described here is checked-in source architecture only. It has
not yet established Step-8 RTL elaboration/compile, functional simulation,
Quartus compile/timing closure, artifact-driven BRAM replay equivalence, or board
audio/ADC operation.

Step 9 closes the hand-written physical-board composition at
`rtl/platform/de1soc/de1_soc_trecap_top.sv`. The generated Platform Designer CSR
and F2SDRAM boundaries, audio and LTC2308 wrappers, sole source/core owner,
telemetry/HPS owner, and real board status are connected once. Real core-y
valid/data fan out into a best-effort audio monitor, while y-ready remains always
accept so codec state cannot backpressure the mathematical core. The direct
clock helper no longer exports fake safe boundaries or a hardwired PLL-lock
claim. Generated `system` HDL remains vendor/QIP-owned.

This Step-9 boundary remains source-only. Step 16 extends it with a
peripheral-only 12.288 MHz `AUD_XCK` PLL wrapper, lock-qualified open-drain FPGA
I2C initialization of WM8731 address `0x1a`, 48 kS/s signed 16-bit codec-master
I2S, bidirectional complete-frame async FIFOs, and dedicated saturating 64-bit
RX-overflow/TX-overflow/TX-underflow counters. The explicit
`de1soc_linein_demo` profile selects that configuration.

Step 17 independently freezes the pinned Rev-H LTC2308 path: 100 ksample/s,
2.5 MHz registered serial clock, a two-flop synchronized off-chip DOUT bit,
twelve-bit fabric word assembly, epoch-latched six-bit channel commands,
first-result discard, a 92-cycle post-enable/abort request holdoff, code-2048
signed recentering, and the explicit
`de1soc_adc_demo` profile. The board exports the active source rate downstream,
so ADC reports 100,000 while BRAM/audio report 48,000. No ADC async FIFO or
second RTL clock is introduced.

Step 10 freezes the clock/reset source architecture. `CLOCK_50` directly owns
the sole active 50 MHz `clk_fabric` domain. `clock_reset_ctrl` qualifies released
`KEY[0]` high for 20 ms, combines it with the active-low HPS-to-FPGA reset, and
uses the only at-least-two-stage fabric reset synchronizer to create
`rst_n_platform`; all fabric owners release simultaneously. The full-board HPS
reset is global to the fabric, while C0 remains HPS-independent through its
separate core-only hierarchy.

Sample, STATUS, METRICS, and heartbeat events are exact-average fractional clock
enables, never clocks. Telemetry soft reset is a synchronous clear and cannot
create a derived asynchronous reset. Alternate board clocks are reserved and do
not imply split-clock support. Audio BCLK state has edge-specific local reset
synchronization. Audio capture is gated on qualified PLL lock, FPGA codec-bus
grant, and configuration done. `HPS_I2C_CONTROL` must stay low while the FPGA
owns the codec bus; FPGA logic never drives the HPS mux control.

These milestones are source-only. Generated Platform Designer products, native
RTL compile/functional simulation, external audio/ADC timing (Step 18), Quartus
and TimeQuest results, I2C ACKs, measured PLL/XCK/BCLK/LRCK/CONVST/SCLK behavior,
ADC analog/channel validation, and live board evidence (Step 20) remain pending.
Physical BRAM replay remains the prerequisite correctness gate before either
live source.

## Acceptance criteria for repository architecture

