# Generated header flow

File class: **[1] hand-written architecture document**.

This document defines the implementation flow that turns the shared Phase 2 contracts into checked-in SystemVerilog, C, and Python headers. It is narrower than `generated_contracts.md`: that file defines the full generated-contract policy; this file defines the actual header-generation pipeline, review rules, and failure handling that the team shall follow when writing `scripts/gen_headers.py` and using `make gen-headers`.

This file is not a verification architecture document. It does not define scoreboards, monitors, assertions, regressions, or coverage.

## Current arithmetic configuration ownership

The maintained arithmetic source is
`sw/reference_model/spec/generated/core_config.json`. From the combined repository
root, run:

```bash
python sw/reference_model/scripts/gen_config.py
```

That generator emits model-local
`sw/reference_model/include/trecap_golden/generated/core_config.hpp` and
`sw/reference_model/python/trecap_golden/generated/_core_constants.py`.
The reference library and Python tools consume those generated values.

The root `spec/generated/core_config.json` is the promoted integration snapshot.
A baseline change must update that snapshot and the related promoted contracts as
part of the same deliberate change. Root `scripts/gen_headers.py` then owns the
RTL/HPS/dashboard outputs and the separate compatibility path
`sw/reference_model/generated/trecap_config.py`. That path is not the reference
Python package's `python/trecap_golden/generated/trecap_config.py`.

This separation keeps arithmetic ownership in the reference package and CSR,
packet, interface and board ownership in the integrated implementation. The
promotion map and source manifests record their relationship; two files with
similar names must not become independently edited definitions.

## Design goal

The generated header flow exists to prevent silent drift between:

```text
RTL packages
HPS C CSR/register code
HPS C UDP packet code
PC Python packet parser
PC Python command client
reference-model constants
artifact manifests
filelists and compile-order assumptions
```

The following values shall not be duplicated manually in implementation code:

```text
N, L, P, H, F, G, D
internal width constants
source-mode IDs
CSR offsets
CSR bit positions
CSR access semantics
transport VERSION major/minor
packet type IDs
packet header fields
payload byte counts
STATUS payload size
packet-enable bits
SPEC_MODE values
overflow/sticky flag bits
command IDs and legal argument ranges
interface struct field names and widths
```

Readable comments may mention baseline values. Executable constants shall come from generated headers.

## Generation sequence

The root flow is:

```text
1. Edit source schema JSON only.
2. Run make gen-headers.
3. scripts/gen_headers.py validates all source schema files.
4. scripts/gen_headers.py writes generated files to a temporary staging directory.
5. The script compares staged outputs with checked-in paths.
6. The script updates outputs only when explicitly generating.
7. The script writes spec/generated/gen_manifest.json last.
8. Run make check-generated.
9. Review the schema diff and generated-output diff together.
```

`gen_manifest.json` shall be written last. If generation fails halfway, the repository shall not be left with a believable manifest that describes stale outputs.

## Required script behavior

`scripts/gen_headers.py` shall:

```text
- validate JSON syntax;
- validate each JSON file against its schema when the schema exists;
- check that no generated output path escapes the repository root;
- check that every output directory exists or create it;
- produce deterministic output byte-for-byte;
- avoid embedding wall-clock timestamps in generated outputs;
- emit stable field ordering;
- use LF newlines;
- emit exactly one final newline per generated text file;
- emit the required generated-file banner;
- write gen_manifest.json with source and output hashes;
- return nonzero on any invalid schema, duplicate field, duplicate offset, duplicate packet ID, illegal range, or output write failure.
```

The generator may print progress messages to stdout. Those messages are not part of the contract. The generated files and manifest are the contract.

## Generated-file banner

Every generated output shall contain this phrase near the top:

```text
AUTO-GENERATED - DO NOT EDIT
```

Required examples:

```systemverilog
// AUTO-GENERATED - DO NOT EDIT
// Generator: scripts/gen_headers.py
// Source manifest: spec/generated/gen_manifest.json
```

```c
/* AUTO-GENERATED - DO NOT EDIT
 * Generator: scripts/gen_headers.py
 * Source manifest: spec/generated/gen_manifest.json
 */
```

```python
# AUTO-GENERATED - DO NOT EDIT
# Generator: scripts/gen_headers.py
# Source manifest: spec/generated/gen_manifest.json
```

Manual edits to files with this banner are invalid. Required changes go through schema changes and regeneration.

## Manifest contract

`spec/generated/gen_manifest.json` shall be deterministic JSON using sorted top-level keys or a documented stable key order.

Minimum required fields:

```json
{
  "schema": "trecap_generated_manifest_v1",
  "generator": {
    "name": "scripts/gen_headers.py",
    "version": "0.1.0",
    "timestamp_policy": "not_embedded_in_generated_outputs"
  },
  "sources": [
    {
      "path": "spec/generated/core_config.json",
      "sha256": "..."
    }
  ],
  "outputs": [
    {
      "path": "rtl/include/generated/trecap_core_pkg.sv",
      "sha256": "..."
    }
  ]
}
```

Rules:

```text
- All paths are repository-relative POSIX paths.
- Hashes are lowercase SHA-256 hex strings.
- Source hashes cover canonical file bytes as committed.
- Output hashes cover exact generated output bytes.
- No local absolute paths appear in the manifest.
- No username, hostname, or wall-clock timestamp appears in generated outputs.
```

A build timestamp may be printed in logs, but it shall not make checked generated outputs drift.

## Cross-language consistency requirements

The generator shall check at least these invariants before writing outputs:

```text
CSR map:
  - every offset is 32-bit aligned;
  - no two registers share an offset;
  - access type is one of R, W, R/W, W1P, W1C, or documented extension;
  - bit fields do not overlap;
  - reset values fit the declared width;
  - 64-bit low/high pairs have explicit snapshot/commit semantics where required.

Packet layout:
  - packet_type values are unique;
  - payload size rules fit the Revision G UDP no-fragmentation bound;
  - fixed-size payload byte counts match field offsets;
  - reserved flags are declared;
  - STATUS payload size remains exactly the generated value used by HPS and PC parser.

Core config:
  - D equals L + G for the current baseline;
  - H equals L/2 for the current baseline;
  - all widths are positive integers;
  - Wmag2 is wide enough for the declared canonical bin width.

Interface types:
  - packed structs have explicitly declared widths;
  - no implicit C padding is assumed;
  - SV/C/Python field order is identical where a payload crosses language boundaries.
```

## Generated SystemVerilog package style

Generated SV packages shall use:

```systemverilog
package trecap_core_pkg;
    localparam int unsigned T_N = 12;
    localparam int unsigned T_L = 256;
    // ...
endpackage
```

Rules:

```text
- Use localparam for constants.
- Use typedef enum logic [...] for generated enums.
- Use packed structs for payload/interface records.
- Avoid macros except include guards if absolutely necessary.
- Do not import hand-written packages from generated packages.
- Do not include board-specific paths or artifact host paths.
```

Generated packages shall not depend on RTL modules. The compile order remains packages, interfaces, modules, and then tops.

## Generated C header style

Generated C headers shall be C11-compatible and shall not require non-standard compiler extensions for constants.

Required style:

```c
#ifndef TRECAP_PACKET_H_
#define TRECAP_PACKET_H_

#include <stdint.h>

#define TRECAP_PACKET_MAGIC UINT32_C(0x54524350)

enum trecap_packet_type {
    TRECAP_PACKET_WAVE = 0x0001u,
};

#endif  /* TRECAP_PACKET_H_ */
```

Rules:

```text
- Use fixed-width integer types from stdint.h.
- Use explicit little-endian load/store helpers in hand-written HPS C code.
- Do not rely on host struct padding for wire-format parsing.
- Generated offsets shall be numeric constants, not duplicated in hand-written code.
```

## Generated Python style

Generated Python shall be importable without hardware attached and without third-party GUI dependencies.

Required style:

```python
# AUTO-GENERATED - DO NOT EDIT
PACKET_MAGIC = 0x54524350
PACKET_TYPE_WAVE = 0x0001
STATUS_PAYLOAD_BYTES = 72
```

Rules:

```text
- Keep generated Python dependency-free.
- Parser code may live in hand-written dashboard modules.
- Generated Python shall expose constants and struct format strings only.
- The dashboard shall not duplicate packet offsets manually.
```

## Interaction with filelist generation

Header generation and filelist generation are related but separate:

```text
scripts/gen_headers.py      owns generated SV/C/Python constants.
scripts/gen_filelists.py    owns compile-order filelists.
```

`make rtl-filelist` shall not invent constants. `make gen-headers` shall not decide compile order. A change that adds a new package or module usually needs both:

```text
1. schema/header update for constants or typedefs;
2. filelist generator update for compile order.
```

## Manual edit guard

The pre-commit hook should reject staged manual edits to generated outputs unless the relevant source schema or generator script is also staged.

Allowed generated-output changes:

```text
- schema changed and generated outputs changed accordingly;
- generator changed and generated outputs changed accordingly;
- generated output normalized after tool bugfix, with manifest updated.
```

Suspicious generated-output changes:

```text
- only a generated header changed;
- generated header changed but manifest hash did not;
- generated output contains a timestamp, hostname, or absolute path;
- generated output changes only because local JSON key ordering changed.
```

| Target | Meaning |

## Review procedure for a new CSR

To add a CSR field:

```text
1. Edit spec/generated/csr_map.json.
2. Update spec/schemas/csr_map.schema.json only if the schema lacks the needed shape.
3. Run make gen-headers.
4. Run make check-generated.
5. Confirm trecap_csr_pkg.sv and trecap_csr.h both changed consistently.
6. Confirm HPS C and RTL code include generated constants, not hand-coded offsets.
7. Update docs/architecture/memory_map.md if the visible map changed.
8. Update docs/architecture/interface_contracts.md if the transfer semantics changed.
```

Do not add a CSR offset directly inside `trecap_csr_bank.sv` or `sw/hps/src/csr_map.c`.

## Review procedure for a new packet field

To add or change a packet field:

```text
1. Edit spec/generated/packet_layouts.json.
2. Regenerate headers.
3. Confirm the SV packetizer, HPS validator, and Python parser consume generated offsets.
4. Confirm payload size remains within the no-fragmentation bound.
5. Confirm reserved fields and flags are still explicitly checked.
6. Update docs/architecture/interface_contracts.md and this file if the flow changes.
```

Do not patch the PC parser first. The parser is a consumer, not the authority.

## Review procedure for an interface type

To add or change an interface payload type:

```text
1. Edit spec/generated/interface_types.json.
2. Regenerate `trecap_iface_pkg.sv`.
3. Check all RTL users compile against the generated typedef.
4. If C or Python mirrors the type, regenerate those outputs too.
5. Update docs/architecture/module_api.md if port rules change.
```

Do not define a second hand-written struct with similar fields under `rtl/telemetry/` or `rtl/hps_bridge/`.

## Failure policy

A generated-contract failure is not a cosmetic failure. Treat it as an architecture issue.

| Failure | Meaning | Required action |
| --- | --- | --- |
| Schema validation fails | Source contract is malformed | Fix JSON/schema before writing RTL. |
| Duplicate CSR offset | Ambiguous register map | Fix `csr_map.json`. |
| Duplicate packet ID | Ambiguous parser behavior | Fix `packet_layouts.json`. |
| Generated output drift | Checked output stale or hand-edited | Regenerate or revert. |
| Manifest drift | Generator not deterministic or output changed | Fix generator or commit complete set. |
| C/Python/SV constants disagree | Generator bug | Stop implementation and fix generator. |

Do not work around a generator failure by copying constants by hand into RTL, C, or Python.

## Keeping generated contracts usable

A contract update includes its input JSON/schema, the generator change when needed,
the complete emitted SV/C/Python set, and the generation manifest. The generated
files remain committed, deterministic, and independent of local machine paths.
Do not leave a partially updated set for another consumer to interpret.

## Non-negotiable rules

```text
Generated files are committed, but not hand-edited.
Schema files are reviewed like source code.
SV/C/Python constants come from the same schemas.
CSR map is normative, not a recommendation.
Packet layout is normative, not parser folklore.
No RTL, HPS C, or Python dashboard file may define a private duplicate of a shared offset or payload size.
```
