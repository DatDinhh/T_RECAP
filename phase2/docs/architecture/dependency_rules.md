# Dependency rules

File class: **[1] hand-written architecture document**.

This document defines allowed and forbidden dependencies for the T-RECAP Phase 2 implementation repository. It is the enforcement companion to `repo_architecture.md`, `module_inventory.md`, `interface_contracts.md`, and `module_api.md`.

This is not a verification architecture document.

## Authority

The active integrated Phase 2 specification under `docs/specs/` is the authority. This file converts that specification into repository dependency rules that can be checked by review, filelists, and scripts.

## Core principle

The dependency graph must preserve this ownership boundary:

```text
source adapters
    -> core algorithm
    -> valid-only taps
    -> telemetry packet formatting
    -> HPS bridge / DDR ring writer
    -> HPS UDP streamer
    -> PC dashboard
```

Dependencies may flow downstream toward integration. Dependencies shall not flow backward from demo/transport layers into the core algorithm.

## Step-8 compile-surface ownership

`filelists/rtl_telemetry.f` is a pure formatter closure: generated/hand-written
packages, common/interface helpers, packetizers, scheduler, packet FIFO, and
`trecap_telemetry_top`. It shall not acquire FFT/core files or the composed top.

`filelists/rtl_core_telemetry.f` is the reusable standalone composition closure.
It adds FFT/core dependencies followed by telemetry and
`trecap_core_telemetry_top`; it shall not acquire source selection, HPS/DDR,
Platform Designer, or board files. The DE1-SoC full filelist must keep
`trecap_source_core_integration` as its sole mathematical-core owner and must not
also compile/instantiate the standalone composition.

Within either path, dependencies include valid-only taps and authoritative core
counters/metric aggregates flowing downstream. `record_ready`, FIFO fullness,
packet enables, telemetry soft reset, and DDR status shall not flow backward into
source/core ready, FFT/IFFT, WOLA, or core metric accumulation.

## Step-9 physical-board closure ownership

`filelists/rtl_de1soc_full.f` and `filelists/quartus_de1soc.qsf.inc` own the
hand-written full-board closure. They list Platform Designer, the Step-16 audio
PLL/I2C/I2S owners, LTC2308, source/core, telemetry/HPS, and physical-board
owners once in dependency order.
They exclude the standalone core-plus-telemetry top and vendor-generated
`system` HDL; the latter enters through the generated QIP flow.

`de1_soc_trecap_top` may bind pins and owners but may not synthesize replacement
core taps, return safe-idle CSR/DDR responses, or place codec readiness in the
mathematical y-ready path. Core-y audio monitoring is best-effort/drop-on-FIFO-
full with dedicated accounting; it never backpressures the mathematical core.
The LTC2308 configuration is a real six-bit next-conversion value and not a
constant board scaffold.

## Step-10 clock/reset ownership

`clock_reset_ctrl.sv` is the sole owner of full-board fabric hard-reset
conditioning. It qualifies released `KEY[0]` for 20 ms, combines that result
with the active-low HPS-to-FPGA reset, and uses one at-least-two-stage
`trecap_reset_sync` to produce `rst_n_platform`. `de1_soc_trecap_top.sv` may wire
that net but may not instantiate a second fabric reset synchronizer. All fabric
owners share `clk_fabric = CLOCK_50` and the same reset release.

Sample, STATUS, METRICS, and heartbeat events are fractional clock-enable pulses
and shall not appear in an `always_ff` event control. Telemetry soft reset is a
synchronous clear and shall not be ANDed into an active-low asynchronous reset.
Alternate board clocks may terminate at the physical top but may not drive
active logic. A future split-clock build must add real CDC architecture rather
than relabeling the current same-clock nets.

## Forbidden RTL dependencies

These are hard failures:

```text
rtl/core/ shall not import rtl/telemetry/.
rtl/core/ shall not import rtl/hps_bridge/.
rtl/core/ shall not instantiate source adapters.
rtl/core/ shall not know packet type IDs, UDP payload layout, DDR header layout, CSR offsets, HPS addresses, or Platform Designer bus names.
rtl/telemetry/ shall not contain trecap_ddr_ring_writer.sv.
rtl/telemetry/ shall not own RING_BASE, RING_SIZE_BYTES, producer pointer commit, consumer pointer commit, or WRAP record generation.
rtl/hps_bridge/ shall not contain audio codec pin logic or board LED demo logic.
rtl/platform/de1soc/ shall not reimplement STFT/WOLA arithmetic.
rtl/top/ shall not hide new algorithm behavior outside owned submodules.
rtl/platform/de1soc/de1_soc_trecap_top.sv shall not add a second fabric reset synchronizer.
clock-enable ticks shall not clock sequential logic.
telemetry soft reset shall not create a derived asynchronous reset.
```

Bad dependency example:

```text
rtl/core/trecap_mag2_mask.sv imports trecap_packet_pkg.sv to decide whether SPEC129 is enabled.
```

Why bad: spectrum packet selection is telemetry/display behavior. The core mask decision is algorithm behavior and cannot depend on packet mode.

Good dependency example:

```text
rtl/core/trecap_mag2_mask.sv imports trecap_core_pkg.sv for T_W_MAG2 and receives thr2_active from control logic.
rtl/telemetry/trecap_spec_packetizer.sv imports trecap_packet_pkg.sv for SPEC129 payload size.
```

## Filelist dependency rules

`filelists/*.f` are generated build-order contracts. Active build targets consume filelists; they do not guess source order.

Required filelists:

```text
filelists/rtl_core.f
filelists/rtl_core_plus_fft.f
filelists/rtl_telemetry.f
filelists/rtl_hps_bridge.f
filelists/rtl_de1soc_full.f
filelists/quartus_de1soc.qsf.inc
```

Rules:

```text
Packages compile before interfaces.
Interfaces compile before modules.
Common wrappers compile before modules that instantiate them.
Core modules compile before top variants that instantiate them.
Telemetry filelist shall not include hps_bridge DDR writer modules.
HPS bridge filelist may include generated packet/record typedefs and hps_bridge modules.
Full DE1-SoC filelist is the only filelist that includes platform/de1soc wrappers.
```

If a file is not in the correct generated filelist, it is not part of that build cut.

## HPS dependency rules

HPS software depends on generated C headers and runtime config:

```text
sw/hps/include/generated/trecap_csr.h
sw/hps/include/generated/trecap_packet.h
sw/hps/config/trecap_hps_config.json
```

Forbidden:

```text
Hard-coded CSR offsets in C source.
Hard-coded packet payload sizes in C source.
FFT/IFFT/WOLA/mask computation in HPS code.
Using Linux virtual address as RING_BASE.
Blocking forever in sendto() while holding back Rd advancement.
```

Required:

```text
HPS checks transport VERSION before enabling telemetry.
HPS validates DDR record headers and payload lengths before UDP forwarding.
HPS handles WRAP records with effective length R - off(Rd).
HPS uses RING_WR_SNAPSHOT for producer pointer and RING_RD_COMMIT for consumer pointer.
HPS command server validates source IP, command length, magic, version, CRC field, and argument ranges.
HPS command server validates the configured production source port as well as IP.
HPS command bridge owns every v2 non-PING RFC1982/cache decision, including READ_STATUS_VERSION.
HPS command bridge obtains ring geometry only from validated local runtime/reservation state.
HPS command bridge owns RESET -> CONFIGURE -> ENABLE, a CONTROL=0 recovery attempt, verified disabled readback, and a software RESET_REQUIRED lock when hardware disable cannot be proven.
HPS command bridge routes source/packet/decimation/spectrum mutations in both wire versions through disabled-controls, transport-epoch-idle, replay-idle, readback, and safe restore.
```

The simple parser may not issue direct live CSR writes for those safe control
mutations. PING remains outside the mutation ledger and returns diagnostic
STATUS only. The canonical listener is `192.168.10.2:5006`; wildcard binding or
first-PING peer learning is an explicit lab/test override.

## PC dashboard dependency rules

PC dashboard depends on generated Python constants:

```text
sw/pc_dashboard/generated/trecap_packet.py
```

Forbidden:

```text
Duplicating packet offsets by hand in packet_parser.py.
Duplicating command versions, type IDs, result offsets, dispositions, or reject reasons in command_client.py.
Using dashboard data as bit-accurate signoff evidence.
Assuming no packet loss.
Merging dma_drop_count and packet_fifo_drop_count.
```

Required:

```text
Parser rejects malformed headers, bad flags, and wrong payload sizes.
Receiver handles sequence gaps using modulo-2^32 arithmetic.
GUI redraw is decoupled from UDP receive.
Dashboard displays STATUS, WAVE, METRICS, and one spectrum mode after T0/full demo.
Command client binds source port 5007 in the canonical direct-link profile.
Command client validates exact 32-byte v2 results and echoed command type/sequence.
```

## Dependency review checklist

For every new file, answer these questions before committing:

```text
[ ] Which layer owns this file?
[ ] Is the file path consistent with that layer?
[ ] Does it import only allowed packages/headers?
[ ] Does it duplicate any generated constant?
[ ] Does it create a backward dependency from transport/demo into core?
[ ] Does it introduce a hidden board dependency into rtl/core/?
[ ] Does it use generated filelists rather than ad-hoc source order?
[ ] Does it preserve C0 independence if it is part of the core path?
[ ] Does it preserve T0 transport ownership if it is part of telemetry/HPS bridge?
[ ] Does it keep verification-specific architecture out of this implementation repo revision?
```
