## Current architecture milestone

Step 17 completes the checked-in ADC source architecture for the pinned DE1-SoC
Rev-H/LTC2308 contract. The controller uses one 50 MHz fabric domain, a
100 ksample/s exact-average scheduler, a 2.5 MHz registered serial output, and a
preserved two-flop synchronizer on the single-bit `ADC_DOUT` return before
assembling a 12-bit straight-binary word in fabric. The six-bit next-conversion
command selects single-ended/unipolar/awake operation, latches `SW[6:4]` only on
entry to the ADC epoch, waits 92 cycles after enable/abort before accepting a
request, and discards the first previous-configuration result.
The adapter recenters at code 2048 before the guarded source mux. The explicit
`de1soc_adc_demo` profile neither replaces BRAM replay as the default/correctness
path nor blocks the independent LINE-IN profile.

The Step-17 source checker/model and profile checks are not native RTL compile
or simulation, Quartus, TimeQuest, measured CONVST/SCLK/DOUT timing, analog
linearity/channel identity, or live-board evidence. Older DE1-SoC revisions may
use a different ADC, so bring-up must verify the PCB revision and device marking.

Step 15 previously completed the checked-in PC dashboard source architecture. The receiver
and strict generated parser remain independent of GUI redraw. Bounded display
buffers feed dedicated `x[n-D]`/`y[n]` waveform and error views, a latest-spectrum
view, and a bounded SPEC64/SPEC129 spectrogram history whose time axis is the
transport `frame_idx`. The display derives packet rate from receive timestamps
and keeps local sequence gaps, PC queue/parser/truncation state, HPS malformed
and UDP-send state, FPGA packet-FIFO drops, FPGA DDR-writer drops, overflow, and
wire `payload_truncated` state visibly distinct.

Live command controls do not create a second command path. They enqueue work for
one persistent asynchronous serialized `CommandClient`, so version-2 sequence
state remains monotonic and telemetry receive/GUI refresh do not wait on command
I/O. Result disposition, reject reason, raw STATUS/VERSION, timeout, and local
failure remain visible. Capture replay feeds the same parser and buffers using
the recorded receive timestamp; validated append extends the existing framed
capture without writing a second magic header.

`make dashboard-step15-test` and cumulative `make step15-source` are host/source
evidence only. They do not establish live HPS/FPGA UDP, ten-minute GUI soak,
hardware CSR application/result, Ethernet-disconnect non-stall behavior, or
bit-accurate signoff.

Step 14 previously completed the checked-in versioned PC-to-FPGA command source
path. The exact Revision-G version-1 request remains 28 bytes, seven commands,
and no generic result. An explicit version 2 reuses the 28-byte request, adds
command types `0x0008..0x000E`, and returns one exact 32-byte result for every
version-2 non-PING request. The HPS listener binds `192.168.10.2:5006`, requires
the configured production peer `192.168.10.1:5007`, applies RFC1982
duplicate/cache rules, owns RESET-to-CONFIGURE-to-ENABLE lifecycle and replay
admission, and consumes generated CSR minor 1.8. PING remains diagnostic STATUS
only and does not touch the version-2 ledger. Its source checker, non-native RTL
structural/model checker, and HPS/PC host-test sources are implementation gates,
not live UDP, Linux mapping, native RTL simulation, Quartus, or hardware evidence.

Step 13 previously completed the checked-in HPS transport from the frozen CSR and
reserved-DDR interfaces to Revision-G UDP. It implements strict configuration
and live-reservation admission, full record and WRAP validation, bounded UDP
send/drop/consumer-commit behavior, an exactly-once malformed latch with an
explicit re-arm sequence, and UDP-only diagnostic STATUS mode. Its source
checker and RAM-backed host test do not constitute active-DTB, native HPS
`/dev/mem`, physical Ethernet, systemd, FPGA, Quartus, or board evidence.

Step 12 previously froze the DDR-ring ownership and Linux reservation source
contract.
The FPGA exclusively advances the producer pointer `W`; the HPS exclusively
advances the consumer pointer `Rd`; WRAP consumes the exact physical tail; and a
transport-reset epoch establishes a defined empty-ring baseline before traffic
is re-enabled. The sole official reservation mechanism is the no-map DTS source
`platform/de1soc/linux/trecap_reserved_memory.dtsi`. The source contract,
checker, and directed ownership/WRAP/reset testbench do not constitute compiled
DTB, Linux boot/runtime, HPS runtime, or physical-board evidence.

Step 11 previously closed the deterministic BRAM-replay source hierarchy from
the replay source through exact mathematical-core completion and a post-core
STATUS commit at the HPS-visible DDR boundary. Its filelist, end-to-end
testbench, and native runners are retained as the Step-11 historical gate; no
accepted simulator execution evidence is implied by their presence.

Step 10 previously froze the source clock/reset architecture. The implemented board path
has one active 50 MHz fabric domain, `clk_fabric`, driven directly by `CLOCK_50`.
`clock_reset_ctrl.sv` owns the entire hard-reset path: a 20 ms stable-high
qualification of released `KEY[0]`, combination with the active-low HPS-to-FPGA
reset, and one `trecap_reset_sync` of at least two stages producing canonical
`rst_n_platform`. All fabric owners release simultaneously from that net. The
board top contains no second reset synchronizer, while C0 remains independent of
HPS and Platform Designer through its separate core-only tops.

The 48 kHz BRAM/audio sample, 10 Hz STATUS, 30 Hz METRICS, and 2 Hz heartbeat-
toggle events are exact-average fractional clock-enable pulses in `clk_fabric`;
they are not generated clocks. The LTC2308 wrapper uses the same phase-
accumulator method for
its separate continuous 100 kHz request cadence and treats the 2.5 MHz
`ADC_SCLK` only as a registered protocol output. The off-chip `ADC_DOUT` bit
passes a preserved two-flop synchronizer before fabric-domain word assembly.
Telemetry soft reset is implemented as a synchronous transport
clear and cannot assert a derived asynchronous reset or reset the mathematical
core. `CLOCK2_50`, `CLOCK3_50`, and `CLOCK4_50` are reserved, and split-clock
fabric operation is unsupported until a real CDC redesign is implemented. The
audio BCLK receive and transmit edge domains have local edge-specific reset
synchronization. Step 16 adds a peripheral-only 12.288 MHz fractional PLL output
for `AUD_XCK`, lock-qualified FPGA-I2C initialization of the WM8731 at address
`0x1a`, and a 48 kS/s, signed 16-bit, codec-master I2S endpoint. It does not
change the single 50 MHz fabric-clock rule.

Step 9 previously closed the physical DE1-SoC board-top source composition. The class `[1]`
`rtl/platform/de1soc/de1_soc_trecap_top.sv` now binds the generated Platform
Designer CSR and F2SDRAM interfaces, audio and LTC2308 platform wrappers, the
sole source/core owner, the telemetry/HPS owner, and real board status. It does
not generate synthetic taps, substitute safe-idle bus responses, tie the ADC
configuration to a placeholder, or discard core-y observability. Core y remains
always accepted. Audio line-out uses a fabric-to-BCLK async FIFO as a
best-effort monitor, so transmit FIFO pressure cannot backpressure the
mathematical core. Receive frames use a separate BCLK-to-fabric async FIFO.
Dedicated saturating 64-bit RX-overflow, TX-overflow, and TX-underflow counters
remain board diagnostics rather than being assigned to unrelated generated CSR
overflow bits.

The Step-16/17 source implementations are not board proof. The HPS-side codec mux
must leave `HPS_I2C_CONTROL` low while the FPGA owns the open-drain codec I2C
bus; FPGA logic observes that grant and never drives the HPS control. The
explicit `de1soc_linein_demo` profile is available, but BRAM replay remains the
correctness prerequisite. External audio/ADC timing is a Step-18 gate, while
Quartus/TimeQuest, I2C ACK, measured clocks, ADC analog/channel behavior, and
live-sample evidence remain Step-20 work.

Step 8 previously closed the reusable core-plus-telemetry source composition. The class
`[1]` `rtl/top/trecap_core_telemetry_top.sv` now instantiates exactly one real
`trecap_core_top` and exactly one `trecap_telemetry_top`. Normalized samples,
finite-stream geometry, and tail ticks enter the mathematical core first; direct
valid-only taps then feed telemetry without any ready path returning to source,
frame scheduling, FFT/IFFT, WOLA, output, or metric accumulation. The dedicated
`filelists/rtl_core_telemetry.f` contains the core/FFT and telemetry dependencies,
while `filelists/rtl_telemetry.f` remains telemetry-only.

STATUS consumes authoritative core sample/frame counters rather than rebuilding
them from delayed taps. METRICS consumes core-owned error aggregates and combines
them with telemetry's eligible-bin aggregates. In the board hierarchy, the raw
CSR `CLEAR_METRICS` request is queued by the source/core layer and the exact safe
apply pulse clears both owners, so the metric epoch cannot split. Runtime-invalid
telemetry controls fail closed, in-flight records drain atomically, and CSR W1C
flags are set from new-fault events instead of sticky feedback levels.
Source discontinuity also gates one telemetry admission cycle: partial
collections are discarded, a selected record finishes atomically, unselected
candidates remain locally drained through their final beat, and the packet FIFO
is preserved, preventing mixed-source WAVE payloads.

Step 7 previously closed the source-to-core implementation path. The class `[1]`
`rtl/top/trecap_source_core_integration.sv` instantiates BRAM replay, audio and ADC
adapters, the diagnostic source, the safe source mux, and `trecap_core_top.sv`. It
owns source pacing, guarded source-mode epochs, discontinuity clearing, exact
finite BRAM-replay analysis/tail routing, safe-boundary return signals, and
new-fault event mapping for only the generated `OVERFLOW_FLAGS` meanings that
match exactly: arithmetic overflow, ring/history overflow, and source-mode error.
Other replay/source, adapter-overrun, ADC-protocol, and core-protocol faults stay
on dedicated status outputs instead of being silently assigned unrelated CSR
bits. Step 11 superseded the earlier single-LED aggregation with distinct busy,
end-to-end completion, and fault indicators. The core taps are valid-only;
telemetry has no ready or throttle path back into source selection or core math.

`rtl/platform/de1soc/de1_soc_trecap_top.sv` is the physical Quartus board top. It
instantiates the audio/ADC platform capture wrappers, the source-to-core layer,
`trecap_de1soc_full_top.sv` as the pin-agnostic telemetry/HPS/DDR logical top, and
the Step-6 Platform Designer boundary. The board source path now comes exclusively
through the platform capture wrappers and source/core integration layer. Real
core taps, counters, frame/config boundaries, source-safe boundaries, and
the explicitly mapped source-mode fault events now close the forward and reverse
integration loops. Dedicated source/core/platform fault levels remain local
observability, not additional CSR fields.

This remains a source-implementation milestone, not hardware verification. The
Step-14 RTL/HPS gates and Step-15 PC host gates do not establish live PC/HPS/FPGA
execution evidence. Quartus 20.1 must normalize and generate
the Qsys
`system` HDL/QIP and SOPCINFO, the generated ABI checker must pass, the DTS must
be compiled and proven active in a booted Linux system, and the full design still
needs Quartus/TimeQuest compile and timing evidence, physical BRAM replay, and
board audio/ADC bring-up.

## System direction

The full forward path is:

```text
BRAM replay / LINE-IN audio / ADC / diagnostic source
    -> trecap_source_core_integration
    -> FPGA STFT/WOLA selective-suppression core
    -> non-stalling FPGA telemetry taps
    -> FPGA telemetry formatter
    -> FPGA packet FIFO / priority shedder
    -> FPGA DDR record builder
    -> FPGA DDR ring writer
    -> HPS DDR ring reader
    -> HPS UDP streamer over Ethernet
    -> PC dashboard
```

The reverse control path is:

```text
PC command
    -> HPS command parser
    -> HPS command bridge / sequence-result cache
    -> generated CSR writes and readback
    -> FPGA CSR shadow/commit/replay logic
    -> safe-boundary update or retained replay result
```

The correctness path is separate:

```text
reference-model artifacts
    -> coefficient/vector/reference-output files
    -> RTL simulation comparison
    -> BRAM replay on FPGA
    -> artifact comparison
```

Ethernet telemetry and PC plots are observability and demonstration infrastructure. They are not the bit-accurate signoff authority.

## Non-negotiable rules

1. `rtl/core/` shall build without HPS, DDR ring, Ethernet, UDP, dashboard, board pins, Platform Designer, audio wrapper, or ADC wrapper.
2. BRAM replay and artifact-driven comparison shall exist before live audio or Ethernet demo work is treated as active implementation.
3. CSR offsets, packet IDs, packet payload sizes, status bits, version numbers, source-mode IDs, and core constants shall come from generated shared headers.
4. `trecap_ddr_ring_writer.sv` belongs only under `rtl/hps_bridge/`.
5. `rtl/telemetry/` formats records and may drop records. It does not write DDR.
6. Telemetry shall not backpressure sample input, frame scheduling, FFT/IFFT, WOLA, or core metrics accumulation.
7. HPS software shall not compute FFT, IFFT, magnitude-squared masks, WOLA reconstruction, or sample-by-sample reconstruction error.
8. PC dashboard software shall not be used as a core correctness authority.
9. Generated files shall not be hand-edited. Change schemas or generators, then regenerate.
10. Legacy Phase 1 files shall stay under `legacy/phase1/` and shall not compile into the Phase 2 root build.

## Failure behavior

| Failure | Required behavior |
| --- | --- |
| Packet FIFO full | Drop telemetry event or lower-priority resident packet; increment `PACKET_FIFO_DROP_COUNT`; do not stall core. |
| DDR ring full | Drop at writer stage; increment `DMA_DROP_COUNT`; do not stall core. |
| DDR waitrequest persists | Drop or defer according to writer policy; expose status; do not stall core. |
| Ethernet disconnected | HPS drops UDP datagrams or send failures; advances consumer pointer; core continues. |
| Malformed DDR record | HPS disables telemetry and requires soft reset/reconfiguration; no byte-scanning recovery in baseline. |
| Illegal command | Reject and count; do not modify active state. |
| Threshold update | Use shadow registers and frame-boundary commit. |
| Source-mode update | Reset affected stream state or mark discontinuity; do not mix metrics silently. |
