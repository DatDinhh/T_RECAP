# Generated contracts

File class: **[1] hand-written architecture document**.

This document defines the generated-contract flow for `T_RECAP_Phase2`. It specifies which files are source-of-truth inputs, which files are generated outputs, what generators must guarantee, and how drift is checked.

Manual duplication of shared constants across SystemVerilog, HPS C, Python dashboard code, and reference-model tooling is forbidden.

## Authority

The active integrated Phase 2 specification under `docs/specs/` is the authority. This file converts the spec's generated shared contract flow into repository implementation rules.

## Provenance tags

```text
[0] imported from the Phase 2 reference-model zip, or generated by that reference model
[1] hand-written implementation, documentation, or config source file
[2] generated file; do not edit by hand
```

This file is `[1]`.

Important distinction:

```text
A file in a directory named generated/ is not automatically [2].
Some JSON files under spec/generated/ are source-of-truth inputs and are [0] or [1].
The SV/C/Python headers, filelists, and manifest emitted by scripts are [2].
```

All of these must be generated or consumed from generated files.

## Generated-file banner

Every generated output shall contain a banner at the top. Required phrase:

```text
AUTO-GENERATED - DO NOT EDIT
```

Recommended full banner content:

```text
AUTO-GENERATED - DO NOT EDIT
Generator: scripts/gen_headers.py
Generator version: <version>
Source schemas: <list>
Source hash: <sha256>
Output hash recorded in: spec/generated/gen_manifest.json
```

For SystemVerilog, use comments:

```systemverilog
// AUTO-GENERATED - DO NOT EDIT
```

For C headers:

```c
/* AUTO-GENERATED - DO NOT EDIT */
```

For Python:

```python
# AUTO-GENERATED - DO NOT EDIT
```

## Generation manifest contract

`spec/generated/gen_manifest.json` shall contain enough data to prove deterministic regeneration.

Minimum shape:

```json
{
  "schema": "trecap_generated_manifest_v1",
  "generator": {
    "name": "scripts/gen_headers.py",
    "version": "0.1.0",
    "python": "3.x",
    "timestamp_policy": "not_embedded_in_generated_outputs"
  },
  "sources": [
    {
      "path": "spec/generated/core_config.json",
      "sha256": "..."
    }
  ],
  "outputs": [
    {
      "path": "rtl/include/generated/trecap_core_pkg.sv",
      "sha256": "..."
    }
  ]
}
```

Rules:

```text
Do not embed wall-clock timestamps in generated outputs.
If a timestamp is needed for human debugging, put it only in the manifest and exclude it from drift-sensitive output hashes.
Sort JSON object keys where possible for deterministic output.
Sort generated declarations by offset/order fields from the source schema, not Python dictionary accident.
Use LF line endings.
Use stable formatting.
```

## CSR map contract

`spec/generated/csr_map.json` owns:

```text
CSR offset
register name
access type
reset value
field bit positions
write semantics: level, W1P, W1C, shadow, commit, snapshot
owner: FPGA CSR, FPGA core, FPGA writer, HPS-patched status, reserved
legal value ranges
```

Generated outputs:

```text
rtl/include/generated/trecap_csr_pkg.sv
sw/hps/include/generated/trecap_csr.h
```

CSR source entry should include:

```json
{
  "name": "VERSION",
  "offset": "0x004",
  "access": "R",
  "reset": "0x00010008",
  "description": "Transport/CSR capability version major=1 minor=8",
  "fields": [
    {"name": "major", "msb": 31, "lsb": 16},
    {"name": "minor", "msb": 15, "lsb": 0}
  ]
}
```

Rules:

```text
CSR map is normative, not recommended.
RTL CSR bank, HPS C, and Python command tooling shall consume generated definitions.
HPS C shall not duplicate offsets manually.
Multiword fields such as THR2 and ring pointers require generated commit/snapshot metadata.
```

## Packet layout contract

`spec/generated/packet_layouts.json` owns:

```text
DDR/UDP magic numeric value
header version
header byte count
packet type IDs
common flag bits
exact payload sizes
payload field offsets
array element sizes and ordering
WRAP packet rule marker
command packet layout
supported command protocol versions and per-command introduced version
exact command-result layout, dispositions, and reject reasons
command valid ranges
UDP max payload/datagram rule
```

Generated outputs:

```text
rtl/include/generated/trecap_packet_pkg.sv
sw/hps/include/generated/trecap_packet.h
sw/pc_dashboard/generated/trecap_packet.py
```

Packet source entry should include:

```json
{
  "packet_type": "STATUS",
  "id": "0x0005",
  "payload_bytes": 72,
  "fields": [
    {"name": "sample_count", "offset": 0, "type": "uint64"},
    {"name": "frame_count", "offset": 8, "type": "uint64"},
    {"name": "packet_fifo_drop_count", "offset": 64, "type": "uint32"}
  ]
}
```

Rules:

```text
Packet payload sizes shall be exact unless the packet type is explicitly variable-size WAVE.
Reserved flags default to reject.
Header CRC is disabled in Revision G and generated constants shall reflect that.
Python parser shall validate generated sizes, not handwritten sizes.
HPS shall reject records whose payload_bytes do not match generated rules.
Command protocol v1 remains exactly seven types and no generic result.
Command protocol v2 reuses the exact 28-byte request, adds types 0x0008..0x000E, and defines the exact 32-byte result.
Telemetry common-header version remains 1 when transport/CSR capability minor advances to 1.8.
```

## Generated filelist contract

`gen_filelists.py` owns filelist generation.

Minimum generated filelists:

```text
filelists/rtl_core.f
filelists/rtl_core_plus_fft.f
filelists/rtl_telemetry.f
filelists/rtl_hps_bridge.f
filelists/rtl_de1soc_full.f
filelists/quartus_de1soc.qsf.inc
```

Filelist rules:

```text
Packages before interfaces.
Interfaces before modules.
Common primitives before modules that instantiate them.
Core before top variants.
Telemetry without DDR writer.
HPS bridge with DDR writer.
Full DE1-SoC with platform wrappers.
```

Generated filelists shall not include legacy Phase 1 files from root or `legacy/phase1/`.

## Commit policy

Generated headers and filelists are committed because Quartus, C builds, and Python imports need a usable checkout.

Policy:

```text
[1] schema/source files are reviewed by humans.
[1] generator scripts are reviewed by humans.
[2] generated outputs are committed but not manually edited.
make check-generated regenerates and fails on drift.
pre-commit should guard obvious hand edits to generated outputs.
```

If generated output changes, the commit should include:

```text
source schema/script change
regenerated output files
gen_manifest update
brief explanation in commit message
```

Do not commit generated changes without the source change that explains them.

## R0-tolerant behavior

During R0, the repository may not yet have `scripts/gen_headers.py` or generated files. Therefore:

```text
pre-commit hooks may skip check-generated if R1 scripts do not exist.
Makefile targets should fail clearly when a requested script is missing.
Docs may describe generated outputs before they exist.
```

Once R1 begins, missing generated files are build failures.

## `make gen-headers` contract

Command:

```bash
make gen-headers
```

Required behavior:

```text
Read source JSON files.
Validate against schemas when schemas are available.
Emit SV/C/Python generated outputs.
Emit gen_manifest.json.
Use deterministic formatting and LF endings.
Return nonzero on schema error, missing required field, duplicate CSR offset, duplicate packet ID, invalid range, or generated-output write error.
```

## `make check-generated` contract

Command:

```bash
make check-generated
```

Required behavior:

```text
Regenerate all generated outputs.
Compare regenerated output with checked-in files.
Fail if any checked-in generated output differs.
Fail if gen_manifest differs.
Fail if generated file is missing AUTO-GENERATED banner.
Return zero only when generated outputs are deterministic and committed.
```

Recommended implementation options:

```text
Use temporary output directory and compare bytes.
Or regenerate in place then run git diff --exit-code on generated files.
```

The temporary-directory method is cleaner because it avoids modifying the working tree on failure.

## `make rtl-filelist` contract

Command:

## Add/change CSR procedure

To add or change a CSR:

```text
1. Edit spec/generated/csr_map.json.
2. Update spec/schemas/csr_map.schema.json if the schema needs a new field kind.
3. Run make gen-headers.
4. Run make check-generated.
5. Update RTL CSR bank implementation.
6. Update HPS CSR access code if new behavior is needed.
7. Update docs/architecture/interface_contracts.md or module_api.md if the public API changed.
8. Run make compile-hps-bridge and make hps-build.
```

Forbidden:

```text
Adding a `#define` offset directly in C.
Adding a `localparam` CSR offset directly in SV.
Adding an ungenerated Python constant in command_client.py.
```

## Add/change packet procedure

To add or change a packet:

```text
1. Edit spec/generated/packet_layouts.json.
2. Update packet_layouts schema if needed.
3. Run make gen-headers.
4. Run make check-generated.
5. Update the packetizer under rtl/telemetry/.
6. Update HPS validation if behavior changed.
7. Update PC parser/dashboard display if needed.
8. Run make compile-telemetry, make hps-build, and make dashboard-import.
```

Reserved packets such as PEAKS and DEBUG shall remain disabled unless exact payload layouts and parser behavior are defined.

## Add/change interface type procedure

To add or change a shared struct/interface:

```text
1. Edit spec/generated/interface_types.json.
2. Update interface_types schema if needed.
3. Run make gen-headers.
4. Run make check-generated.
5. Update SystemVerilog modules using the struct.
6. Regenerate filelists if new interface/module files were added.
7. Run affected compile target.
```

Changing a field name or width is an API break. Do not do it casually.

## Versioning policy

Generated contracts should carry independent version fields:

```text
schema version
core contract revision
transport major/minor VERSION
generator version
gen_manifest schema version
```

Transport rule:

```text
Major version mismatch: HPS rejects telemetry enable.
Minor version mismatch: HPS accepts only if explicitly supported.
```

Generated C/Python constants shall expose the supported version fields so HPS/dashboard do not parse incompatible records silently.

## Endianness and packing policy

Generated packet headers shall state:

```text
little-endian fields
no implicit C padding
exact byte offsets
numeric magic constants, not raw ASCII-string comparison
header_crc disabled in Revision G
one UDP datagram per telemetry record
```

HPS C structures should avoid direct unverified packed-struct overlay on untrusted DDR data. Prefer explicit little-endian load helpers or static assertions for any packed overlay.

## Validation requirements by consumer

### RTL

```text
Imports generated SV packages.
Uses generated widths and constants.
Does not hand-code CSR offsets or packet sizes.
Compiles using generated filelists.
```

### HPS C

```text
Includes generated C headers.
Checks VERSION before enabling telemetry.
Validates header/payload sizes from generated constants.
Uses runtime config for addresses and ports.
```

### PC Python

```text
Imports generated packet constants.
Validates packet sizes/flags/types.
Does not duplicate offsets manually.
```

### Reference model

```text
Consumes generated core config.
Emits artifacts consistent with artifact contract.
Does not define independent conflicting core constants.
```
