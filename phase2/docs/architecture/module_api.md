# Module API contract

File class: **[1] hand-written architecture document**.

This file defines the implementation-facing API rules for modules in `T_RECAP_Phase2`. It is written after `repo_architecture.md`, `module_inventory.md`, and `interface_contracts.md`, and it is intended to make every future SystemVerilog, HPS C, and PC Python module look like it belongs to the same system.

This document is not a verification architecture document. It does not define scoreboards, monitors, coverage, or regression tests.

The APIs are source-complete through Step 17, including the Step-11 BRAM replay
completion boundary, the Step-12 producer/consumer and reservation contracts,
and the Step-13 strict HPS ring consumer, UDP transport, malformed latch/re-arm,
diagnostic STATUS path, and the Step-14 versioned command server/bridge, exact
result/cache contract, safe lifecycle/mutations, and replay-result path. Step 15
closes the dashboard API, Step 16 closes the LINE-IN clock/control/I2S/CDC API,
and Step 17 closes the pinned Rev-H LTC2308 100-kS/s serial, normalization,
source-rate, and profile API. The
checked-in host and structural/model gates are source artifacts; these APIs do
not claim their execution, accepted native RTL simulation, active-DTB or
native HPS runtime, physical Ethernet, systemd, Quartus/TimeQuest, or hardware
operation.

## API design goals

The module API must enforce four things:

```text
1. RTL core can compile without HPS, DDR, Ethernet, dashboard, board pins, or Platform Designer.
2. All cross-language constants come from generated contracts.
3. Telemetry observes the core but never backpressures it.
4. DDR ring ownership is isolated in rtl/hps_bridge/.
```

The API should make wrong wiring obvious. If a core module has a UDP field, CSR offset, DDR pointer, board switch, or HPS address in its port list, the API is wrong.

## Global SystemVerilog package rules

Generated packages are the only source for T-RECAP constants:

```systemverilog
import trecap_core_pkg::*;      // N, L, H, F, G, D, widths, source IDs
import trecap_csr_pkg::*;       // CSR offsets, bit positions, reset values, VERSION
import trecap_packet_pkg::*;    // packet IDs, payload sizes, flags, max sizes
import trecap_iface_pkg::*;     // structs and shared interface types
```

Allowed package usage by layer:

| Layer | Allowed generated packages | Not allowed |
| --- | --- | --- |
| `rtl/common/` | Usually none, or only generic width parameters from callers | T-RECAP contract constants baked into generic utilities |
| `rtl/interfaces/` | `trecap_core_pkg`, `trecap_iface_pkg`, optionally `trecap_packet_pkg` for record interfaces | Platform/HPS physical addresses |
| `rtl/sources/` | `trecap_core_pkg`, `trecap_iface_pkg` | Packet layout, DDR ring layout |
| `rtl/fft/` | `trecap_core_pkg`, `trecap_iface_pkg` | CSR offsets, UDP packet fields |
| `rtl/core/` | `trecap_core_pkg`, `trecap_iface_pkg` | `trecap_csr_pkg`, `trecap_packet_pkg`, DDR/HPS bus types |
| `rtl/telemetry/` | `trecap_core_pkg`, `trecap_packet_pkg`, `trecap_iface_pkg` | Avalon/AXI DDR master details |
| `rtl/hps_bridge/` | `trecap_core_pkg`, `trecap_csr_pkg`, `trecap_packet_pkg`, `trecap_iface_pkg` | Board pins/audio codec pins |
| `rtl/platform/de1soc/` | Any generated package needed for integration | Core arithmetic hidden behind board-specific logic |
| `rtl/top/` | Any generated package needed for integration | New algorithm behavior not present in owned submodules |

Hard-coded duplicates of these values are forbidden in implementation code:

```text
N, L, P, H, F, G, D
W_Qw, W_tw, W_mag2, W_ifft, W_ola
THR2 width and legal range
transport VERSION major/minor
CSR offsets and bit positions
packet type IDs
payload byte counts
STATUS payload size
WRAP packet type
packet-enable bits
source-mode IDs
```

Readable comments may mention baseline values, but executable constants shall come from generated packages/headers.

## SystemVerilog file header contract

Every hand-written RTL file should start with a short ownership header:

```systemverilog
// SPDX-License-Identifier: MIT
// File class: [1] hand-written RTL.
// Layer: rtl/<layer>/
// Owner: <module owner>
// Purpose: <one sentence>
// Contract: <spec/doc anchor>
// Generated dependencies: <packages, if any>
```

Recommended structure:

```systemverilog
`default_nettype none

import trecap_core_pkg::*;
import trecap_iface_pkg::*;

module trecap_example_block #(
    // Public parameters are allowed only when this is a reusable primitive
    // or an integration top. Contract constants shall come from packages.
    parameter int unsigned DEPTH = 16
) (
    input  logic clk,
    input  logic rst_n,

    input  logic in_valid,
    output logic in_ready,
    input  trecap_example_t in_payload,

    output logic out_valid,
    input  logic out_ready,
    output trecap_example_t out_payload
);

    // Implementation.

endmodule

`default_nettype wire
```

`default_nettype none` catches misspelled nets. The final restore to `wire` is included because some third-party or vendor-generated code still assumes the default net type.

## Module naming contract

| Item | Rule | Example |
| --- | --- | --- |
| T-RECAP module | Prefix with `trecap_` | `trecap_frame_scheduler` |
| Board-facing top | Board name may prefix | `de1_soc_trecap_top` |
| Package | Prefix with `trecap_`, suffix `_pkg` | `trecap_packet_pkg` |
| Interface | Prefix with `trecap_`, suffix `_if` | `trecap_sample_if` |
| Source file | One module per file | `trecap_mag2_mask.sv` contains `module trecap_mag2_mask` |
| Generated package | Under `rtl/include/generated/` | `trecap_core_pkg.sv` |
| Vendor wrapper | Use descriptive wrapper name | `platform_designer_wrapper.sv` |

Do not place several unrelated implementation modules in one file. Small typedef-only packages are exceptions.

## Clock and reset port contract

Single-clock module:

```systemverilog
input logic clk,
input logic rst_n,
```

Multi-clock module:

```systemverilog
input logic clk_core,
input logic rst_core_n,
input logic clk_csr,
input logic rst_csr_n,
input logic clk_avmm,
input logic rst_avmm_n,
```

Rules:

```text
Reset is active low and named rst_n or rst_<domain>_n.
Reset deassertion shall be synchronized per clock domain.
A module shall not sample another domain directly without a named CDC primitive or handshake.
Multi-bit CDC shall use async FIFO, snapshot/commit, Gray-coded pointer, or an explicitly documented equivalent.
```

## Parameter ownership contract

There are three legal parameter classes.

| Class | Owner | Allowed in | Rule |
| --- | --- | --- | --- |
| Contract constants | `spec/generated/*.json` -> generated packages | All modules | Never redefined in leaf RTL. |
| Public integration parameters | Top-level wrappers | `rtl/top/`, `rtl/platform/de1soc/` | May select profile/top behavior, not arithmetic contract. |
| Generic primitive parameters | Reusable utilities | `rtl/common/` | May define width/depth only; shall not redefine T-RECAP constants. |

Bad:

```systemverilog
parameter int L = 256;   // bad inside a leaf core module
```

Good:

```systemverilog
localparam int unsigned FFT_LEN = T_L;  // generated package constant
```

Reusable primitive example:

```systemverilog
module sync_fifo #(
    parameter int unsigned WIDTH = 32,
    parameter int unsigned DEPTH = 16
) (...);
```

The primitive is legal because it does not know `L`, `H`, `D`, packet IDs, or CSR offsets.

## Localparam contract

`localparam` may be used for derived implementation values if it is derived from generated constants or local generic primitive parameters.

Allowed:

```systemverilog
localparam int unsigned UNIQUE_BINS = (T_L / 2) + 1;
localparam int unsigned SPEC129_MASK_BYTES = (UNIQUE_BINS + 7) / 8;
```

Not allowed:

```systemverilog
localparam int unsigned UNIQUE_BINS = 129;  // bad: duplicate of L-derived value
localparam int unsigned STATUS_BYTES = 72;  // bad outside generated packet package/header
```

## Port naming contract

| Signal class | Required convention |
| --- | --- |
| Clock | `clk`, or `clk_core`, `clk_csr`, `clk_avmm` for multiple clocks |
| Reset | `rst_n`, or `rst_core_n`, `rst_csr_n`, `rst_avmm_n` |
| Valid-only tap | `tap_*_valid` plus associated payload; no `tap_*_ready` into the core |
| Ready/valid stream | `in_valid`, `in_ready`, `in_payload`, `out_valid`, `out_ready`, `out_payload` |
| Sample index | `logic [63:0] sample_idx` or field in generated struct |
| Frame index | `logic [63:0] frame_idx` or field in generated struct |
| Threshold | `thr2_shadow`, `thr2_active`, `thr2_commit_req`, `thr2_commit_pending` |
| Sticky flag clear | `clear_sticky_flags_w1c` or generated CSR field name |
| Write-one pulse | suffix `_w1p` for decoded pulse |
| Write-one-clear | suffix `_w1c` for decoded clear mask |
| DDR producer pointer | `ring_wr_ptr` or generated field name |
| DDR consumer pointer | `ring_rd_ptr` or generated field name |

Do not use names like `data1`, `stuff`, `flag`, `tmp2` in module APIs. Internal short temporary names are acceptable only inside small `always_comb` blocks.

## Core sample API

Preferred payload shape, generated from `interface_types.json`:

```systemverilog
typedef struct packed {
    logic                         valid;
    logic signed [T_SAMPLE_W-1:0] data;
    logic [63:0]                  sample_idx;
} trecap_sample_t;
```

Rules:

```text
sample_idx is the accepted-sample index, not clock-cycle count.
External source adapters convert BRAM/audio/ADC/diagnostic source to signed N-bit before core entry.
The core shall not know which source produced the sample.
BRAM replay source shall support full-tail zero flush for signoff vectors.
```

Module API pattern:

```systemverilog
module trecap_core_top (
    input  logic clk,
    input  logic rst_n,

    input  logic sample_valid,
    input  logic signed [T_SAMPLE_W-1:0] sample_data,
    input  logic [63:0] sample_idx,

    output logic y_valid,
    output logic signed [T_SAMPLE_W-1:0] y_data,
    output logic [63:0] y_sample_idx,

    output trecap_core_taps_t taps
);
```

The sample input is not a backpressured stream. Source selection and pacing belong in `rtl/sources/` or top-level integration.

## Frame event API

Preferred payload shape:

```systemverilog
typedef struct packed {
    logic        valid;
    logic [63:0] frame_idx;
    logic [63:0] trigger_sample_idx;
} trecap_frame_event_t;
```

Rules:

```text
Frame events are generated every H accepted samples.
Frame state starts at zero after reset or source-mode reinitialization.
Frame event timing shall preserve D = L + G alignment.
No telemetry or DDR signal may delay a frame event.
```

## Valid-only tap API

Core telemetry taps are observation-only:

```text
tap_sample_valid
tap_x_delayed
tap_y_out
tap_error
tap_sample_idx
tap_frame_valid
tap_frame_idx
tap_mag2_unique_bins
tap_mask_unique_bins
tap_frame_stats
```

Rules:

```text
No ready signal returns into the core.
Taps may be sampled, packetized, dropped, or decimated.
A dropped tap increments the proper pre-writer drop counter once telemetry exists.
Taps shall not contain DDR record headers or UDP packet metadata.
```

This is the hard boundary between correctness logic and demo/observability logic.

## Core plus telemetry composition API

`trecap_core_telemetry_top.sv` accepts the same normalized ready/valid sample,
finite-stream, tail, core-output, and active-control inputs required by the real
mathematical core. It owns exactly one `trecap_core_top` and one
`trecap_telemetry_top`; direct valid-only tap wires are the only data connection
between them.

The API exposes authoritative `core_sample_count`, `core_frame_count`, error
sums, maximum error, and truncation status. STATUS and METRICS must use those
signals directly. `ctrl.thr2_active` is the sole threshold presented to the core,
and the same safe `CLEAR_METRICS` apply event clears core and telemetry aggregate
state. A telemetry soft reset synchronously clears only formatter/FIFO state and
must not create a derived asynchronous reset, reset core arithmetic, or change
the core metric epoch.

`record_ready` may stall or cause telemetry drops below the packetizers. It must
not influence `sample_ready`, `y_ready`, the finite-stream tail handshake, or any
core scheduler/metric state.

A source discontinuity drives `observation_epoch_reset` into telemetry admission.
It discards partial packetizer collections through normal drop handling but does
not reset the packet FIFO or retract an already-selected record. An unselected
candidate is drained locally, with drain ownership held until its final beat.
This keeps WAVE samples from crossing source epochs while preserving record-level
ready/valid atomicity.

## Ready/valid stream API outside the core

Ready/valid is allowed after the non-stalling tap boundary:

```systemverilog
input  logic                 in_valid;
output logic                 in_ready;
input  trecap_record_meta_t  in_meta;
input  logic [PAYLOAD_W-1:0] in_payload;

output logic                 out_valid;
input  logic                 out_ready;
output trecap_record_meta_t  out_meta;
output logic [PAYLOAD_W-1:0] out_payload;
```

Rules:

```text
Ready/valid streams are legal between packetizers, packet FIFO, record builder, and DDR writer.
Backpressure in this path shall cause telemetry drops, not core stalls.
When payload bytes are stored separately from metadata, metadata and payload commit shall remain atomic at the record boundary.
```

## Status and counter API

Every drop or reject counter must have one owner.

| Counter/status | Owner | API exposure |
| --- | --- | --- |
| `PACKET_FIFO_DROP_COUNT` | `rtl/telemetry/` or pre-writer queue logic | CSR and STATUS low word |
| `DMA_DROP_COUNT` | `rtl/hps_bridge/trecap_ddr_ring_writer.sv` | CSR and STATUS low word |
| `CSR_COMMAND_REJECT_COUNT` | `rtl/hps_bridge/trecap_csr_bank.sv` | CSR and combined HPS STATUS patch |
| HPS command reject count | `sw/hps/src/command_server.c` | Patched STATUS only |
| UDP send error count | `sw/hps/src/udp_sender.c` | Patched STATUS only |
| Malformed record count | `sw/hps/src/ring_reader.c` | Patched STATUS only; exactly one increment per malformed latch |
| HPS sequence gap count | `sw/hps/src/ring_reader.c` | Patched STATUS only |
| PC sequence gap count | PC parser | Dashboard only |

Do not merge `PACKET_FIFO_DROP_COUNT` and `DMA_DROP_COUNT`; they identify different bottlenecks.

## Source module APIs

Source adapters live under `rtl/sources/` and expose signed core samples.

### `trecap_bram_replay_source.sv`

Required API behavior:

```text
Loads x_in.memh from artifacts/test_vectors/<vector>/.
Emits real input samples followed by full-tail zero flush samples.
Tracks sample_idx for the emitted stream.
Does not instantiate STFT/WOLA core logic.
```

Minimum ports:

```systemverilog
input  logic clk;
input  logic rst_n;
input  logic start;
input  logic clear;
output logic sample_valid;
output logic signed [T_SAMPLE_W-1:0] sample_data;
output logic [63:0] sample_idx;
output logic done;
output logic error;
```

### `trecap_audio_adapter.sv`

Required API behavior:

```text
Maps audio codec sample format to signed N-bit core scale.
Uses exactly `sat_N(rnd_shr(a_audio, B_audio-N))` when `B_audio >= N`.
Does not define final source-mode commit behavior.
Does not change core delay D.
```

### `trecap_adc_adapter.sv`

Required API behavior:

```text
Maps unsigned ADC data to signed N-bit core scale.
Optional DC blocking is wrapper-level behavior and must be declared in profile/config.
```

### `trecap_source_mux.sv`

Required API behavior:

```text
Selects exactly one source mode.
Source-mode change shall occur only through safe commit/reset logic.
It registers active/pending mode and emits switch/discontinuity status.
The enclosing source/core integration layer owns ready/valid guarding and clearing adapter, input-ring, OLA, scheduler, and alignment state.
```

### `trecap_source_core_integration.sv`

Required API behavior:

```text
Instantiates the normalized BRAM, audio, ADC, and diagnostic source paths, source mux, and mathematical core.
Accepts only CSR-validated active THR2/source-mode values and the post-safe-boundary source apply pulse.
Guards ready and valid during a source epoch change so no first beat of the new source is lost.
Clears source-dependent core state and emits a discontinuity pulse on a non-idempotent source change.
Routes BRAM replay samples before tau_last into analysis and the remaining D ticks into the pure WOLA tail input.
Exports real frame/config and source safe boundaries plus valid-only core taps.
Emits one-cycle new-fault CSR set events only for exact generated `OVERFLOW_FLAGS` matches: arithmetic overflow, ring/history overflow, and source-mode error.
Keeps replay/source, adapter-overrun, ADC-protocol, and core-protocol fault levels on dedicated outputs rather than aliasing them onto unrelated CSR bits.
Treats clear_i as a datapath/source-epoch clear that preserves the CSR-selected mux mode; shared rst_n owns coordinated source-mode reset.
Reports replay_done_o as final source-token acceptance, not exact/quiescent core completion.
Never accepts telemetry, DDR, packet-FIFO, or network backpressure.
```

This is a pin-agnostic integration module under `rtl/top/`. Physical codec, ADC,
HPS, DDR, and board pins remain outside it. At the physical board top, the
dedicated non-CSR fault levels join the writer/source/build-contract aggregate on
`LEDR[9]`; this LED aggregation does not make those levels CSR-visible.

## Core module APIs

Core modules shall not expose CSR, DDR, or packet fields.

| Module | API rule |
| --- | --- |
| `trecap_input_ring.sv` | Accepts signed sample ticks, backpressures C0 replay while a frame request/extraction owns the ring, and provides an L-sample frame window to the scheduler/window stage. |
| `trecap_frame_scheduler.sv` | Emits frame events every `H` accepted samples. No packet knowledge. |
| `trecap_analysis_window.sv` | Multiplies frame samples by frozen `window_qw.memh` coefficients. No internal coefficient generation. |
| `trecap_hermitian_canonicalizer.sv` | Takes raw FFT bins and returns canonical bins. No threshold register ownership. |
| `trecap_mag2_mask.sv` | Applies full-width unsigned `THR2` comparison and protection rules. |
| `trecap_spectrum_mask_builder.sv` | Constructs conjugate-symmetric masked spectrum. |
| `trecap_synthesis_wola.sv` | Applies IFFT output, synthesis window, and OLA accumulation. |
| `trecap_delay_error_metrics.sv` | Aligns delayed input with output, computes error, updates metrics/taps. |
| `trecap_core_top.sv` | Integrates core path and exposes valid-only taps. |

## FFT module APIs

FFT modules shall be isolated so the team can choose custom radix-2 or vendor IP without infecting the rest of the repository.

Required API shape:

```text
frame input -> FFT/IFFT control -> natural-order complex output
```

Rules:

```text
Forward FFT behavior must match the normalized custom contract or an explicitly frozen vendor-IP contract.
IFFT behavior must match unscaled inverse contract or an explicitly frozen vendor-IP contract.
Twiddle ROM loads frozen forward and inverse artifacts.
No sine/cosine generation exists in RTL.
```

If vendor FFT IP is used, `trecap_fft256.sv` and `trecap_ifft256.sv` become wrappers. The wrapper API remains stable.

## Telemetry module APIs

Telemetry modules format packets. They do not write DDR.

| Module | API rule |
| --- | --- |
| `trecap_telemetry_top.sv` | Consumes valid-only taps and emits ready/valid formatted records. |
| `trecap_packet_scheduler.sv` | Selects packet emission based on enable bits, event rate, and priority. |
| `trecap_wave_packetizer.sv` | Builds WAVE payload with delayed input, output, error triples, and stride. |
| `trecap_spec_packetizer.sv` | Builds SPEC64 or SPEC129 payload depending on generated selector values. |
| `trecap_metrics_packetizer.sv` | Builds METRICS payload with legal flags. |
| `trecap_status_packetizer.sv` | Builds FPGA-originated STATUS skeleton. HPS may patch outgoing UDP copy only. |
| `trecap_packet_fifo.sv` | Preserves metadata/payload atomicity and implements priority admission/drop policy. |
| `trecap_priority_dropper.sv` | Optional helper for priority-based shedding if FIFO does not implement it internally. |

Telemetry output to HPS bridge:

```systemverilog
output logic                rec_valid;
input  logic                rec_ready;
output trecap_record_meta_t rec_meta;
output logic [REC_DATA_W-1:0] rec_payload_data;
output logic                rec_payload_last;
```

The exact payload transport may use RAM, streaming beats, or a packed payload bus. The record boundary and payload byte count must remain exact.

## HPS bridge module APIs

HPS bridge modules own CSR, ring pointers, record headers, and DDR writes.

| Module | API rule |
| --- | --- |
| `trecap_avmm_csr_adapter.sv` | Terminates the strict 32-bit, single-beat Avalon-MM CSR agent; performs full 21-bit-to-12-bit byte-address decode and serializes one response at a time. |
| `trecap_csr_bank.sv` | Implements normative CSR map and generated reset/access semantics, including minor-1.8 counter clear and retained CSR-originated replay request/result state. |
| `trecap_csr_shadow_commit.sv` | Handles multiword controls such as 56-bit THR2 and 64-bit pointers. |
| `trecap_ring_pointer_ctrl.sv` | Owns snapshot/commit transfer of producer and consumer pointers. |
| `trecap_ddr_record_builder.sv` | Builds 32-byte headers and aligned DDR record bodies. |
| `trecap_avmm_write_master.sv` | Converts record write requests to Avalon-MM or selected bus protocol. |
| `trecap_ddr_ring_writer.sv` | Owns ring free-space, WRAP, producer pointer commit, and `DMA_DROP_COUNT`. |
| `trecap_hps_bridge_top.sv` | Integrates the Avalon-MM CSR adapter, private CSR bank, record builder, writer, replay admission feedback, transport-counter clear, and Platform Designer-facing boundaries. |

`trecap_ddr_ring_writer.sv` shall not appear under `rtl/telemetry/`.

## Platform module APIs

Platform modules own board-specific details:

```text
physical pins
hand-written typed wrapper around generated Platform Designer module `system`
clock/reset conditioning
peripheral-only audio PLL and codec-control I2C initialization
audio codec wrapper
ADC wrapper
board switches, LEDs, and debug display if used
```

Board-facing logic shall not be hidden in `rtl/core/`.

`rtl/platform/de1soc/de1_soc_trecap_top.sv` is the physical Quartus top and
owns board pins. `rtl/top/trecap_de1soc_full_top.sv` is a pin-agnostic logical
transport top; its name does not make it the Quartus board entity.

The Step-9 board API is composition-only. It binds one generated-system
boundary, one audio wrapper, one LTC2308 wrapper, the sole source/core owner,
and the telemetry/HPS owner. CSR and F2SDRAM request/response channels use real
end-to-end nets, not safe-idle constants. Audio and ADC samples enter through
their wrappers; real core taps/counters pass downstream without board-generated
replacement taps.

The Step-10 `clock_reset_ctrl` API exports one direct `clk_fabric = CLOCK_50`, one
canonical `rst_n_platform`, synchronized board controls, exact-average 48 kHz
source pacing, 10 Hz STATUS, 30 Hz METRICS, and a 2 Hz heartbeat-toggle enable.
It owns 20 ms stable-high qualification of released `KEY[0]`, combination with
the active-low HPS-to-FPGA reset, and the sole at-least-two-stage fabric reset
synchronizer. It may not export pseudo-domain clocks/resets, invent a frame or
source-safe boundary, or expose a hardwired PLL-lock assertion.

Step 16 adds exactly one `audio_pll_wrapper` and one
`audio_codec_i2c_init` beside the existing `audio_codec_wrapper`. Their status
qualifies audio readiness only; it must not become an additional hard-reset
source for the 50 MHz fabric.

All fabric APIs consume the same clock/reset pair and release simultaneously.
The clock-enable pulses shall never be used as clocks. Alternate board clocks
are reserved; split-clock fabric operation is unsupported until interfaces and
CDC paths are redesigned. Audio BCLK receive-edge and transmit-edge state use
their own local reset-release synchronizers.

Core y remains always accepted. Its valid/data fan out to audio as a
best-effort monitor. A fabric-to-BCLK async FIFO absorbs reconstructed-output
bursts; FIFO full drops/counts a monitor sample rather than backpressuring the
core. A separate BCLK-to-fabric async FIFO carries complete signed stereo input
frames atomically. The wrapper exports dedicated saturating 64-bit receive-
overflow, transmit-overflow, and transmit-underflow counters. Those diagnostics
must not be aliased onto unrelated generated CSR overflow meanings.

`audio_pll_wrapper` supports the frozen 50 MHz-to-12.288 MHz peripheral clock
profile and exports a qualified lock plus an explicit supported-configuration
status. `audio_codec_i2c_init` owns open-drain `FPGA_I2C_SCLK`/`FPGA_I2C_SDAT`,
addresses the WM8731 at `0x1a`, and programs 48 kS/s, signed 16-bit I2S with the
codec as BCLK/LRCK master. Initialization is admitted only when PLL lock and the
FPGA codec-bus grant are present. The HPS must keep `HPS_I2C_CONTROL` low; FPGA
logic may observe that signal but must never drive it. Codec-ready gates capture
and line-out admission. The portable PLL model and source checkers are not
Quartus, TimeQuest, I2C ACK, measured-clock, or live-audio evidence.

The Step-17 LTC2308 API is pinned to the Rev-H board contract. It owns idle-low/
active-high CONVST, a 40-ns pulse, at least 1.6 us post-CONVST wait, twelve
MSB-first result clocks at 2.5 MHz, and a six-bit next-configuration word. It
runs a 100 ksample/s exact-average scheduler, synchronizes the single-bit
off-chip DOUT input through at least two preserved flops, and registers complete
sample-valid/data together in `clk_fabric`. `ADC_SCLK` is not an RTL clock and
there is no multi-bit ADC CDC after the wrapper.

The board latches `SW[6:4]` only on entry to `TSRC_ADC_LIVE`, holds the
single-ended/unipolar/awake command for that source epoch, and primes by
discarding the previous-command result. `sample_count_o` is a saturating 64-bit
count of published eligible samples. Busy/transaction-done and request-overrun/
protocol-error stickies retain their distinct API meanings. The adapter, not the
wrapper, owns unsigned-code recentering at 2048, signed core-width scaling,
ready/valid staging, drop accounting, and optional profile-declared DC blocking.
Unsupported static timing/width/synchronizer configurations fail closed with
idle pins and no sample requests.

## Top-level build variants

| Top module | API boundary |
| --- | --- |
| `trecap_core_only_top.sv` | Pure core wrapper. No telemetry/HPS/platform. |
| `trecap_core_bram_replay_top.sv` | BRAM replay source plus core for C0/board replay. |
| `trecap_core_telemetry_top.sv` | Standalone normalized source -> one real core -> one non-stalling telemetry formatter/FIFO; no source mux, DDR writer, or platform pins. |
| `trecap_source_core_integration.sv` | Pin-agnostic normalized sources, guarded source mux, exact replay tail routing, core, and valid-only taps. |
| `trecap_de1soc_full_top.sv` | Pin-agnostic telemetry, HPS bridge, and DDR logical integration; no physical board pins. |
| `de1_soc_trecap_top.sv` | Physical DE1-SoC Quartus top that binds real source/platform wrappers, logical owners, Platform Designer CSR/F2SDRAM, non-stalling best-effort core-y monitoring, board status, and pins. |

Do not create a single monolithic demo top that bypasses these build variants.

## HPS C API rules

HPS software lives under `sw/hps/` and shall include generated headers from:

```text
sw/hps/include/generated/trecap_csr.h
sw/hps/include/generated/trecap_packet.h
```

C modules should follow these responsibilities:

| File | API rule |
| --- | --- |
| `config.c` | Strictly parses the flat runtime profile, pins frozen windows and safety booleans, and validates the live reservation before normal mapping. |
| `csr_map.c` | Owns CSR mmap/read/write helpers. Uses generated CSR offsets. |
| `ring_reader.c` | Owns reset/reconfigure/`Rd=0`/active state, producer snapshot, complete record validation, exact-tail WRAP, atomic consumer commit, and malformed latch. |
| `udp_sender.c` | Sends one exact record per UDP datagram with no DDR padding or fragmentation; classifies nonblocking or bounded-timeout failures. |
| `command_server.c` | Preserves exact v1 parsing, validates v2 28-byte commands and the exact source IP/port, emits PING STATUS-only diagnostics, and encodes exact 32-byte v2 non-PING results. |
| `command_bridge.c` | Owns the RFC1982 ledger/cache, RESET-to-CONFIGURE-to-ENABLE lifecycle, safe disabled/idle control mutations, counter clear, replay admission/result wait, readback, timeout, CONTROL=0 recovery attempt, and RESET_REQUIRED software lock when hardware disable cannot be proven. |
| `status_patch.c` | Patches only local UDP STATUS copies with HPS-owned counters. |
| `trecap_udp_streamer.c` | Enforces resource admission, send/drop/commit ordering, exactly-once malformed behavior, command polling, and UDP-only diagnostic STATUS mode. |

Normal mode shall fail closed before `/dev/mem` access unless the exact live
reserved-memory contract is active. Dummy mode shall open UDP only. A malformed
record shall never be byte-scanned or repeatedly parsed; streaming resumes only
after soft reset, ring reconfiguration, `Rd=0` commit, zero-`W` verification, and
normal re-arm.

HPS C shall not contain FFT, IFFT, mask decision, WOLA, reconstruction, or sample-by-sample error algorithms.

The canonical listener binds `192.168.10.2:5006` and production requests must
originate from `192.168.10.1:5007`. A wildcard listener or first-valid-PING peer
learning is an explicit lab/test mode only. Ring physical addresses are never
arguments on the wire. `SET_SOURCE_MODE`, `SET_PACKET_ENABLE`, `SET_WAVE_DECIM`,
`SET_SPEC_MODE`, and `SET_SPEC_SHIFT` in either command version must pass through
the bridge's disabled-controls, `transport_epoch_idle`, replay-idle, verified
readback, and safe-restore sequence; direct live CSR mutation is forbidden.

## PC Python API rules

PC dashboard code lives under `sw/pc_dashboard/` and shall import generated packet constants from:

```text
sw/pc_dashboard/generated/trecap_packet.py
```

Python modules should follow these responsibilities:

| File | API rule |
| --- | --- |
| `packet_parser.py` | Validates header, flags, payload sizes, endian format, and packet type. |
| `udp_receiver.py` | Background receive loop. Does not block GUI redraw. |
| `ring_buffers.py` | Rolling display buffers and sequence-gap accounting. |
| `plots.py` | Plot primitives only. |
| `dashboard.py` | UI composition and 20-30 Hz redraw. |
| `command_client.py` | Builds exact v1/v2 requests from generated constants, binds the configured source port, keeps PING STATUS-only, and validates exact v2 result type/sequence/disposition/reason fields. |

PC code is not a correctness authority and shall not regenerate expected `y_out.memh`.

## API review checklist

A module API is acceptable only if all checks below pass:

```text
[ ] File path matches the ownership layer.
[ ] Module name matches file name.
[ ] Only allowed generated packages/headers are imported.
[ ] No hard-coded duplicate contract constants are used.
[ ] Clock/reset names follow the convention.
[ ] Multi-clock API has explicit CDC boundary.
[ ] Core modules have no CSR, packet, DDR, HPS, UDP, PC, board-pin, or Platform Designer ports.
[ ] Telemetry taps are valid-only and cannot backpressure the core.
[ ] Telemetry modules do not instantiate DDR writers or bus masters.
[ ] HPS bridge modules own all DDR ring pointer and record-writing behavior.
[ ] HPS C uses generated CSR/packet headers and runtime config.
[ ] PC Python imports generated packet constants.
[ ] Generated files are not hand-edited.
```
