# HPS Ethernet, DDR ring, and UDP bring-up

File class: **[1] hand-written bring-up document**.

This document defines the staged bring-up for the Phase 2 transport path:

```text
FPGA source/core/taps
  -> telemetry formatter
    -> DDR ring writer
      -> HPS DDR ring reader
        -> UDP streamer
          -> PC dashboard
```

It also defines the reverse command path:

```text
PC command
  -> HPS command parser
    -> HPS command bridge / sequence-result cache
      -> generated CSR writes and readback
        -> FPGA safe-boundary/replay owners
```

Ethernet telemetry is not bit-accurate signoff. BRAM replay remains the correctness path.

## Authority

The active integrated Phase 2 specification under `docs/specs/` is the authority. This document follows the Revision G ownership rules:

```text
FPGA fabric owns real-time STFT/WOLA signal processing.
HPS owns Ethernet transport, DDR-ring consumption, command reception, and CSR access.
PC owns visualization and user controls.
Telemetry may be dropped and counted, but must not stall the core.
```

## Address-space rule

There are three different address spaces:

| Field / value | Used by | May be written to FPGA CSR? |
| --- | --- | ---: |
| HPS physical DDR address | Linux/HPS mapping code | no, unless equal to FPGA-visible address by documented platform mapping |
| HPS userspace virtual pointer from `mmap()` | local C process | never |
| FPGA-visible bus address | `trecap_ddr_ring_writer.sv` | yes, into `RING_BASE_LO/HI` |

`RING_BASE` is the address seen by the FPGA DDR writer bus master. It is not a Linux virtual address.

## Bring-up milestones

Follow these milestones in order.

| Milestone | Name | Pass condition |
| --- | --- | --- |
| M0 | HPS Ethernet bring-up | PC can ping HPS; HPS can send dummy UDP counter to PC. |
| M1 | CSR bridge | HPS reads FPGA `ID` and `VERSION`; HPS writes a harmless control register. |
| M2 | DDR ring dummy writer | FPGA writes dummy STATUS records into DDR; HPS forwards them over UDP. |
| M3 | Waveform telemetry | PC plots delayed input `x[n-D]`, output `y[n]`, and error `e[n]`. |
| M4 | Metrics telemetry | PC plots eligible suppression ratio and kept-energy ratio. |
| M5 | Spectrum telemetry | PC plots either SPEC64 or SPEC129. Do not require both for first demo. |
| M6 | PC-to-FPGA commands | PC changes `THR2`; FPGA applies it at a frame boundary. |
| M7 | Full live demo | Live source, processed output, Ethernet dashboard, stable counters. |

Do not enable WAVE, SPEC, and METRICS before STATUS-only forwarding is proven.

## M1: CSR bridge smoke

Before enabling DDR ring writes, HPS must read CSR ID and VERSION.

Expected CSR checks:

```text
ID numeric value      = 0x54524350
VERSION major         = 1
VERSION minor         = 8
```

The HPS compares parsed little-endian numeric values, not raw ASCII byte strings.

Expected helper:

```bash
python scripts/bringup/smoke_csr.py --config sw/hps/config/trecap_hps_config.json
```

Minimum smoke sequence:

```text
1. mmap CSR window from `csr_base_phys` and `csr_span_bytes`.
2. Read ID.
3. Read VERSION.
4. Read STATUS and DMA_STATUS.
5. Clear telemetry enable and ring writer enable.
6. Pulse telemetry soft reset.
7. Write and read back a harmless configuration field if the CSR access type permits it.
```

If ID/VERSION fails, stop. Do not debug DDR ring or UDP dashboard yet.

## M2: DDR ring initialization

The ring is configured only while telemetry is disabled.

Required sequence:

```text
1. Clear CONTROL.telemetry_enable.
2. Clear CONTROL.ring_writer_enable.
3. Pulse CONTROL.telemetry_soft_reset.
4. Allocate or reserve the DDR ring region.
5. Map the DDR ring read-only through synchronous, non-cacheable `/dev/mem`.
6. Write RING_BASE_LO and RING_BASE_HI using the FPGA-visible address.
7. Write RING_SIZE_BYTES.
8. Pulse RING_CONFIG_COMMIT while telemetry is disabled.
9. Write RING_RD_LO_SHADOW = 0.
10. Write RING_RD_HI_SHADOW = 0.
11. Pulse RING_RD_COMMIT.
12. Request RING_WR_SNAPSHOT and verify W = 0.
13. Set CONTROL.ring_writer_enable = 1.
14. Set CONTROL.telemetry_enable = 1.
```

Do not enable the writer with stale producer/consumer pointers.

## Ring invariants

The DDR ring uses 64-bit monotonic byte pointers:

```text
W  = FPGA-owned producer pointer
Rd = HPS-owned consumer pointer
R  = ring size in bytes, power of two
off(p) = p & (R - 1)
used = W - Rd
valid state: 0 <= used <= R
```

Minimum ring constraints:

```text
ring size is power of two
ring size is multiple of 64
recommended first implementation: 32 MiB
base address is 64-byte aligned
stronger base alignment may be required by the bus decoder
```

The WRAP rule matters. If a normal record would cross the physical end of the ring, the writer must account for the tail plus the new record, commit a WRAP record, and then write the normal record at offset zero. Checking only free space for the normal record is wrong.

## HPS streamer loop

The HPS UDP streamer must behave like this:

```text
1. Snapshot W using RING_WR_SNAPSHOT.
2. While Rd != W:
   a. Read header at ring_base + off(Rd).
   b. Validate magic, version, header_bytes, type, flags, payload size, and boundary conditions.
   c. If WRAP, advance Rd by R - off(Rd), commit Rd, and continue.
   d. If normal and valid, send exactly one UDP datagram containing header + payload.
   e. Do not transmit DDR padding bytes.
   f. Advance Rd by align64(32 + payload_bytes).
   g. Commit Rd through RING_RD_COMMIT.
3. Poll command UDP socket.
4. Continue even if PC is slow or disconnected.
```

UDP send must be nonblocking or bounded-timeout. If `sendto()` fails or would block, the HPS increments `udp_send_error_count`, drops that UDP datagram, advances `Rd`, commits `Rd`, and continues.

## Packet validation checklist

Before forwarding a DDR record, HPS validates:

```text
[ ] magic == 0x54524350
[ ] supported version
[ ] header_bytes == 32
[ ] known packet_type
[ ] reserved flags are zero
[ ] status_diagnostic flag is not set on FPGA-originated normal records
[ ] payload_bytes matches exact packet type rule or WAVE range rule
[ ] METRICS has exactly one of aggregate_metrics/per_frame_metrics
[ ] METRICS payload_scaled == 0 for Revision G
[ ] WAVE channels == 3
[ ] WAVE nsamp in legal range
[ ] WAVE stride >= 1
[ ] SPEC129 nbin == 129 if used
[ ] SPEC64 nbin == 64 if used
[ ] normal records do not cross ring boundary
[ ] WRAP consumes the exact physical tail
[ ] header_crc == 0 in Revision G
```

Malformed record policy is latch-and-rearm, not byte scanning. On the first
malformed incident, HPS increments `malformed_record_count` exactly once, enters
`MALFORMED_LATCHED` before MMIO, disables telemetry and the writer, and
recommits the unchanged current `Rd`. The default process stays alive for
diagnostics but does not reparse or recommit that bad `Rd`. Streaming resumes
only after soft reset, ring reconfiguration, `Rd=0` commit, zero-`W`
verification, and the normal arm sequence. `--stop-on-malformed` is a
debug-only exit-code-3 override.

## STATUS-only first

Initial packet enable should be STATUS-only:

```text
PACKET_ENABLE = STATUS_EN
SPEC_MODE     = 0 or one explicitly disabled value
WAVE_DECIM    = safe default, but WAVE_EN disabled
SPEC_SHIFT    = safe default, but SPEC_EN disabled
```

Pass criteria for STATUS-only:

```text
[ ] PC receives UDP datagrams on port 5005.
[ ] HPS validates header and STATUS payload size.
[ ] STATUS.payload_bytes == 72.
[ ] sample_count and frame_count are plausible.
[ ] dma_drop_count and packet_fifo_drop_count are displayed separately.
[ ] overflow_flags are visible.
[ ] sequence numbers advance for normal records.
[ ] Closing the PC receiver does not stall FPGA core processing.
```

Only after STATUS-only works should WAVE, METRICS, and one spectrum mode be enabled.

## WAVE bring-up

Enable WAVE after STATUS-only is stable.

Expected payload content:

```text
xdel = delayed input x[n - D]
yout = reconstructed output y[n]
err  = xdel - yout
stride = active WAVE_DECIM
```

The PC must reconstruct time using:

```text
sample_base + i * stride
```

not `sample_base + i` when decimated.

## METRICS bring-up

Enable METRICS after WAVE or STATUS is stable.

Rules:

```text
exactly one of aggregate_metrics/per_frame_metrics is set
payload_scaled = 0 in Revision G
low-64-bit counters are display counters, not full artifact signoff counters
payload_truncated is set if omitted high bits are known nonzero
```

The dashboard must keep `dma_drop_count` and `packet_fifo_drop_count` separate.

## SPEC bring-up

Pick exactly one mode for first integration:

```text
SPEC_MODE = 1 -> SPEC64
SPEC_MODE = 2 -> SPEC129
```

Do not try to output both SPEC64 and SPEC129 in the first scheduler. Simultaneous support is deferred.

Rules:

```text
PACKET_ENABLE.SPEC_EN gates spectrum generation.
SPEC_MODE selects the format.
No separate SPEC64_EN or SPEC129_EN bits exist in Revision G.
SPEC_SHIFT must be in range for Wmag2 = 56.
```

## Command path bring-up

Commands arrive from PC to the HPS listener bound to `192.168.10.2:5006`.
Production admission requires the exact configured source IP and port,
`192.168.10.1:5007`, plus size, magic, version, type, arguments, and zero CRC.
Binding `0.0.0.0` or learning a peer from the first fully valid PING is an
explicit isolated-lab override only.

Revision-G command version 1 remains exactly seven types in the 28-byte request
and defines no generic result. Version 2 reuses the exact request layout, adds
types `0x0008..0x000E`, and returns an exact 32-byte result for every version-2
non-PING request. PING in either version returns a fresh diagnostic STATUS with `seq=0`
only and does not alter the v2 RFC1982 ledger/cache.

First useful command:

```text
SET_THR2
```

Required sequence:

```text
1. HPS writes THR2_LO.
2. HPS writes THR2_HI with upper unused bits zero.
3. HPS pulses THR2_COMMIT.
4. FPGA applies active threshold only at a frame boundary.
5. STATUS shows active THR2 after commit.
```

Do not write active core threshold asynchronously.

Source mode, packet enable, wave decimation, spectrum mode, and spectrum shift
commands can disturb an active epoch. In both wire versions the HPS bridge must
disable telemetry and the writer, verify disabled readback,
`STATUS.transport_epoch_idle=1`, and no replay busy/pending; apply and verify the
generated CSR mutation; then safely restore and verify the prior enable state.
Direct live CSR writes for these controls are rejected.

`RESET_TRANSPORT` is not a replay abort. If replay is pending, active,
path-busy, or E2E-busy, RESET fails without writing `REPLAY_CONTROL`. A healthy,
quiescent RESET also performs no replay-control write. Only a quiescent failed
epoch with `rearm_required=1` receives one rearm pulse; successful readback must
preserve `result_epoch` and clear the retained replay result/error state.

## Drop behavior

A correct system drops telemetry rather than stalling core processing.

Required separate counters:

```text
PACKET_FIFO_DROP_COUNT  -> pre-writer tap/FIFO drops
DMA_DROP_COUNT          -> DDR writer/ring-space/oversized/writer-policy drops after writer acceptance
udp_send_error_count    -> HPS send failures
malformed_record_count  -> HPS malformed DDR records
oversized_record_count  -> HPS oversized DDR records
sequence_gap_count      -> normal committed/forwarded sequence gaps observed by HPS/PC
```

Do not merge packet FIFO drops and DMA drops. They identify different bottlenecks.

```text
[ ] Bind the production listener to 192.168.10.2:5006.
[ ] Accept production commands only from exact peer 192.168.10.1:5007.
```

## Full startup sequence

Baseline startup:

```text
1. Keep CONTROL.telemetry_enable = 0.
2. Keep CONTROL.ring_writer_enable = 0.
3. Pulse CONTROL.telemetry_soft_reset.
4. Allocate/reserve DDR ring region.
5. Map the DDR ring read-only through synchronous, non-cacheable `/dev/mem`;
   cached mappings are forbidden because this userspace reader has no
   cache-invalidation path.
6. Write RING_BASE_LO, RING_BASE_HI, RING_SIZE_BYTES.
7. Pulse RING_CONFIG_COMMIT while telemetry disabled.
8. Write RING_RD_LO_SHADOW = 0.
9. Write RING_RD_HI_SHADOW = 0.
10. Pulse RING_RD_COMMIT.
11. Verify W = 0 through RING_WR_SNAPSHOT.
12. Start the HPS command server with an empty v2 sequence ledger/cache.
13. From the bound PC socket, send v2 `RESET_TRANSPORT`.
14. Send v2 `CONFIGURE_DDR_RING`; all arguments are zero and geometry comes only from validated local state.
15. Configure THR2 if needed, then use bridge-owned disabled/idle mutations for WAVE_DECIM, SPEC_MODE, SPEC_SHIFT, and STATUS-only PACKET_ENABLE.
16. Send v2 `SET_TELEMETRY_ENABLE 1` only after verified RESET/CONFIGURE completion.
17. Start PC receiver/dashboard and verify valid STATUS.
18. Enable WAVE, SPEC, and METRICS only through the same safe mutation path after STATUS is proven.
19. Verify command results, sequence/cache behavior, payload sizes, timestamps, and separate drop/error counters.
```

## Shutdown sequence

```text
1. Disable telemetry_enable.
2. Disable ring_writer_enable.
3. Stop PC dashboard or receiver.
4. Stop HPS streamer.
5. Commit final Rd if the streamer has consumed records.
6. Release DDR ring mapping.
7. Preserve logs and run manifest.
```

The FPGA core may continue processing while telemetry is disabled.

## Troubleshooting

| Symptom | Likely cause | Correct first action |
| --- | --- | --- |
| PC cannot ping HPS | Cable/IP/firewall/interface issue | Fix M0 before touching FPGA RTL. |
| HPS cannot read ID/VERSION | CSR bridge/address map issue | Fix M1 before DDR ring. |
| ID works but W never advances | Ring not configured, writer disabled, no dummy/status packet source | Check ring init and writer enable. |
| W advances but HPS reads garbage | Wrong ring base address or cache policy | Recheck FPGA-visible vs HPS physical address. |
| HPS disables telemetry | Malformed latch triggered | Save the bad header and counters; confirm no reread of `Rd`, fix the producer, then perform the complete reset/reconfigure/`Rd=0` re-arm sequence. |
| UDP send fails | PC not listening/firewall/socket buffer | Confirm nonblocking send still advances Rd. |
| STATUS works but WAVE malformed | WAVE payload size/stride/channel fields wrong | Keep STATUS-only, debug WAVE packetizer. |
| SPEC works but dashboard plot wrong | SPEC64/SPEC129 parser or shift/mask packing issue | Validate generated packet constants and payload bytes. |
| Command accepted but threshold changes mid-frame | CSR shadow/commit bug | Fix THR2 commit boundary. |
| Core stalls when PC closed | Illegal telemetry backpressure | Fix packet FIFO/drop behavior immediately. |

## Acceptance checklist

The HPS Ethernet bring-up is accepted when:

```text
[ ] HPS and PC can ping each other on the selected topology.
[ ] HPS dummy mode sends legal diagnostic STATUS without CSR/DDR mapping or root, and the PC validates it.
[ ] HPS reads FPGA ID and VERSION through generated CSR constants.
[ ] HPS initializes the ring with telemetry disabled and verifies W = 0.
[ ] HPS forwards valid STATUS records first.
[ ] STATUS.payload_bytes is exactly 72.
[ ] HPS validates records before forwarding.
[ ] HPS uses nonblocking or bounded-timeout UDP sends.
[ ] Closing PC receiver/dashboard does not stall the FPGA core.
[ ] Packet FIFO and DMA drops are counted separately.
[ ] WAVE, METRICS, and exactly one spectrum mode can be enabled after STATUS-only works.
[ ] PC command SET_THR2 uses shadow/commit and frame-boundary application.
[ ] No HPS code computes FFT, IFFT, masks, WOLA, or reconstruction error.
[ ] The team does not claim Ethernet telemetry as bit-accurate correctness signoff.
```
