# DDR ring bring-up

File class: **[1] hand-written bring-up document**.

This document defines the bring-up procedure for the FPGA-to-HPS DDR telemetry ring in the T-RECAP Phase 2 implementation repository.

The DDR ring sits in the transport path:

```text
FPGA telemetry formatter
  -> packet FIFO
    -> DDR record builder
      -> DDR ring writer
        -> HPS DDR ring reader
          -> HPS UDP streamer
            -> PC dashboard
```

This document is not a replacement for BRAM replay signoff. A working DDR ring proves transport mechanics only. It does not prove STFT/WOLA arithmetic correctness.

## Authority

The active integrated Phase 2 specification under `docs/specs/` is the authority. This document follows the Revision G transport contract:

```text
1. Telemetry may be dropped and counted.
2. Telemetry shall not backpressure the STFT/WOLA core.
3. The HPS bridge owns DDR record building and DDR ring writing.
4. RING_BASE is the FPGA-visible DDR bus address, not a Linux virtual address.
5. Producer and consumer pointers use snapshot/commit, not torn low/high updates.
6. BRAM replay plus reference artifacts remains the correctness path.
```

## What this document proves

A passed DDR ring bring-up proves:

```text
[ ] The HPS can configure ring base/size through the CSR bank.
[ ] The FPGA writer resets producer pointer W to zero during ring configuration.
[ ] The HPS commits consumer pointer Rd = 0 before enabling writes.
[ ] The FPGA writes committed DDR records with the generated packet header layout.
[ ] The HPS reads only records below the committed producer pointer.
[ ] WRAP records are handled without crossing the physical ring end.
[ ] DDR alignment, cache policy, payload-size checks, and malformed-record handling work.
[ ] Drop counters distinguish packet-FIFO drops from DDR-writer/ring-space drops.
```

It does **not** prove:

```text
[ ] STFT/WOLA arithmetic is correct.
[ ] y_out.memh matches the reference outputs.
[ ] live audio has correct source scaling.
[ ] PC plots are bit-accurate signoff artifacts.
[ ] Ethernet loss implies core loss.
```

## Contract summary

### Ring memory

```text
B = FPGA-visible ring base address
R = ring size in bytes
W = FPGA-owned producer pointer, 64-bit monotonic byte pointer
Rd = HPS-owned consumer pointer, 64-bit monotonic byte pointer
off(p) = p & (R - 1)
used = W - Rd
valid state: 0 <= used <= R
```

Board baseline:

```text
R >= 1 MiB
R power of two
R multiple of 64 bytes
B 64-byte aligned
recommended first implementation: R = 32 MiB
```

For a simulation-only wrap test, the ring may be reduced under a clearly named test profile. A reduced ring must not be used to claim board-level Revision G acceptance unless the active spec is updated.

### Address-space rule

There are three address values that must not be confused:

| Address value | Owner | Valid use |
| --- | --- | --- |
| HPS userspace virtual pointer | local Linux process | local `memcpy` / volatile loads only |
| HPS physical DDR address | Linux/reserved-memory/DMA allocator | HPS mapping and debug only |
| FPGA-visible DDR bus address | Platform Designer bridge view | value written into `RING_BASE_LO/HI` |

The value written into FPGA CSR `RING_BASE_LO/HI` must be the FPGA-visible bus address.

### Record alignment

Normal record length:

```text
Hbytes = 32
Pbytes = payload_bytes
Lrec = align64(Hbytes + Pbytes)
```

Normal records:

```text
[ ] start on a 64-byte-aligned offset
[ ] contain a 32-byte header
[ ] contain exactly payload_bytes valid payload bytes
[ ] contain zero padding after payload up to the 64-byte boundary
[ ] do not cross the physical end of the ring
```

### WRAP rule

If a normal record would cross the physical ring end, the writer must first commit a WRAP record.

WRAP record requirements:

```text
packet_type       = 0x007F
payload_bytes     = 0
effective length  = R - off(W)
header location   = B + off(W)
padding           = zero through physical ring end
seq               = ignored; zero or previous normal seq
```

The writer must not advance a WRAP record by `align64(32 + payload_bytes)`. WRAP consumes the full physical tail.

### Free-space rule

Before writing a normal record of aligned length `Lrec`:

```text
o = off(W)
Ttail = R - o
Lreq = (Ttail + Lrec) if o + Lrec > R else Lrec
Ffree = R - (W - Rd) - Gguard
Gguard >= 64
```

The write is legal only when:

```text
Ffree >= Lreq
```

If not, the packet is dropped and `DMA_DROP_COUNT` increments. Checking only `Ffree >= Lrec` is a bug when wrap is required.

### Memory coherency

The Step-13 userspace reader maps the ring read-only from synchronous
`/dev/mem`. Cached mappings are forbidden and
`allow_cached_ring_mapping` must remain `false` because no cache-invalidation
implementation exists. A future kernel/DMA driver may define a different
coherency contract, but it must not silently weaken this baseline. Do not debug
packet parsing until the live reservation and non-cacheable mapping are proven.

## Required CSR sequence

Ring initialization must follow this order:

```text
1. Clear CONTROL.telemetry_enable.
2. Clear CONTROL.ring_writer_enable.
3. Pulse CONTROL.telemetry_soft_reset.
4. Write RING_BASE_LO.
5. Write RING_BASE_HI.
6. Write RING_SIZE_BYTES.
7. Pulse RING_CONFIG_COMMIT while telemetry is disabled.
8. Write RING_RD_LO_SHADOW = 0.
9. Write RING_RD_HI_SHADOW = 0.
10. Pulse RING_RD_COMMIT.
11. Pulse RING_WR_SNAPSHOT.
12. Read RING_WR_LO_SNAP and RING_WR_HI_SNAP; expect W = 0.
13. Set CONTROL.ring_writer_enable = 1.
14. Set CONTROL.telemetry_enable = 1.
```

Do not enable the writer before `Rd = 0` has been committed.

For the Step-14 network command path, this raw sequence is owned by the HPS
command bridge and exposed only as:

```text
RESET_TRANSPORT -> CONFIGURE_DDR_RING -> SET_TELEMETRY_ENABLE 1
```

`CONFIGURE_DDR_RING` has three zero arguments. It uses the already validated
runtime profile and live reservation; no network datagram may supply a ring
address, size, or guard value. On partial failure the bridge attempts
`CONTROL=0` and verifies both controls off in STATUS. If MMIO/readback cannot
prove that state, software locks `RESET_REQUIRED`, reports hardware disable as
unverified, and requires an operator or transport reset. `CLEAR_COUNTERS` does not reset this ring state: it preserves
producer `W`, consumer `Rd`, sticky flags, telemetry sequence, peer binding, and
the command sequence/cache ledger.

## Bring-up ladder

Follow the ladder in order. Do not jump directly to WAVE/SPEC/METRICS streaming.

### D0: generated contract sanity

Goal: prove all software and RTL use the same CSR and packet constants.

Checklist:

```text
[ ] csr_map.json defines RING_BASE_LO/HI, RING_SIZE_BYTES, RING_CONFIG_COMMIT.
[ ] csr_map.json defines RING_WR_SNAPSHOT and latched W registers.
[ ] csr_map.json defines RING_RD shadow/commit registers.
[ ] packet_layouts.json defines 32-byte header and WRAP type.
[ ] Generated SV package contains the same offsets.
[ ] Generated HPS C header contains the same offsets.
[ ] Generated Python packet constants contain the same packet IDs and payload sizes.
```

Failure policy:

```text
If any offset is duplicated by hand in C or Python, stop and fix generated-contract flow.
```

### D1: DDR allocation and cache policy

Goal: reserve or allocate a ring buffer that the FPGA writer and HPS reader can both access.

Required documentation update:

```text
platform/de1soc/address_map/address_map.md
sw/hps/config/trecap_hps_config.json
```

Minimum runtime config fields:

```json
{

  "project": "T_RECAP_Phase2",
  "board": "de1soc",
  "address_contract": "platform/de1soc/address_map/hps_bridge_regions.json",
  "address_contract_stage": "step4_address_map_source_frozen",
  "csr_base_phys": "0x00000000ff200000",
  "csr_span_bytes": 4096,
  "ring_base_hps_phys": "0x000000003e000000",
  "ring_base_fpga": "0x000000003e000000",
  "ring_size_bytes": 33554432,
  "ring_guard_bytes": 64,
  "telemetry_dst_ip": "192.168.10.1",
  "telemetry_dst_port": 5005,
```

This is the canonical Step-13 profile shape, including the required safety

updating the authoritative address map and regenerating/checking every

runtime, and hardware evidence gates.

Pass condition:

```text
[ ] HPS can map the CSR window.
[ ] HPS can map the DDR ring buffer.
[ ] HPS can clear the DDR ring memory without crashing Linux.
[ ] The ring region is not allocated for unrelated Linux memory.
[ ] Runtime mapping is verified read-only/non-cacheable and cached mapping is rejected.
```

### D2: idle CSR ring configuration

Goal: configure ring base/size while writer is disabled.

Example smoke command shape:

```bash
python scripts/bringup/smoke_csr.py \
  --config sw/hps/config/trecap_hps_config.json \
  --ring-init-only
```

Expected observations:

```text
ID      = 0x54524350
VERSION = 0x00010008
STATUS.ring_configured = 1 after RING_CONFIG_COMMIT
DMA_STATUS.writer_idle = 1
DMA_STATUS.malformed_config = 0
```

Failure triage:

| Symptom | Likely cause | First check |
| --- | --- | --- |
| ID mismatch | wrong CSR base or endian compare bug | HPS config and generated `trecap_csr.h` |
| VERSION mismatch | stale generated headers or old RTL | `make check-generated` and Quartus image |
| ring_configured stays 0 | bad base/size/alignment | `memory_map.md` and ring size power-of-two |
| malformed_config set | illegal base, size, or enable order | ring init sequence |

### D3: producer/consumer reset confirmation

Goal: verify pointer reset and snapshot/commit logic before any DDR record is written.

Procedure:

```text
1. Run ring initialization sequence.
2. Pulse RING_WR_SNAPSHOT.
3. Read W snap low/high.
4. Confirm W = 0.
5. Commit Rd = 0.
6. Read status flags.
```

Pass condition:

```text
[ ] W snapshot reads exactly zero.
[ ] No torn high/low values are observed across repeated snapshots.
[ ] DMA_DROP_COUNT = 0.
[ ] PACKET_FIFO_DROP_COUNT = 0.
[ ] OVERFLOW_FLAGS.cdc_error = 0.
```

If W does not reset to zero, stop. Do not enable HPS UDP streaming.

### D4: single dummy STATUS record

Goal: prove one FPGA-originated record can be written and committed to DDR.

Recommended configuration:

```text
PACKET_ENABLE = STATUS_EN only
SPEC_MODE     = 0
WAVE_DECIM    = 1
ring size     = normal board ring, preferably 32 MiB
```

Procedure:

```text
1. Disable telemetry.
2. Reset telemetry.
3. Configure ring.
4. Commit Rd = 0.
5. Enable ring writer.
6. Enable telemetry.
7. Wait for one STATUS period.
8. Snapshot W.
9. Read DDR bytes [0, W).
10. Parse exactly one normal record.
```

Header fields expected for STATUS:

```text
magic          = 0x54524350
version        = 1
header_bytes   = 32
packet_type    = 0x0005
payload_bytes  = 72
header_crc     = 0
```

Pass condition:

```text
[ ] W advances by align64(32 + 72) for a single STATUS record.
[ ] Header is little-endian numeric, not raw ASCII string compare.
[ ] Padding bytes after payload are zero.
[ ] HPS reads no bytes beyond committed W.
```

### D5: HPS reader validation path

Goal: prove the HPS reader validates and forwards committed records without using GUI logic.

Run HPS streamer in console mode:

```bash
./trecap_udp_streamer \
  --config sw/hps/config/trecap_hps_config.json \
  --status-only \
  --print-records
```

Expected behavior:

```text
[ ] HPS snapshots W.
[ ] HPS reads records while Rd != W.
[ ] HPS validates header and payload length.
[ ] HPS forwards one UDP datagram per record.
[ ] HPS advances Rd by align64(32 + payload_bytes).
[ ] HPS commits Rd through RING_RD_COMMIT after consuming the record.
```

Do not involve dashboard plots yet. Use a packet receiver or hex dump first.

### D6: WRAP test

Goal: prove the writer does not emit a normal record crossing the physical end of the ring.

Preferred environment:

```text
simulation or controlled hardware diagnostic mode
```

Recommended test method:

```text
1. Use a test-only profile that starts W near the end of the ring.
2. Schedule one normal STATUS record that would cross the end.
3. Confirm FPGA commits a WRAP record consuming R - off(W).
4. Confirm the next normal record starts at offset zero.
```

Expected WRAP behavior:

```text
[ ] WRAP header is at tail offset.
[ ] WRAP payload_bytes = 0.
[ ] WRAP effective length is R - off(W).
[ ] Tail padding through physical end is zero.
[ ] Next normal record starts at offset 0.
[ ] WRAP is not forwarded to PC.
[ ] WRAP does not consume a PC-visible sequence number.
```

Fail immediately if any normal record crosses the physical end. That is a memory-corruption bug, not a dashboard bug.

### D7: ring full and drop accounting

Goal: verify non-stall telemetry drop behavior.

Procedure:

```text
1. Stop or pause the HPS reader after enabling telemetry.
2. Keep the FPGA core/telemetry producing records.
3. Let ring occupancy approach full.
4. Confirm records are dropped, not core-stalled.
5. Resume HPS reader.
```

Expected behavior:

```text
[ ] Core sample/frame counters keep advancing.
[ ] DMA_DROP_COUNT increments for DDR-writer/ring-space drops.
[ ] OVERFLOW_FLAGS.ring_overflow may set.
[ ] STATUS.dma_drop_count exposes the low word of DMA_DROP_COUNT.
[ ] PACKET_FIFO_DROP_COUNT is not incorrectly merged with DMA_DROP_COUNT.
```

If core counters stop while ring is full, the non-stall rule is broken.

### D8: packet FIFO full and pre-writer drop accounting

Goal: distinguish pre-writer FIFO drops from DDR-writer drops.

Procedure:

```text
1. Configure a small telemetry packet FIFO in a test build or assert a diagnostic FIFO-full mode.
2. Enable STATUS plus high-rate WAVE/SPEC events.
3. Force FIFO pressure before the DDR writer accepts the record.
```

Expected behavior:

```text
[ ] PACKET_FIFO_DROP_COUNT increments.
[ ] OVERFLOW_FLAGS.packet_fifo_overflow sets.
[ ] STATUS.packet_fifo_drop_count reports the low word.
[ ] DMA_DROP_COUNT is not required to increment for pre-writer drops.
[ ] STATUS records are admitted last-dropped / highest priority according to scheduler policy.
```

A simple incoming-drop FIFO cannot claim STATUS dropped last unless it implements eviction/reservation that protects high-priority admission.

### D9: malformed-record policy

Goal: verify the HPS exactly-once latch-and-rearm response to malformed DDR
data.

Procedure:

```text
1. Use a controlled debug mode or test harness to corrupt one header field.
2. Let HPS reader encounter the malformed record.
3. Confirm it does not scan forward through arbitrary bytes.
```

Expected behavior:

```text
[ ] malformed_record_count increments.
[ ] HPS disables telemetry writer.
[ ] HPS commits current Rd.
[ ] The incident is counted, parsed, and recommitted exactly once.
[ ] The default process stays alive for diagnostics without rereading the bad Rd.
[ ] HPS requires soft reset, ring reconfiguration, Rd=0 commit, zero-W
    verification, and the normal arm sequence before streaming resumes.
[ ] HPS does not read out of bounds.
```

Byte-scanning resynchronization is not part of the baseline.
`--stop-on-malformed` is a debug-only exit-code-3 override after the latch has
been established.

### D10: long soak

Goal: prove ring behavior is stable over time.

Minimum first-soak profile:

```text
source mode       = BRAM replay or diagnostic source
PACKET_ENABLE     = STATUS_EN only, then STATUS+WAVE, then STATUS+WAVE+METRICS
SPEC_MODE         = 0 at first; add one spectrum mode only after WAVE/METRICS
runtime           = 15 minutes minimum for transport smoke, longer before demo
PC dashboard      = optional for this test; HPS console counters are sufficient
```

Soak pass condition:

```text
[ ] HPS streamer remains alive.
[ ] No malformed record.
[ ] No out-of-range Rd/W state.
[ ] No unexpected writer reset.
[ ] Packet sizes remain legal.
[ ] Drop counters are explainable under intentional overload only.
[ ] Core sample/frame counters continue when PC is disconnected.
```

## HPS reader checklist

The HPS ring reader must validate before forwarding:

```text
[ ] magic == 0x54524350
[ ] version is supported
[ ] header_bytes == 32
[ ] packet_type is known
[ ] reserved and illegal flag bits are zero
[ ] header_crc == 0
[ ] payload_bytes is legal for the packet type
[ ] normal record length = align64(32 + payload_bytes)
[ ] normal record does not cross ring end
[ ] WRAP uses effective length R - off(Rd)
[ ] padding bytes are not sent over UDP
```

Packet-specific payload rules:

```text
WAVE      payload_bytes = 16 + 6 * nsamp, 1 <= nsamp <= 192
SPEC129   payload_bytes = 287
SPEC64    payload_bytes = 268
METRICS   payload_bytes = 56
STATUS    payload_bytes = 72
WRAP      payload_bytes = 0, not forwarded to PC
```

## Stop conditions

Stop the test and disable telemetry if any of these occur:

```text
[ ] W - Rd > R.
[ ] A normal record crosses the physical ring end.
[ ] HPS reads beyond committed W.
[ ] HPS compares magic as ASCII bytes instead of numeric little-endian value.
[ ] STATUS payload size is not 72 under Revision G.
[ ] header_crc is nonzero.
[ ] HPS discovers a malformed record.
[ ] Cache-coherency policy is unknown.
[ ] Ring base written into CSR is a userspace virtual address.
[ ] Core sample/frame counters stop because the ring or PC is slow.
```

## Common failures

| Failure | Meaning | Fix |
| --- | --- | --- |
| `ID` read fails | wrong CSR base, bridge disabled, stale bitstream | check Platform Designer and `trecap_hps_config.json` |
| `VERSION` wrong | stale generated headers or old RTL image | regenerate headers and rebuild Quartus |
| W never advances | telemetry disabled, writer disabled, no records scheduled | check CONTROL and PACKET_ENABLE |
| W advances but header invalid | wrong ring base address or endian/packing bug | inspect DDR at FPGA-visible physical address |
| First STATUS payload is not 72 | packet schema drift | fix `packet_layouts.json` and regenerate |
| WRAP appears in UDP stream | HPS forwarding WRAP incorrectly | fix `ring_reader.c` |
| PC sequence gaps under no-loss run | HPS skipped committed normal record | inspect Rd advancement and WRAP logic |
| HPS sees old packet repeatedly | unsupported cached mapping or bad reservation | Stop; restore the read-only non-cacheable mapping and revalidate the live reservation. |
| DMA drops increment immediately | ring free-space math or Rd commit bug | inspect `W`, `Rd`, `Lreq`, `Gguard` |
| Packet FIFO drops merge with DMA drops | counter ownership bug | keep pre-writer and writer-stage drops separate |

## Acceptance checklist

A first DDR ring implementation is acceptable when:

```text
[ ] HPS can configure ring base/size and reset pointers.
[ ] Network lifecycle enforces RESET -> CONFIGURE -> ENABLE and never accepts ring addresses from the peer.
[ ] CLEAR_COUNTERS preserves W, Rd, sticky flags, telemetry sequence, peer binding, and command ledger/cache.
[ ] W snapshot/commit and Rd shadow/commit are coherent and untorn.
[ ] STATUS-only records are written to DDR and forwarded to UDP.
[ ] HPS validates all headers before forwarding.
[ ] WRAP records work and are not forwarded.
[ ] Normal records never cross the ring end.
[ ] HPS mapping is read-only and non-cacheable; cached access is rejected.
[ ] Ring full causes telemetry drops and counters, not core stalls.
[ ] Packet-FIFO drops and DDR-writer drops are separately visible.
[ ] A malformed incident is counted exactly once, latches without byte scanning
    or repeated parsing, and requires the complete re-arm sequence.
[ ] A long soak produces stable counters and no unexplained malformed records.
```

Only after this passes should `pc_dashboard_bringup.md` be used for full live visualization.
