# BRAM replay signoff bring-up

File class: **[1] hand-written bring-up document**.

This document defines the first board-level correctness path for T-RECAP Phase 2. It exists to prevent a common failure mode: making a live Ethernet dashboard look active while the STFT/WOLA core is not yet bit-accurate.

BRAM replay is the correctness path. Ethernet telemetry is an observability/demo path.

## Authority

The active integrated Phase 2 specification under `docs/specs/` is the authority. This document follows the core-first rule:

```text
reference artifacts
  -> BRAM replay source
    -> FPGA STFT/WOLA core
      -> output/artifact comparison
```

No HPS, DDR ring, Ethernet, UDP streamer, PC dashboard, ADC, or live audio path is required for C0 BRAM replay.

## What BRAM replay must prove

A C0 BRAM replay implementation must demonstrate:

```text
1. The FPGA core consumes the same frozen x_in.memh stream used by the reference model.
2. The FPGA core applies the same coefficient ROM contents and generated constants.
3. The replay source continues full-tail zero flush until Ny outputs are emitted.
4. The FPGA output y[n] matches y_out.memh for the selected vector, or mismatch details are captured.
5. Frame statistics match frame_stats.csv when the board exposes them for replay.
6. Aggregate metrics match metrics.json when the board exposes them for replay.
7. Overflow/wrap flags remain deasserted on the frozen signoff vector set.
8. Delay alignment uses D = L + G = 384 samples, not D = L.
9. Accepted-sample and frame conservation still hold under prolonged core backpressure.
```

Do not weaken this to “the waveform looks close on a plot.”

Expected interpretation:

| Command | Why it matters |
| --- | --- |
| `make check-layout` | Confirms Phase 1 root files are quarantined and required folders exist. |
| `make gen-headers` | Produces SV/C/Python constants from shared schemas. |
| `make check-generated` | Catches generated-header drift. |

| `make coeffs` | Emits coefficient ROM artifacts. |

| `make check-artifacts` | Checks hashes, row counts, schema shape. |
| `make compile-core` | Confirms C0 RTL compiles without transport/platform dependencies. |

If one of these fails, BRAM replay is not ready.

For remote Step-14 admission, send `START_BRAM_REPLAY` only after the verified
RESET-to-CONFIGURE-to-ENABLE lifecycle and safe replay-idle admission. Record the
32-byte result, starting `REPLAY_STATUS.result_epoch`, completion epoch, and
retained accept/reject bits. A timeout is not acceptance, and a board-key start
must not overwrite a pending CSR-originated result. Passing the checked-in
structural/model or host source gates is not evidence that this sequence ran on
native RTL or DE1-SoC hardware.

## Replay source contract

`trecap_bram_replay_source.sv` must provide a clean sample stream:

```text
out_valid
out_sample signed [N-1:0]
out_sample_idx [63:0]
replay_done
replay_error or replay_status if implemented
```

Minimum behavior:

```text
1. Emit x_in.memh samples from sample index 0 to Ns - 1.
2. Continue emitting zero samples after Ns for the full-tail flush interval.
3. Stop only after the design has emitted exactly Ny output samples.
4. Provide sample index and optional vector ID/build hash for traceability.
5. Never generate random input during signoff replay.
```

The BRAM replay source must not depend on HPS software, Ethernet, PC dashboard, live audio, ADC, or board switches.

## Full-tail rule

The replay does not stop after the last real input sample. It must continue zero-flush ticks until the output length `Ny` is complete.

Baseline constants:

```text
N = 12
L = 256
H = 128
F = 15
G = 128
D = L + G = 384
```

The delayed comparison is:

```text
y[n] compared against xz[n - D]
```

Using `D = L` is a deprecated Phase 1/old-draft mistake for the current DE1-SoC Phase 2 baseline.

## Board replay modes

### Mode A: self-checking board replay

Preferred C0 board mode. The FPGA stores or streams enough expected data to perform a local comparison:

```text
x_in.memh -> BRAM replay source
expected y_out.memh -> expected-output ROM/BRAM or checker stream
core output -> comparator
mismatch counter -> visible register/LED/JTAG-readable status
```

Minimum pass outputs:

```text
PASS/FAIL
first_mismatch_sample_idx
expected_sample
actual_sample
total_mismatch_count
core_overflow_flags
replay_done
```

### Mode B: board capture and host-side compare

Allowed if self-checking replay is too heavy for first C0 hardware:

```text
x_in.memh -> BRAM replay source
core output captured through JTAG/UART/SignalTap/small dump path
host script compares capture against y_out.memh
```

This is less clean than self-checking replay because capture paths can drop or reorder data. If used, the capture transport must prove it did not lose samples.

### Mode C: simulation-only replay

Simulation-only replay is required but not sufficient for board signoff. C0 acceptance requires board BRAM replay before live input is used for demo.

## Step-by-step board replay bring-up

### Step 1: select one vector

Start with a small, boring vector:

```text
zero input or short finite stream
THR2 = 0
full_tail policy
```

Do not start with near-threshold multitone or noise. Those are useful after basic alignment works.

### Step 2: verify artifact hashes and row counts

```bash
make check-artifacts
```

Manually inspect the selected vector config:

```bash
python sw/reference_model/tools/inspect_memh.py artifacts/test_vectors/<vector>/x_in.memh || true
python sw/reference_model/tools/inspect_memh.py artifacts/reference_outputs/<vector>/y_out.memh || true
```

The exact tool names may change with the imported reference package. The required behavior does not change: row counts and hashes must match the manifests.

### Step 3: compile core-only RTL

```bash
make compile-core
```

If core compile requires `rtl/telemetry/`, `rtl/hps_bridge/`, `sw/hps/`, `sw/pc_dashboard/`, or `platform/de1soc/`, C0 has been violated.

### Step 4: build the BRAM replay image

Use the Quartus smoke/full path appropriate for the current state:

```bash
make quartus-core-smoke
```

or, once board wrapper exists:

```bash
make quartus-de1soc PROFILE=config/profiles/de1soc_bram_replay.json
```

The BRAM replay profile must keep source mode fixed to BRAM replay. It must not select live audio or ADC.

### Step 5: program FPGA

```bash
make program-sof SOF=path/to/trecap_core_bram_replay_top.sof
```

or use Quartus Programmer and record the exact `.sof` path in the run manifest.

### Step 6: reset and run replay

Expected sequence:

```text
1. Assert board/core reset.
2. Release reset synchronously through the board reset controller.
3. Start replay, or allow replay to auto-start if that is the top-level design choice.
4. Wait for replay_done.
5. Read PASS/FAIL, mismatch counters, overflow flags, and emitted sample count.
```

No Ethernet dashboard is required for this step.

### Step 7: compare outputs

Required compare fields:

```text
emitted_y_count == Ny
y_out sample-by-sample match, or mismatch report exists
frame_stats rows match when exposed
metrics fields match when exposed
overflow flags are zero for frozen signoff vectors
```

If only a subset is exposed in the first C0 board top, document that limitation. Do not call the board signoff complete until mandatory fields are covered.

## Acceptance criteria

A BRAM replay run passes only if:

```text
[ ] The selected vector is named in the manifest.
[ ] The artifact hashes match committed manifests.
[ ] Coefficient ROM contents match committed coefficient artifacts.
[ ] The replay source emits all real samples and full-tail zero flush ticks.
[ ] The core emits exactly Ny samples.
[ ] y_out comparison passes sample-for-sample.
[ ] frame_stats comparison passes where the replay top exposes frame stats.
[ ] metrics comparison passes where the replay top exposes aggregate metrics.
[ ] THR2=0 case has no eligible masks set.
[ ] No overflow/wrap/sticky error flag is asserted.
[ ] The run does not depend on HPS, Ethernet, UDP, PC dashboard, live audio, or ADC.
```

If any of these are false, the status is not PASS. Use `FAIL` or `INCOMPLETE`.

## Failure triage

| Symptom | Likely cause | First debug action |
| --- | --- | --- |
| Output shifted by constant offset | Wrong delay or startup/full-tail timing | Recheck `D = L + G = 384`, frame trigger, OLA read pointer. |
| First frames fail only | Startup ring initialization or zero extension bug | Inspect frame 0 construction and BRAM replay reset. |
| Tail fails only | Replay stopped before full-tail flush | Check `Ny`, post-input zero ticks, final frame count. |
| THR2=0 suppresses bins | Mask comparison/protection/threshold register bug | Check unsigned mag2 compare and THR2 width. |
| All values scaled wrong | FFT/IFFT scaling or window fixed-point shift bug | Check generated widths and rounding points. |
| Sporadic mismatches | Uninitialized memory or CDC/reset issue | Force reset coverage and initialize BRAM/ROM. |
| Simulation passes, board fails | ROM path, synthesis memory inference, reset, or timing issue | Check `.memh` inclusion and Quartus warnings. |
| Frame stats match, y mismatches | IFFT/synthesis/WOLA path issue | Inspect synthesis window and OLA accumulator. |
| y matches, metrics mismatch | Metric accumulator width/schema bug | Check decimal-string counters and overflow flags. |

Do not fix a replay mismatch by changing expected artifacts until the reference model change has been reviewed and frozen.

## Relationship to telemetry

C0 core may expose valid-only telemetry taps, but taps are observational. They must not control replay or backpressure the core.

T0 may later use the same taps for:

```text
WAVE
SPEC64 or SPEC129
METRICS
STATUS
```

A failing Ethernet packet does not invalidate a passing BRAM replay. A passing Ethernet plot does not repair a failing BRAM replay.

## Release gate

Before live input or Ethernet demo work is treated as active implementation, the team must have at least:

```text
[ ] one THR2=0 vector passing BRAM replay;
[ ] one nonzero THR2 vector passing BRAM replay;
[ ] one short finite-stream vector passing full-tail replay;
[ ] no overflow flags on those runs;
[ ] replay manifests stored under runs/ or release package;
[ ] known unresolved mismatches documented.
```

If this gate is skipped, the project will waste time debugging transport symptoms caused by a broken core.
