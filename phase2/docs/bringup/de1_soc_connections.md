# DE1-SoC physical connections and lab topology

File class: **[1] hand-written bring-up document**.

This document defines the physical connection plan for the T-RECAP Phase 2 DE1-SoC bring-up bench. The Step-7 board source now contains the real source-to-core wiring; this document keeps the hardware bench, Quartus programming path, HPS console, HPS Ethernet path, and optional live audio path from being mixed together informally.

This file does not define the signal-processing algorithm. It also does not prove correctness. Correctness is still established through BRAM replay and artifact comparison.

## Authority

The active integrated Phase 2 specification under `docs/specs/` is the authority. This document restates the physical setup required for:

```text
BRAM/audio/ADC/diagnostic source
  -> trecap_source_core_integration
    -> FPGA fabric core
      -> valid-only FPGA telemetry formatter
        -> FPGA DDR ring writer
          -> HPS DDR ring reader
            -> HPS UDP streamer over Ethernet
              -> PC dashboard
```

The reverse command path is:

```text
PC command UDP
  -> HPS command parser
    -> HPS command bridge / sequence-result cache
      -> generated CSR writes and readback
        -> FPGA safe-boundary/replay owners
```

The HPS owns Ethernet. The FPGA fabric owns the signal-processing core. The PC owns visualization and user commands only.

The physical Quartus top is `rtl/platform/de1soc/de1_soc_trecap_top.sv`. It
instantiates `rtl/top/trecap_source_core_integration.sv` and the pin-agnostic
`rtl/top/trecap_de1soc_full_top.sv`; the latter is not the board-pin entity.
These are checked-in source connections only. They do not establish Quartus
compilation or TimeQuest closure, functional verification, BRAM-replay
equivalence, or working codec/ADC hardware.

Step 10 freezes one active `CLOCK_50`-derived 50 MHz fabric domain and one
canonical full-board reset. `clock_reset_ctrl` qualifies released `KEY[0]` high
for 20 ms, combines it with the active-low HPS-to-FPGA reset, and synchronizes
release once for all fabric owners. The HPS reset is global to the full-board
fabric; C0 remains HPS-independent through its separate core-only top.

## Baseline physical connection profile

Use this connection set for the final DE1-SoC telemetry demo:

```text
1. 12 V power adapter -> DE1-SoC power jack
2. PC USB -> DE1-SoC J13 USB-Blaster II
3. PC USB -> DE1-SoC J4 HPS UART
4. DE1-SoC RJ45 -> PC Ethernet, router, or switch
5. Optional audio cable -> LINE-IN / LINE-OUT only during controlled R11 bring-up
```

For first transport bring-up, avoid shared campus networks. Use a direct point-to-point Ethernet link unless the lab network rules require a switch.

Recommended direct-link network:

```text
PC Ethernet IP       = 192.168.10.1/24
DE1-SoC HPS IP       = 192.168.10.2/24
Telemetry UDP port   = 5005
Command UDP port     = 5006
```

Do not put the command port on an untrusted network. The Revision G command protocol is a lab/demo protocol; it is not authenticated or encrypted.

## Step-7 board controls and display

The checked-in physical top assigns the local controls as follows:

```text
KEY[0]          active-low board reset; release must remain high for 20 ms
KEY[1]          debounced BRAM replay start/restart request
SW[2:0]         diagnostic waveform selector when the CSR active source is diagnostic
SW[6:4]         ADC channel sampled only on entry to TSRC_ADC_LIVE
SW[7]           ADC request mode: 0 = continuous, 1 = debounced KEY[2] one-shot
KEY[2]          one ADC request only while SW[7]=1 and ADC is active/ready
SW[9:8]         HEX page: core sample count, core frame count, STATUS, or overflow/drop summary
LEDR[0]         synchronized platform reset released
LEDR[2]         real core tap observed
LEDR[7]         aggregate writer/source/build-contract/core-protocol/audio-FIFO/codec-control/ADC fault indication
LEDR[8]         BRAM-replay end-to-end completion is busy
LEDR[9]         BRAM-replay exact core completion followed by later DDR STATUS commit is done
```

The switches do not bypass CSR source-mode or THR2 shadow/commit control. These
assignments are observability and local replay controls, not functional evidence.
In particular, `LEDR[7]` includes dedicated fault levels that have no matching
generated CSR field; aggregating them on the LED does not make them CSR-visible.

The 48 kHz sample, 10 Hz STATUS, 30 Hz METRICS, and 2 Hz heartbeat-toggle
signals are fractional clock enables, not clock pins. `CLOCK2_50`, `CLOCK3_50`,
and `CLOCK4_50` are reserved. Do not attempt a split-clock experiment without a
new CDC design. Audio BCLK reset release is edge-specific inside the wrapper.
The peripheral-only PLL drives `AUD_XCK` at 12.288 MHz and FPGA I2C configures
WM8731 address `0x1a` for 48 kS/s, signed 16-bit codec-master I2S. The
[physical timing contract](../architecture/physical_timing.md) defines audio I/O
and CDC constraints exercised by the BRAM-profile native12 fit. Its required
audio timing checks passed; see the [implementation results](../results/fpga_implementation.md)
for the complete gate outcome. Physical clocks, codec operation and analog
performance still require board qualification.

The LTC2308 continuous-request scheduler uses a separate exact-average 100 kHz
fractional accumulator. At the frozen 50 MHz profile it divides exactly.
`ADC_SCLK` is a 2.5 MHz registered serial protocol output, not a timing domain;
only the off-chip `ADC_DOUT` bit crosses a preserved two-flop synchronizer before
the 12-bit word is assembled in fabric.

## Power and handling checklist

Before power-on:

```text
[ ] Board is on a non-conductive surface.
[ ] No loose wire or probe is touching adjacent pins.
[ ] DIP/SW positions are recorded if they affect reset or source mode.
[ ] USB-Blaster cable is connected firmly.
[ ] HPS UART cable is connected if HPS Linux will be used.
[ ] RJ45 cable is connected only after deciding direct-link vs switch topology.
[ ] Optional audio cables are disconnected unless doing R11 audio work.
```

Power-on sequence:

```text
1. Connect USB-Blaster and UART first.
2. Connect Ethernet.
3. Apply 12 V power.
4. Wait for board power LEDs and HPS boot behavior.
5. Open HPS UART console before starting HPS Ethernet bring-up.
6. Program FPGA only after selecting the correct Quartus output file.
```

Power-off sequence:

```text
1. Stop HPS UDP streamer if running.
2. Disable telemetry in software if possible.
3. Stop PC dashboard.
4. Power off board.
5. Disconnect optional audio and probes.
```

Do not repeatedly hot-plug probes or audio cables while debugging unknown reset behavior.

## USB-Blaster / FPGA programming connection

The USB-Blaster path is used by:

```text
make program-sof
quartus_pgm
Quartus Programmer GUI
SignalTap / JTAG debug, if used
```

Expected programming flow:

```text
PC Quartus tools
  -> USB-Blaster II / J13
    -> FPGA configuration SRAM
      -> selected top module
```

The selected `.sof` must match the intended bring-up stage:

| Stage | Expected top | Purpose |
| --- | --- | --- |
| C0 core-only smoke | `trecap_core_only_top.sv` | Compile/program minimal core wrapper if supported. |
| C0 BRAM replay | `trecap_core_bram_replay_top.sv` | Board-level artifact replay without Ethernet. |
| T0/full demo | `de1_soc_trecap_top.sv` | Physical board top binding source/core, Platform Designer/HPS, DDR, telemetry, and board pins. |

Do not program an old Phase 1 `t_recap_demo_top.sv` and call it Phase 2. Phase 1 files belong under `legacy/phase1/` and are not part of the Phase 2 root build.

## Ethernet connection

Ethernet is used only after the HPS side is running. The correct path is:

```text
FPGA DDR ring writer
  -> HPS-visible DDR ring
    -> HPS userspace/kernel reader
      -> HPS Ethernet MAC/PHY
        -> PC UDP receiver/dashboard
```

Wrong path:

```text
FPGA fabric -> direct Ethernet MAC in RTL -> PC
```

That direct-fabric Ethernet path is not the Revision G architecture for this project.

### Static IP direct-link setup

On the PC, configure the Ethernet adapter to:

```text
IP address: 192.168.10.1
netmask:    255.255.255.0
command UDP source/bind port: 5007
```

On the HPS Linux console, the exact interface name can vary. Common names include `eth0` or `end0`. Use `ip link` to confirm.

Example HPS commands:

```bash
ip link
sudo ip addr flush dev eth0
sudo ip addr add 192.168.10.2/24 dev eth0
sudo ip link set eth0 up
ping -c 3 192.168.10.1
```

On some stripped-down embedded images, `sudo` may not exist because the console is already root. Do not commit a script that assumes both cases blindly. `scripts/bringup/smoke_udp_recv.py` and `sw/hps/scripts/setup_static_ip.sh` should document the expected environment once HPS software exists.

### Link sanity checks

Before blaming FPGA RTL:

```text
[ ] PC link LED is active.
[ ] DE1-SoC RJ45 link LED is active.
[ ] HPS can ping PC.
[ ] PC can ping HPS.
[ ] PC firewall permits UDP telemetry port 5005.
[ ] PC firewall permits UDP command return path if needed.
[ ] HPS command listener is bound to 192.168.10.2:5006 in production, not wildcard.
[ ] PC command client is bound to 192.168.10.1:5007 and HPS pins both IP and port.
[ ] HPS streamer prints the configured destination IP/port.
```

If ping fails, do not debug CSR, DDR, packet parser, or dashboard yet. Fix physical/network link first.

## Optional audio cables

Audio is deliberately not part of C0 and not required for first T0. Its Step-16
source implementation is present, but leave LINE-IN and LINE-OUT disconnected
unless doing the controlled R11 live-audio bring-up after BRAM replay.

During R11 operational bring-up, control and audio enter through:

```text
rtl/platform/de1soc/audio_pll_wrapper.sv -> AUD_XCK 12.288 MHz
rtl/platform/de1soc/audio_codec_i2c_init.sv -> WM8731 0x1a
rtl/platform/de1soc/audio_codec_wrapper.sv -> signed 16-bit I2S async FIFO
  -> rtl/sources/trecap_audio_adapter.sv
    -> rtl/sources/trecap_source_mux.sv
      -> rtl/top/trecap_source_core_integration.sv
        -> core sample stream and valid-only taps
```

Audio must not bypass the source mux or inject board-specific signals directly
into `rtl/core/`. Before programming, configure the HPS side so
`HPS_I2C_CONTROL` remains low; FPGA logic uses that as the codec-bus grant and
never drives the HPS mux signal. Select
`config/profiles/de1soc_linein_demo.json` explicitly for this build.

## Optional LTC2308 ADC source

ADC is also outside C0 and first T0. Before selecting it, verify that the PCB is
the pinned DE1-SoC Rev-H design and that the converter is marked LTC2308; older
revisions may use a different ADC and are not compatible with this profile.

The source path is:

```text
LTC2308 ADC_DOUT -> two-flop synchronizer -> adc_wrapper 12-bit word/valid
  -> trecap_adc_adapter code-2048 recentering
    -> trecap_source_mux / TSRC_ADC_LIVE
      -> trecap_source_core_integration
        -> core sample stream and valid-only taps
```

Select `config/profiles/de1soc_adc_demo.json` explicitly. It freezes 100
ksample/s, 2.5 MHz SCLK, single-ended/unipolar/awake operation, straight-binary
unsigned 12-bit data, DC blocking disabled, and full telemetry. Channel 0 is the
default command `6'b100010`; `SW[6:4]` is latched only on source entry. Leave and
re-enter ADC mode to change channel so the previous-command result is discarded
again.

`ADC_CS_N` is electrically the active-high, idle-low CONVST signal despite its
legacy name. Do not invert it as an active-low chip select. The profile keeps
the converter awake (`SLP=0`); do not add the sleep-wake delay to ordinary
transactions. Pin assignment and source checks are not measured waveform,
TimeQuest, analog accuracy, or hardware evidence.

## Bring-up modes and required connections

### C0: core-only compile / BRAM replay

Required physical connections:

```text
12 V power
USB-Blaster
optional HPS UART only for board-level logs if the top uses HPS-side helpers
```

Not required:

```text
RJ45 Ethernet
HPS UDP streamer
PC dashboard
LINE-IN audio
ADC live source
```

C0 is intentionally isolated from transport. It proves the core can build and consume reference artifacts before live/demo paths exist.

### T0 status-only transport

Required physical connections:

```text
12 V power
USB-Blaster
HPS UART
RJ45 Ethernet
PC Ethernet direct-link or switch/router
```

T0 starts with STATUS-only telemetry. Do not enable waveform, spectrum, and metrics until STATUS packets have been validated end-to-end.

### Full demo

Required physical connections:

```text
12 V power
USB-Blaster
HPS UART
RJ45 Ethernet
optional LINE-IN/LINE-OUT after R11
```

Full demo is allowed only after:

```text
C0 BRAM replay is passing.
T0 STATUS-only path is stable.
HPS can read ID/VERSION CSR.
HPS can forward valid DDR records to UDP.
PC dashboard can parse generated packet constants.
```

## Failure triage

| Symptom | First thing to check | Do not do yet |
| --- | --- | --- |
| Quartus cannot see board | USB-Blaster cable, driver, `jtagconfig` | Edit RTL. |
| FPGA programs but no HPS logs | HPS UART cable/interface/baud/image | Change CSR map. |
| HPS cannot ping PC | IP address, subnet, firewall, cable | Debug packetizer. |
| PC gets no UDP but ping works | HPS streamer config, firewall, UDP port | Rewrite dashboard parser. |
| STATUS parses but WAVE fails | Keep STATUS-only, validate packet sizes and enables | Enable all packets at once. |
| Core output wrong in BRAM replay | Artifacts, generated constants, ROM contents, delay `D = 384` | Debug Ethernet. |
| Telemetry drops occur | Read separate packet-FIFO and DMA drop counters | Stall the core to “fix” drops. |
| ADC codes absent or wrong channel | Verify Rev-H/LTC2308, ADC profile, active source, epoch-latched `SW[6:4]`, priming transaction, and ADC stickies | Change core scaling or bypass the source mux. |

## Hard rules

```text
Do not use Ethernet/dashboard as a bit-accurate signoff path.
Do not connect direct FPGA Ethernet for this Revision G architecture.
```
