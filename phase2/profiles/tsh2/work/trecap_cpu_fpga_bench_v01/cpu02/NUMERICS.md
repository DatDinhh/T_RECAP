# Fixed-width CPU02 kernel

CPU01 is a scalar diagnostic oracle baseline. Its checked multiplication executes a generic unsigned 64-bit division to establish each multiplication's safety. FFT and IFFT alone perform 24,584,192 such checks per 3,001-frame epoch. CPU02 replaces generic run-time configuration and multiplication checks with baseline-specific bounds, inline arithmetic, and preallocated fixed arrays. This diagnosis is based on source inspection, not a sampled profile; it does not apportion the observed 13.7-second pilot among costs.

The numerical contract remains N=12, L=256, H=128, F=15, eight FFT stages normalized by rounding each butterfly output right one bit, unscaled IFFT, Hermitian canonicalization, protected DC, threshold comparison magnitude squared >= threshold, synthesis window, full-tail overlap-add, and signed12 saturation. Rounding is nearest with ties away from zero. No negative signed shift is used.

Safety follows inductively from retained input/coefficient/stage bounds. Window coefficients are unsigned16, twiddles signed17, analysis output signed27, FFT/canonical output signed28, IFFT/synthesis output signed36, and OLA signed37. An input to any complex multiply is at most signed36 and a twiddle at most signed17: each product has magnitude <=2^51, sum/difference <=2^52, so signed64 cannot overflow. Rounded products plus an old signed36 value remain below 2^38 before the next retained width check. Canonical sums are bounded by 2^28, signed28 magnitude-square sums by 2^55, synthesis products by 2^51, and OLA addition of signed37 plus signed36 by 2^37. Analysis multiplies signed12 by unsigned16 safely then checks signed27. All arithmetic stays far below signed64 limits. FNV hashing intentionally wraps unsigned64.

Every resident input/output/workspace array is allocated and prefaulted before measurement. No dynamic allocation or table validation occurs in the successful timed processing path. Input range checks, stream reset, fixed-width checks, complete processing, serialization and final count validation remain timed. Coefficient decoding/validation and bit-reversal preparation are outside, analogous to an already configured FPGA. CPU0 pinning, clocks, file IO exclusion, full outputs and external SHA checks follow the existing protocol.

This is an allocation-free scalar fixed-point implementation, not a claim of best possible CPU performance: it uses int64 intermediates and retained stage checks; no hand-written NEON, FFT-library tuning, multithreading or algorithm changes. CPU02 must pass all five complete frozen Y/TSP1 comparisons plus native UBSan and ARM QEMU arithmetic/extreme-frame comparisons before admission.
